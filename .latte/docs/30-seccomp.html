🔒 30-seccomp 系统调用过滤

给进程套上一个"只能做这几件事"的笼子：BPF 过滤器在每次系统调用入口处做判决 · 约 13 分钟

1. 它在解决什么问题

上一讲讲的 LSM 是"贴在对象上的标签检查"，这一讲讲的是另一个维度：限制一个进程能发起哪些系统调用。

想象一个图片处理程序被用户下载运行。它只需要读文件、写文件、退出。但万一这个程序被攻陷（或者本身就是恶意软件），它可能会去 open("/dev/mem") 读物理内存、去 execve("/bin/sh") 起个 shell、外传数据。传统的 UNIX 权限救不了它——因为它本来就有那些文件权限。

seccomp 的思路是白名单：只列出允许的系统调用，其余一律拒绝或杀死。这叫"默认拒绝"，比"默认允许"安全得多——攻击者必须先突破白名单才能做坏事。

为什么用 BPF（Berkeley Packet Filter）而不是普通的 C 函数当规则？三个原因：一是无状态——过滤器是一个纯函数式的指令序列，每次系统调用都从头执行一遍，没有"当前处于什么规则中间"的概念，所以不需要加锁、不需要保存上下文，天然线程安全；二是可验证——BPF 指令集只有十来条指令，指令里没有循环（跳转只能向前），所以内核能在加载时静态检查它一定会终止，不会死循环；三是快——解释执行一个几十条指令的小程序，比走一遍复杂策略匹配快得多。

第三个问题是谁有权设置过滤器。如果任何进程都能随便给自己装过滤器倒还好（限制自己不会更危险），但如果一个低权限进程能给自己装过滤器，然后 fork 出一个高权限子进程——那这个过滤器会"传染"给子进程，反而让子进程权限更受限，这倒不危险。真正危险的是反过来：一个高权限进程 exec 一个低权限程序时，如果低权限程序能预先设置过滤器，就可能阻止高权限程序做某些事（虽然这也不能提权，但会让 setuid 程序行为异常）。

Linux 的解法是 no_new_privs：一旦设置了"不允许通过 exec 获得新权限"这个标志，那么后续 exec 出来的程序不会获得任何新权限。因为带 setuid 的程序 exec 后本来会获得 root 权限，现在被禁止获得新权限，就没法利用过滤器做文章。安装过滤器的两条路：要么进程已经设置了 no_new_privs，要么进程拥有 CAP_SYS_ADMIN。

最后是多层过滤器的合成。一个进程可以叠加多个过滤器（每次 seccomp() 调用加一个），内核会全部执行一遍，取最严格的那个结果。这样 Docker 可以加一层全局过滤器，应用自己也可以再加一层，两层取严。

3. 整体结构

3.1 过滤器在系统调用路径上的位置

  用户态：syscall 指令 / libc 包装
        │
        ▼
  架构入口（arch/x86/entry/common.c）
        │  保存参数到 pt_regs
        ▼
  secure_computing()          ← 检查 TIF_SECCOMP 标志
        │                       没装过滤器 → 直接返回 0，几乎零成本
        ▼
  __secure_computing()
        │
        ├── mode == STRICT → __secure_computing_strict()
        │                    只查内核硬编码的四个系统调用白名单
        │                    不在白名单 → do_exit(SIGKILL)
        │
        └── mode == FILTER → __seccomp_filter()
                              │
                              ▼
                        seccomp_run_filters()
                          遍历当前进程的所有过滤器（从最新到最旧）
                          每个都执行 bpf_prog_run_pin_on_cpu()
                          取"动作值最小"的那个作为最终判决
                              │
                              ▼
                        根据判决动作：
                          ALLOW        → 正常执行系统调用
                          ERRNO(data)  → 直接返回 -data
                          TRAP         → 发 SIGSYS
                          KILL_PROCESS → 整个进程被杀
                          LOG          → 记录后放行

3.2 三种模式的对比

模式值允许什么用途
DISABLED0什么都不限制默认状态
STRICT1只有 read、write、exit、rt_sigreturn内核内置的极端沙箱，基本只用于测试
FILTER2由 BPF 程序决定实际使用的模式，Docker/systemd 隔离服务都用它

3.3 BPF 过滤器的结构

  struct seccomp_data（过滤器唯一能看到的"世界"）

  偏移 0:  nr                 系统调用号
  偏移 4:  arch               架构（AUDIT_ARCH_X86_64 等）
  偏移 8:  instruction_pointer 指令指针
  偏移 16: args[0..5]         6 个 64 位参数

  ┌──────────────────────────────────────────────┐
  │ 加载 nr:   BPF_LD|BPF_W|BPF_ABS, k=0          │
  │ 比较:      BPF_JMP|BPF_JEQ|BPF_K, k=1, jt=0   │
  │            jf=1                                │
  │ 允许:      BPF_RET|BPF_K, k=SECCOMP_RET_ALLOW  │
  │ 拒绝:      BPF_RET|BPF_K, k=SECCOMP_RET_ERRNO  │
  │            | (1<<0)  /* data = EPERM = 1 */   │
  └──────────────────────────────────────────────┘

  执行流程：从第 0 条指令开始，逐条执行，
  遇到 BPF_RET 就返回该指令里的 k 值；
  遇到条件跳转按比较结果跳转到相对偏移处。

BPF 指令的编码：code 的低 8 位是类别（LD/ST/JMP/ALU/RET/MISC），中间 8 位是操作（ABS/W/H/K 等），高 8 位是跳转偏移的存储方式。jt（真时跳）和 jf（假时跳）各 8 位，k 是 32 位立即数。

3.4 判决值的编码

  高 16 位：动作（action）      低 16 位：数据（data）
  ┌────────────────┬────────────┐
  │  action        │   data     │
  └────────────────┴────────────┘

  动作值大小决定优先级（越小越严格）：
    0x00000000  KILL_THREAD  ← 最严
    0x00030000  TRAP
    0x00050000  ERRNO
    0x7fc00000  USER_NOTIF
    0x7ff00000  TRACE
    0x7ffc0000  LOG
    0x7fff0000  ALLOW        ← 最宽松

  多过滤器合成时：取 action 最小者

这个编码很巧妙：把"严格程度"直接编码成数值大小，于是"取最严"就退化成"取最小"，一行比较搞定，不需要额外的优先级表。

3.5 与其它安全机制的分工

  进程要做事
      │
      ├─ 能访问这个对象吗？   → LSM（SELinux/AppArmor）+ DAC + capability
      │
      ├─ 能发起这个系统调用吗？ → seccomp（本文）
      │
      └─ 能看到别人的资源吗？   → namespace（pid/net/mnt/user/ipc/uts/cgroup）
                                ↑ 与 seccomp 正交：seccomp 管"做什么操作"，
                                  namespace 管"能看到什么"

seccomp 与 namespace 的关系：namespace 提供虚拟资源视图（比如 chroot 后看不到外部文件系统，pid namespace 里只看到自己的进程），seccomp 提供操作白名单（哪怕在 chroot 里也不许 execve）。两者互补，容器通常两个都用。

4. 源码走读

4.1 入口：secure_computing

seccomp 的检查点是一个 per-task 的线程标志 TIF_SECCOMP。没装过滤器的进程根本不会走进 seccomp 代码。

include/linux/seccomp.h:42-48

extern int __secure_computing(const struct seccomp_data *sd);
static inline int secure_computing(void)
{
	if (unlikely(test_thread_flag(TIF_SECCOMP)))
		return  __secure_computing(NULL);
	return 0;
}

unlikely 提示编译器"绝大多数情况不会走进去"，让这条分支预测为不成立。加上 test_thread_flag 是每个线程独立的——多线程程序可以给不同线程装不同的过滤器（只要线程组 leader 装了，其它线程自动继承）。

真正的分派：

kernel/seccomp.c:1056-1077

int __secure_computing(const struct seccomp_data *sd)
{
	int mode = current->seccomp.mode;
	int this_syscall;

	if (IS_ENABLED(CONFIG_CHECKPOINT_RESTORE) &&
	    unlikely(current->ptrace & PT_SUSPEND_SECCOMP))
		return 0;

	this_syscall = sd ? sd->nr :
		syscall_get_nr(current, current_pt_regs());

	switch (mode) {
	case SECCOMP_MODE_STRICT:
		__secure_computing_strict(this_syscall);  /* may call do_exit */
		return 0;
	case SECCOMP_MODE_FILTER:
		return __seccomp_filter(this_syscall, sd, false);
	default:
		BUG();
	}
}

mode 从 current->seccomp.mode 读——per-task 字段，不加锁，因为只有自己能改自己的 mode。

4.2 严格模式：内核硬编码的白名单

kernel/seccomp.c:783-800

static void __secure_computing_strict(int this_syscall)
{
	const int *allowed_syscalls = mode1_syscalls;
#ifdef CONFIG_COMPAT
	if (in_compat_syscall())
		allowed_syscalls = get_compat_mode1_syscalls();
#endif
	do {
		if (*allowed_syscalls == this_syscall)
			return;
	} while (*++allowed_syscalls != -1);

#ifdef SECCOMP_DEBUG
	dump_stack();
#endif
	seccomp_log(this_syscall, SIGKILL, SECCOMP_RET_KILL_THREAD, true);
	do_exit(SIGKILL);
}

白名单 mode1_syscalls 是内核里一张写死的表（seccomp.c:778）：__NR_seccomp_read、__NR_seccomp_write、__NR_seccomp_exit、__NR_seccomp_sigreturn。这些宏在 include/asm-generic/seccomp.h 里定义成 __NR_read / __NR_write / __NR_exit / __NR_rt_sigreturn，即"只允许读写、退出和从信号处理返回"。找不到就 do_exit(SIGKILL)——注意是 SIGKILL，不可捕获。

严格模式是历史遗留（为 x86 64 移植设计），实际很少用：它连 open、execve、mmap 都不允许，进程几乎什么都干不了。

4.3 过滤器执行：seccomp_run_filters

这是整个 seccomp 的心脏。

kernel/seccomp.c:310-336

#define ACTION_ONLY(ret) ((s32)((ret) & (SECCOMP_RET_ACTION_FULL)))
static u32 seccomp_run_filters(const struct seccomp_data *sd,
			       struct seccomp_filter **match)
{
	u32 ret = SECCOMP_RET_ALLOW;
	/* Make sure cross-thread synced filter points somewhere sane. */
	struct seccomp_filter *f =
			READ_ONCE(current->seccomp.filter);

	/* Ensure unexpected behavior doesn't result in failing open. */
	if (WARN_ON(f == NULL))
		return SECCOMP_RET_KILL_PROCESS;

	/*
	 * All filters in the list are evaluated and the lowest BPF return
	 * value always takes priority (ignoring the DATA).
	 */
	for (; f; f = f->prev) {
		u32 cur_ret = bpf_prog_run_pin_on_cpu(f->prog, sd);

		if (ACTION_ONLY(cur_ret) < ACTION_ONLY(ret)) {
			ret = cur_ret;
			*match = f;
		}
	}
	return ret;
}

逐点解释：

  • ret 初值是 SECCOMP_RET_ALLOW（最宽松）。
  • WARN_ON(f == NULL) → 返回 KILL_PROCESS：fail closed。如果过滤器链表莫名其妙空了，宁可杀掉进程也不能放行——这是安全代码的基本原则。
  • for (; f; f = f->prev)：prev 指针指向上一个安装的过滤器。每次安装新过滤器都是头插，所以链表头是最新的。最新装的过滤器先跑——这个顺序很重要，因为最新加的规则通常最具体。
  • bpf_prog_run_pin_on_cpu(f->prog, sd)：在当前 CPU 上执行 BPF 程序。返回 32 位判决值。
  • ACTION_ONLY(cur_ret) < ACTION_ONLY(ret)：只比较动作部分，忽略数据部分。这就是"取最严"的实现——因为动作值编码成越大越宽松（见 3.4），取最小即最严。data 位（errno 号）只在最终选中那个过滤器时生效。
  • *match = f：记住是哪个过滤器给出的判决，后面 USER_NOTIF 需要用它。

4.4 判决处理：__seccomp_filter

kernel/seccomp.c:921-951

static int __seccomp_filter(int this_syscall, const struct seccomp_data *sd,
			    const bool recheck_after_trace)
{
	u32 filter_ret, action;
	struct seccomp_filter *match = NULL;
	int data;
	struct seccomp_data sd_local;

	/*
	 * Make sure that any changes to mode from another thread have
	 * been seen after TIF_SECCOMP was seen.
	 */
	rmb();

	if (!sd) {
		populate_seccomp_data(&sd_local);
		sd = &sd_local;
	}

	filter_ret = seccomp_run_filters(sd, &match);
	data = filter_ret & SECCOMP_RET_DATA;
	action = filter_ret & SECCOMP_RET_ACTION_FULL;

	switch (action) {
	case SECCOMP_RET_ERRNO:
		/* Set low-order bits as an errno, capped at MAX_ERRNO. */
		if (data > MAX_ERRNO)
			data = MAX_ERRNO;
		syscall_set_return_value(current, current_pt_regs(),
					 -data, 0);
		goto skip;

rmb()（读内存屏障）是为了配合安装路径里的 smp_mb__before_atomic()：保证"看到 TIF_SECCOMP 标志"之后，一定能看到已经设置好的 mode 和 filter 指针。这是 seccomp 唯一一处需要内存屏障的地方。

populate_seccomp_data 把当前系统调用的信息填进 seccomp_data：调用号、架构、指令指针、6 个参数。

SECCOMP_RET_ERRNO 的处理很直接：根本不执行这个系统调用，直接把返回值设成 -data（比如 -EPERM）。应用程序会看到一个普通的 errno，而不是知道有 seccomp 存在。

其它几个动作：

  • SECCOMP_RET_TRAP：syscall_rollback 恢复寄存器（因为系统调用参数已被破坏），然后 seccomp_send_sigsys 发 SIGSYS 信号。应用可以装 SIGSYS handler 得知"这个系统调用被拒了"。
  • SECCOMP_RET_TRACE：交给 ptrace tracer（如 gdb、strace）处理。tracer 存在时由它决定；不存在时返回 -ENOSYS（模拟"系统调用不存在"）。
  • SECCOMP_RET_USER_NOTIF：把请求转发给监听 fd 的用户态进程（用 SECCOMP_IOCTL_NOTIF_RECV 接收，SECCOMP_IOCTL_NOTIF_SEND 回复）。
  • SECCOMP_RET_LOG：记一条审计日志，但放行。用于"先观察一段时间再收紧"。
  • SECCOMP_RET_KILL_PROCESS：杀掉整个进程组（不只是调用线程）。这是最狠的动作。

4.5 BPF 程序的白名单

用户提供的 BPF 程序不是随便什么都能干。内核在加载时会检查每一条指令，只允许一小撮安全指令。

kernel/seccomp.c:231-299

static int seccomp_check_filter(struct sock_filter *filter, unsigned int flen)
{
	int pc;
	for (pc = 0; pc < flen; pc++) {
		struct sock_filter *ftest = &filter[pc];
		u16 code = ftest->code;
		u32 k = ftest->k;

		switch (code) {
		case BPF_LD | BPF_W | BPF_ABS:
			ftest->code = BPF_LDX | BPF_W | BPF_ABS;
			/* 32-bit aligned and not out of bounds. */
			if (k >= sizeof(struct seccomp_data) || k & 3)
				return -EINVAL;
			continue;
		case BPF_LD | BPF_W | BPF_LEN:
			ftest->code = BPF_LD | BPF_IMM;
			ftest->k = sizeof(struct seccomp_data);
			continue;
		case BPF_LDX | BPF_W | BPF_LEN:
			ftest->code = BPF_LDX | BPF_IMM;
			ftest->k = sizeof(struct seccomp_data);
			continue;
		/* Explicitly include allowed calls. */
		case BPF_RET | BPF_K:
		case BPF_RET | BPF_A:
		case BPF_ALU | BPF_ADD | BPF_K:
		case BPF_ALU | BPF_ADD | BPF_X:
		case BPF_ALU | BPF_SUB | BPF_K:
		case BPF_ALU | BPF_SUB | BPF_X:
		case BPF_ALU | BPF_MUL | BPF_K:
		case BPF_ALU | BPF_MUL | BPF_X:
		case BPF_ALU | BPF_DIV | BPF_K:
		case BPF_ALU | BPF_DIV | BPF_X:
		case BPF_ALU | BPF_AND | BPF_K:
		case BPF_ALU | BPF_AND | BPF_X:
		case BPF_ALU | BPF_OR | BPF_K:
		case BPF_ALU | BPF_OR | BPF_X:
		case BPF_ALU | BPF_XOR | BPF_K:
		case BPF_ALU | BPF_XOR | BPF_X:
		case BPF_ALU | BPF_LSH | BPF_K:
		case BPF_ALU | BPF_LSH | BPF_X:
		case BPF_ALU | BPF_RSH | BPF_K:
		case BPF_ALU | BPF_RSH | BPF_X:
		case BPF_ALU | BPF_NEG:
		case BPF_LD | BPF_IMM:
		case BPF_LDX | BPF_IMM:
		case BPF_MISC | BPF_TAX:
		case BPF_MISC | BPF_TXA:
		case BPF_LD | BPF_MEM:
		case BPF_LDX | BPF_MEM:
		case BPF_ST:
		case BPF_STX:
		case BPF_JMP | BPF_JA:
		case BPF_JMP | BPF_JEQ | BPF_K:
		case BPF_JMP | BPF_JEQ | BPF_X:
		case BPF_JMP | BPF_JGE | BPF_K:
		case BPF_JMP | BPF_JGE | BPF_X:
		case BPF_JMP | BPF_JGT | BPF_K:
		case BPF_JMP | BPF_JGT | BPF_X:
		case BPF_JMP | BPF_JSET | BPF_K:
		case BPF_JMP | BPF_JSET | BPF_X:
			continue;
		default:
			return -EINVAL;
		}
	}
	return 0;
}

白名单里的指令分三类：加载（从 seccomp_data 里读数据、读立即数、读写 BPF 自己的 16 个暂存寄存器）、算术（加减乘除位运算）、跳转（无条件跳转和条件跳转）、返回。没有任何"写内存到任意地址"的能力——最危险的一类指令被排除了。

注意 BPF_LD|BPF_W|BPF_ABS 被改写成 BPF_LDX|BPF_W|BPF_ABS：强制要求先加载到寄存器 X 而不是 A，这是 cBPF→eBPF 转换的遗留（避免"隐式累加器"带来的状态混淆）。

4.6 安装过滤器：no_new_privs 检查

kernel/seccomp.c:543-575

static struct seccomp_filter *seccomp_prepare_filter(struct sock_fprog *fprog)
{
	struct seccomp_filter *sfilter;
	int ret;
	const bool save_orig = IS_ENABLED(CONFIG_CHECKPOINT_RESTORE);

	if (fprog->len == 0 || fprog->len > BPF_MAXINSNS)
		return ERR_PTR(-EINVAL);

	BUG_ON(INT_MAX / fprog->len < sizeof(struct sock_filter));

	/*
	 * Installing a seccomp filter requires that the task has
	 * CAP_SYS_ADMIN in its namespace or be running with no_new_privs.
	 * This avoids scenarios where unprivileged tasks can affect the
	 * behavior of privileged children.
	 */
	if (!task_no_new_privs(current) &&
			!ns_capable_noaudit(current_user_ns(), CAP_SYS_ADMIN))
		return ERR_PTR(-EACCES);

	/* Allocate a new seccomp_filter */
	sfilter = kzalloc(sizeof(*sfilter), GFP_KERNEL | __GFP_NOWARN);
	if (!sfilter)
		return ERR_PTR(-ENOMEM);

	mutex_init(&sfilter->notify_lock);
	ret = bpf_prog_create_from_user(&sfilter->prog, fprog,
					seccomp_check_filter, save_orig);
	if (ret < 0) {
		kfree(sfilter);
		return ERR_PTR(ret);
	}

!task_no_new_privs(current) && !ns_capable_noaudit(..., CAP_SYS_ADMIN) 是核心的授权判断：两个条件都不满足才拒绝。也就是说，有 CAP_SYS_ADMIN 的进程可以无视 no_new_privs 直接装过滤器（root 就是这样）。

ns_capable_noaudit 用的是 current_user_ns()——在用户命名空间里检查能力，这正是容器里能装 seccomp 的原因（容器内 root 在自己的 user ns 里对 CAP_SYS_ADMIN 有权限）。

bpf_prog_create_from_user 的第三个参数是 seccomp_check_filter——把用户的 BPF 程序交给检查回调逐条验证，不合法的直接拒绝安装。

4.7 prctl 接口

kernel/seccomp.c:1717-1743

long prctl_set_seccomp(unsigned long seccomp_mode, void __user *filter)
{
	unsigned int op;
	void __user *uargs;

	switch (seccomp_mode) {
	case SECCOMP_MODE_STRICT:
		op = SECCOMP_SET_MODE_STRICT;
		/*
		 * Setting strict mode through prctl always ignored filter,
		 * so make sure it is always NULL here to pass the internal
		 * check in do_seccomp().
		 */
		uargs = NULL;
		break;
	case SECCOMP_MODE_FILTER:
		op = SECCOMP_SET_MODE_FILTER;
		uargs = filter;
		break;
	default:
		return -EINVAL;
	}

	/* prctl interface doesn't have flags, so they are always zero. */
	return do_seccomp(op, 0, uargs);
}

prctl(PR_SET_SECCOMP, ...) 是老接口，没有 flags 参数（所以装不了 TSYNC、NEW_LISTENER）。新接口是 seccomp(SECCOMP_SET_MODE_FILTER, flags, prog) 系统调用。

而 prctl(PR_SET_NO_NEW_PRIVS, 1, 0, 0, 0) 设置禁止提权标志，它的实现在 kernel/sys.c:2443：

kernel/sys.c:2443-2448

	case PR_SET_NO_NEW_PRIVS:
		if (arg2 != 1 || arg3 || arg4 || arg5)
			return -EINVAL;

		task_set_no_new_privs(current);
		break;

arg2 必须严格等于 1，其余参数必须为 0——这个标志一旦设置就永远不能清除，且会继承给子进程。

5. 动手验证

5.1 写一个只允许 write/exit 的最小程序

下面是完整的 C 程序，用 libseccomp 之外的纯 BPF 方式实现，方便在没有额外依赖的环境里跑：

// seccomp_demo.c —— 只允许 write 和 exit_group
#include stdio.h
#include stdlib.h
#include string.h
#include unistd.h
#include linux/filter.h
#include linux/seccomp.h
#include linux/audit.h
#include sys/prctl.h
#include sys/syscall.h
#include errno.h

#define SCMP_ACT(x) (x)
#define SCMP_ALLOW   SCMP_ACT(SECCOMP_RET_ALLOW)
#define SCMP_ERRNO(x) SCMP_ACT(SECCOMP_RET_ERRNO | (x  SECCOMP_RET_DATA))

int main(void)
{
    /* BPF 指令序列：
     *   0: 加载 seccomp_data.nr（偏移 0）
     *   1: 如果等于 __NR_write  → 跳到 6（ALLOW）
     *   2: 如果等于 __NR_exit_group → 跳到 6（ALLOW）
     *   3: 如果等于 __NR_exit → 跳到 6（ALLOW）
     *   4: 返回 ERRNO(EPERM)
     *   6: 返回 ALLOW
     */
    struct sock_filter filter[] = {
        BPF_STMT(BPF_LD | BPF_W | BPF_ABS, offsetof(struct seccomp_data, nr)),
        BPF_JUMP(BPF_JMP | BPF_JEQ | BPF_K, __NR_write, 3, 0),
        BPF_JUMP(BPF_JMP | BPF_JEQ | BPF_K, __NR_exit_group, 2, 0),
        BPF_JUMP(BPF_JMP | BPF_JEQ | BPF_K, __NR_exit, 1, 0),
        BPF_STMT(BPF_RET | BPF_K, SCMP_ERRNO(EPERM)),
        BPF_STMT(BPF_RET | BPF_K, SCMP_ALLOW),
    };
    struct sock_fprog prog = {
        .len = sizeof(filter) / sizeof(filter[0]),
        .filter = filter,
    };

    /* 1. 禁止提权，这样不需要 root 也能装过滤器 */
    if (prctl(PR_SET_NO_NEW_PRIVS, 1, 0, 0, 0)  0) {
        perror("prctl(NO_NEW_PRIVS)");
        return 1;
    }

    /* 2. 装过滤器 */
    if (syscall(__NR_seccomp, SECCOMP_SET_MODE_FILTER, 0, prog)  0) {
        perror("seccomp");
        return 1;
    }

    /* 3. 现在只有 write / exit / exit_group 可用 */
    write(1, "write 成功\n", 10);

    /* 4. 尝试 open()，应该返回 EPERM */
    int fd = open("/etc/passwd", 0);
    printf("open 返回 %d, errno=%d (%s)\n", fd, errno, strerror(errno));

    /* 5. 尝试 fork()，应该返回 EPERM */
    pid_t p = fork();
    printf("fork 返回 %d, errno=%d (%s)\n", (int)p, errno, strerror(errno));

    return 0;
}

编译运行：

gcc -O2 -Wall -o seccomp_demo seccomp_demo.c
./seccomp_demo
# 预期输出：
# write 成功
# open 返回 -1, errno=1 (Operation not permitted)
# fork 返回 -1, errno=1 (Operation not permitted)

注意：printf 内部可能会调用 write（允许）和 newfstatat（不允许）——glibc 的 printf 会先 fstat 判断是终端还是管道。所以严格来说应该把 newfstatat 也加进白名单，或者用 write 直接输出。上面的代码在多数情况下 printf 仍能工作（因为 stdout 已缓存时不需要 fstat），但更稳妥的写法是全部用 write。

5.2 用 libseccomp 写同样的东西（更简洁）

// 需要 libseccomp-dev
#include seccomp.h
#include stdio.h
#include unistd.h
#include errno.h

int main(void)
{
    scmp_filter_ctx ctx;
    seccomp_init(ctx);
    seccomp_rule_add(ctx, SCMP_ACT_ALLOW, SCMP_SYS(write), 0);
    seccomp_rule_add(ctx, SCMP_ACT_ALLOW, SCMP_SYS(exit_group), 0);
    seccomp_rule_add(ctx, SCMP_ACT_ALLOW, SCMP_SYS(exit), 0);
    seccomp_rule_add(ctx, SCMP_ACT_ERRNO(EPERM), SCMP_SYS(open), 0);
    seccomp_load(ctx);          /* 内部会先 prctl(PR_SET_NO_NEW_PRIVS) */
    write(1, "OK\n", 3);
    printf("open=%d errno=%d\n", open("/etc/passwd", 0), errno);
    return 0;
}

6. 自测

Q1. seccomp 的三种模式分别是什么？DISABLED(0) 不限制；STRICT(1) 内核硬编码只允许 read、write、exit、rt_sigreturn，其余 SIGKILL；FILTER(2) 由用户提供的 BPF 程序决定每个系统调用的命运。
Q2. 多个过滤器同时存在时怎么合成？全部执行一遍，每个过滤器的判决按"动作部分"比较（ACTION_ONLY 掩掉数据位），取动作值最小的那个。因为动作编码成越严越小，所以取最小即取最严。
Q3. 为什么安装 seccomp 过滤器需要 no_new_privs 或 CAP_SYS_ADMIN？防止低权限进程给自己装过滤器后 exec 出一个高权限的 setuid 程序，导致那个高权限程序的行为被过滤器限制（甚至被用来规避某些检查）。no_new_privs 保证 exec 不会带来新权限。
Q4. seccomp_run_filters 里为什么要用 WARN_ON(f == NULL) 返回 KILL_PROCESS？fail closed 原则。过滤器链表异常为空时若返回 ALLOW 就是"失效即放行"（fail open），是最危险的行为。宁可误杀也不能放行。
Q5. BPF 程序为什么不能有向后跳转？向后跳转会形成循环，可能永不终止，导致系统调用 hang 死。BPF 只允许向前跳转，保证一定终止，内核在加载时（seccomp_check_filter）也只放行 BPF_JMP|BPF_JA 和条件跳转这些向前跳的指令。
Q6. SECCOMP_RET_ERRNO 和 SECCOMP_RET_TRAP 的区别？ERRNO 直接把系统调用返回值设为 -data（如 -EPERM），系统调用根本不执行，应用看不出有 seccomp；TRAP 会发 SIGSYS 信号，应用可以装 handler 得知被拒的具体系统调用号（SIGSYS 的 si_syscall 字段）。
Q7. 怎么知道某个进程装了 seccomp 过滤器？cat /proc/PID/status，看 Seccomp 字段（0/1/2 表示模式）和 Seccomp_filters 字段（过滤器个数）。
Q8. seccomp 和 namespace 是什么关系？正交互补。namespace 管"能看到什么"（隔离文件、进程、网络视图），seccomp 管"能做什么操作"（限制系统调用集合）。容器通常两者并用。
