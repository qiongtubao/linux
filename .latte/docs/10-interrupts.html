⚡ 中断：硬件按门铃与内核的分层处理

一个中断号找到一张表，一个向量找到一段汇编，处理工作被切成硬中断、软中断、tasklet、工作队列四层 · 预计阅读 30 分钟

1. 它在解决什么问题

你正在专心读一本书，突然有人敲门。你有两个选择：立刻放下书去开门（打断当前工作），或者在门边放张纸条写"我在忙，稍后"，先把手头这事做完再去。

计算机里的中断就是这件事。网卡收到一个包、磁盘读完了、键盘按了键、定时器到点了——这些硬件事件必须让 CPU 知道。但 CPU 此刻可能正在跑一个很长的计算，如果每次事件都立刻停下所有工作去处理，系统效率会崩掉。所以内核用了分层的办法：

  • 上半部（hardirq）：硬件事件刚到时的"接待工作"。必须极快——不能睡眠、不能加阻塞锁、不能做耗时的操作。通常就是读一下设备寄存器、ack 一下硬件、把数据放进环形缓冲区，然后立刻返回。
  • 下半部（bottom half）：真正的"正事"。可以耗时、可以睡眠、可以排队。由软中断（softirq）、tasklet、工作队列（workqueue）三种机制承载。

从 OS 视角看，中断机制要解决三个问题：① 硬件事件怎么变成 CPU 能识别的"向量"；② CPU 怎么知道这个向量对应哪段处理代码；③ 处理代码怎么在"极短时间 + 禁止睡眠"的约束下把工作分发出去。三个问题分别对应本文的三块内容：APIC/IDT、request_irq()、下半部三种机制。

还要记住一个约束：中断上下文里不能睡眠。因为一旦在中断处理里睡眠，CPU 就得切换到别的进程，而中断处理还没做完——那个进程可能在操作同一份数据。这是内核里最常见的"不能这么做"的原因，后面 in_interrupt() 这个函数就是用来做这种检查的。

3. 整体结构

3.1 从硬件事件到内核代码

设备产生事件（如网卡收到包）
    │  拉低 IRQ 引脚
    ▼
IO-APIC 芯片：记录"哪个 IRQ 线有事件"，决定送给哪个 CPU
    │  通过 APIC 总线发消息
    ▼
Local APIC（LAPIC）：把消息变成一个"中断向量号"，写进 APIC 的 ISR 寄存器
    │  通知 CPU
    ▼
CPU：保存当前上下文 → 查 IDT[vector] → 跳到对应的汇编入口
    │  （栈切换到中断栈 / 内核栈，关闭中断）
    ▼
asm_common_interrupt → common_interrupt()      arch/x86/kernel/irq.c
    │  desc = __this_cpu_read(vector_irq[vector])
    ▼
handle_irq(desc, regs) → handle_irq_event(desc)   kernel/irq/handle.c
    │  遍历 desc->action 链，逐个调用 action->handler(irq, dev_id)
    ▼
驱动注册的 handler（硬中断上下文）
    │  · 读设备寄存器取数据
    │  · ack 硬件
    │  · 把数据放进 ring buffer
    │  · 启动下半部：tasklet_schedule() / queue_work() / raise_softirq()
    ▼
返回 → 恢复上下文 → 回到被打断的地方
    │
    ▼
稍后（在退出中断上下文时，或由 ksoftirqd 线程）：
    __do_softirq()  →  依次执行待处理的 softirq
        TASKLET_SOFTIRQ → 跑 tasklet 队列
    或
    kworker/0:1 线程 → 跑 workqueue 里的 work

3.2 上半部 vs 下半部

维度上半部（hardirq handler）下半部（softirq / tasklet / workqueue）
执行上下文中断上下文（关中断、不可抢占调度）softirq：关 BH 的软中断上下文
workqueue：普通内核线程上下文
能否睡眠绝对不能softirq/tasklet 不能；workqueue 可以
能用的锁只能用自旋锁（不能关中断地拿）softirq 同上；workqueue 可用互斥锁、可睡眠
并发性同一 CPU 上不重入；不同 CPU 上同一 IRQ 默认串行tasklet 在同一 CPU 上串行；workqueue 可多线程并行
典型耗时微秒级，必须 < 整个系统能容忍的延迟不限
典型用途读寄存器、ack 硬件、填环形缓冲协议栈处理、磁盘 I/O 提交、文件系统操作
为什么上半部不能睡眠？中断处理期间 CPU 的 IF 标志（中断使能）通常是关的。如果此时调用 schedule() 切走，等于"在一个还没做完的半截操作中间把 CPU 让给别人"。更糟的是，被唤醒的进程可能正在操作同一份数据——比如网卡驱动的 ring buffer——于是出现难以复现的竞态。

3.3 三种下半部机制怎么选

硬中断 handler 里发生了什么
    │
    ├─ 只是"标记一下有待办事项"（置个标志位）？
    │     └─→ raise_softirq(NET_RX_SOFTIRQ)  → 软中断机制
    │
    ├─ 要做点收尾工作，但很快、不能睡眠？
    │     └─→ tasklet_schedule()             → tasklet 机制
    │
    └─ 工作量大 / 要睡眠 / 要并行？
          └─→ queue_work()                    → 工作队列机制
机制执行者能否睡眠并行度适用
softirq退出中断时由当前 CPU 跑，或 ksoftirqd否各 CPU 独立网络收包等高频路径
tasklet跑在 TASKLET_SOFTIRQ 里否同一 CPU 串行轻量收尾，常配合 spin_lock
workqueue内核线程 kworker/N:M能可多线程耗时、需要睡眠、需要并行的活

3.4 IDT：CPU 的"中断跳转表"

IDT（Interrupt Descriptor Table）是 CPU 内部的一张 256 项的表，每项 16 字节，存着"这个向量对应哪个处理程序、什么类型的门、什么特权级"。CPU 收到中断后，用向量号直接查表跳转——这是一次硬件查表，非常快。

门类型（GATE_INTERRUPT / GATE_TRAP）决定了两件事：处理期间中断是否自动关闭，以及返回时用 iret 还是别的指令。Linux 的普通中断和异常几乎都用中断门（处理期间 IF 自动清零，避免中断嵌套带来的复杂度）。

3.5 十个软中断向量

软中断不是硬件概念，是内核自己"记账"的一套机制。内核定义了 10 个软中断编号，每个对应一类工作：

enum
{
	HI_SOFTIRQ=0,       /* 高优先级推迟任务 */
	TIMER_SOFTIRQ,      /* 定时器 */
	NET_TX_SOFTIRQ,     /* 网络发送 */
	NET_RX_SOFTIRQ,     /* 网络接收 */
	BLOCK_SOFTIRQ,      /* 块设备 */
	IRQ_POLL_SOFTIRQ,   /* 轮询 */
	TASKLET_SOFTIRQ,    /* tasklet 队列 */
	SCHED_SOFTIRQ,      /* 调度器 */
	HRTIMER_SOFTIRQ,    /* 高精度定时器 */
	RCU_SOFTIRQ,        /* RCU（读侧无锁） */
	NR_SOFTIRQS
};

每个 CPU 有一份"待处理软中断位图"，置位表示"这个软中断有事要做"。__do_softirq() 在退出中断上下文时逐个检查并执行。

4. 源码走读

4.1 IDT 的搭建：arch/x86/kernel/idt.c

IDT 表项用几个宏来声明。核心的 G() 宏把"向量号、门类型、特权级、处理程序地址"塞进一个 struct idt_data：

arch/x86/kernel/idt.c:19-43 IDT 表项宏

#define G(_vector, _addr, _ist, _type, _dpl, _segment)	\
	{						\
		.vector		= _vector,		\
		.bits.ist	= _ist,			\
		.bits.type	= _type,		\
		.bits.dpl	= _dpl,		\
		.bits.p		= 1,		\
		.addr		= _addr,		\
		.segment	= _segment,		\
	}

/* Interrupt gate */
#define INTG(_vector, _addr)				\
	G(_vector, _addr, DEFAULT_STACK, GATE_INTERRUPT, DPL0, __KERNEL_CS)

/* System interrupt gate */
#define SYSG(_vector, _addr)				\
	G(_vector, _addr, DEFAULT_STACK, GATE_INTERRUPT, DPL3, __KERNEL_CS)

/*
 * Interrupt gate with interrupt stack. The _ist index is the index in
 * the tss.ist[] array, but for the descriptor it needs to start at 1.
 */
#define ISTG(_vector, _addr, _ist)			\
	G(_vector, _addr, _ist + 1, GATE_INTERRUPT, DPL0, __KERNEL_CS)
  • INTG：普通中断门，DPL0（只能内核态触发）、用默认栈（当前内核栈）。
  • SYSG：系统中断门，DPL3——用户态也能触发，比如 int 0x80（老式系统调用入口）。
  • ISTG：带专用中断栈（IST）的门。用于那些"处理时绝不能用当前栈"的场合，比如双重故障（#DF）——如果连栈都坏了，得换一条备用栈来跑处理程序。

可以看到：除零（#DE）、非法指令（#UD）、通用保护异常（#GP）等都是固定向量；而普通外设中断的向量是动态分配的，装在 apic_idts[] 之后由 idt_setup_apic_and_irq_gates() 批量装填：

arch/x86/kernel/idt.c:283-314 idt_setup_apic_and_irq_gates

void __init idt_setup_apic_and_irq_gates(void)
{
	int i = FIRST_EXTERNAL_VECTOR;
	void *entry;

	idt_setup_from_table(idt_table, apic_idts, ARRAY_SIZE(apic_idts), true);

	for_each_clear_bit_from(i, system_vectors, FIRST_SYSTEM_VECTOR) {
		entry = irq_entries_start + 8 * (i - FIRST_EXTERNAL_VECTOR);
		set_intr_gate(i, entry);
	}

#ifdef CONFIG_X86_LOCAL_APIC
	for_each_clear_bit_from(i, system_vectors, NR_VECTORS) {
		/*
		 * Don't set the non assigned system vectors in the
		 * system_vectors bitmap. Otherwise they show up in
		 * /proc/interrupts.
		 */
		entry = spurious_entries_start + 8 * (i - FIRST_SYSTEM_VECTOR);
		set_intr_gate(i, entry);
	}
#endif
	/* Map IDT into CPU entry area and reload it. */
	idt_map_in_cea();
	load_idt(&idt_descr);

	/* Make the IDT table read only */
	set_memory_ro((unsigned long)&idt_table, 1);

	idt_setup_done = true;
}

几个关键点：

  • 外设中断向量对应的是一段汇编模板（irq_entries_start 处的 common_interrupt 汇编），不是一个 C 函数。CPU 跳过去的是汇编，汇编负责保存现场后调用 C 代码。
  • set_memory_ro() 把 IDT 设成只读，防止攻击者通过任意写把 IDT 表项改掉（那等于给自己造一个任意代码执行的后门）。
  • idt_map_in_cea() 把 IDT 映射到 CPU Entry Area 的固定地址，sidt 指令读不到真实地址——这是内核硬化措施（KASLR 的一部分）。

4.2 从向量找到处理函数：common_interrupt()

CPU 跳进汇编入口后，最终会走到这个 C 函数：

arch/x86/kernel/irq.c:235-263 common_interrupt

/*
 * common_interrupt() handles all normal device IRQ's (the special SMP
 * cross-CPU interrupts have their own entry points).
 */
DEFINE_IDTENTRY_IRQ(common_interrupt)
{
	struct pt_regs *old_regs = set_irq_regs(regs);
	struct irq_desc *desc;

	/* entry code tells RCU that we're not quiescent.  Check it. */
	RCU_LOCKDEP_WARN(!rcu_is_watching(), "IRQ failed to wake up RCU");

	desc = __this_cpu_read(vector_irq[vector]);
	if (likely(!IS_ERR_OR_NULL(desc))) {
		handle_irq(desc, regs);
	} else {
		ack_APIC_irq();

		if (desc == VECTOR_UNUSED) {
			pr_emerg_ratelimited("%s: %d.%u No irq handler for vector\n",
					     __func__, smp_processor_id(),
					     vector);
		} else {
			__this_cpu_write(vector_irq[vector], VECTOR_UNUSED);
		}
	}

	set_irq_regs(old_regs);
}
  • vector_irq[vector]：一张 per-CPU 数组，把"向量号"映射到 struct irq_desc。这是从硬件世界（向量）到内核世界（irq_desc）的转换点。
  • handle_irq(desc, regs)：最终会走到 handle_irq_event()，遍历该 IRQ 上的所有 irqaction 逐个调用。
  • 找不到 handler 时要 ack_APIC_irq()——不然这个中断会不断重发，形成"中断风暴"。
  • VECTOR_UNUSED 与 ERR_VECTOR 是两个特殊值，分别表示"这个向量空着"和"收到了伪中断/spurious 中断"。

4.3 注册中断：request_irq()

用户态 API 是 request_irq()，内核里的原型和文档在 include/linux/interrupt.h：

include/linux/interrupt.h:143-161 request_irq

/**
 * request_irq - Add a handler for an interrupt line
 * @irq:	The interrupt line to allocate
 * @handler:	Function to be called when the IRQ occurs.
 *		Primary handler for threaded interrupts
 *		If NULL, the default primary handler is installed
 * @flags:	Handling flags
 * @name:	Name of the device generating this interrupt
 * @dev:	A cookie passed to the handler function
 *
 * This call allocates an interrupt and establishes a handler; see
 * the documentation for request_threaded_irq() for details.
 */
static inline int __must_check
request_irq(unsigned int irq, irq_handler_t handler, unsigned long flags,
	    const char *name, void *dev)
{
	return request_threaded_irq(irq, handler, NULL, flags, name, dev);
}

request_irq() 只是 request_threaded_irq() 的薄封装（不建线程）。真正的实现：

kernel/irq/manage.c:2002-2086 request_threaded_irq

int request_threaded_irq(unsigned int irq, irq_handler_t handler,
			 irq_handler_t thread_fn, unsigned long irqflags,
			 const char *devname, void *dev_id)
{
	struct irqaction *action;
	struct irq_desc *desc;
	int retval;

	if (irq == IRQ_NOTCONNECTED)
		return -ENOTCONN;

	/*
	 * Sanity-check: shared interrupts must pass in a real dev-ID,
	 * otherwise we'll have trouble later trying to figure out
	 * which interrupt is which (messes up the interrupt freeing
	 * logic etc).
	 *
	 * Also IRQF_COND_SUSPEND only makes sense for shared interrupts and
	 * it cannot be set along with IRQF_NO_SUSPEND.
	 */
	if (((irqflags & IRQF_SHARED) && !dev_id) ||
	    (!(irqflags & IRQF_SHARED) && (irqflags & IRQF_COND_SUSPEND)) ||
	    ((irqflags & IRQF_NO_SUSPEND) && (irqflags & IRQF_COND_SUSPEND)))
		return -EINVAL;

	desc = irq_to_desc(irq);
	if (!desc)
		return -EINVAL;

	if (!irq_settings_can_request(desc) ||
	    WARN_ON(irq_settings_is_per_cpu_devid(desc)))
		return -EINVAL;

	if (!handler) {
		if (!thread_fn)
			return -EINVAL;
		handler = irq_default_primary_handler;
	}

	action = kzalloc(sizeof(struct irqaction), GFP_KERNEL);
	if (!action)
		return -ENOMEM;

	action->handler = handler;
	action->thread_fn = thread_fn;
	action->flags = irqflags;
	action->name = devname;
	action->dev_id = dev_id;

	retval = irq_chip_pm_get(&desc->irq_data);
	if (retval < 0) {
		kfree(action);
		return retval;
	}

	retval = __setup_irq(irq, desc, action);
	// ... （此处约 35 行：失败时清理，DEBUG_SHIRQ_FIXME 下还要试跑一次 handler）
	return retval;
}
EXPORT_SYMBOL(request_threaded_irq);
  • IRQ_NOTCONNECTED（1U << 31）是个特殊标记，表示"这个设备的 IRQ 没接上"，返回 -ENOTCONN 区别于其他错误。
  • 共享中断必须传非空 dev_id：因为一条 IRQ 上可能挂着多个设备，free_irq() 时靠 dev_id 区分要卸哪一个。返回 -EINVAL 就是这个检查。
  • action->name 就是你在 /proc/interrupts 里看到的那串设备名。
  • __setup_irq() 才是真正把 action 挂到 desc->action 链表上、配置硬件（enable/mask 中断线）的地方。

注销用 free_irq()：

kernel/irq/manage.c:1866-1905 free_irq

/**
 *	free_irq - free an interrupt allocated with request_irq
 *	@irq: Interrupt line to free
 *	@dev_id: Device identity to free
 *
 *	Remove an interrupt handler. The handler is removed and if the
 *	interrupt line is no longer in use by any driver it is disabled.
 *	On a shared IRQ the caller must ensure the interrupt is disabled
 *	on the card it drives before calling this function. The function
 *	does not return until any executing interrupts for this IRQ
 *	have completed.
 *
 *	This function must not be called from interrupt context.
 *
 *	Returns the devname argument passed to request_irq.
 */
const void *free_irq(unsigned int irq, void *dev_id)
{
	struct irq_desc *desc = irq_to_desc(irq);
	struct irqaction *action;
	const char *devname;

	if (!desc || WARN_ON(irq_settings_is_per_cpu_devid(desc)))
		return NULL;

#ifdef CONFIG_SMP
	if (WARN_ON(desc->affinity_notify))
		desc->affinity_notify = NULL;
#endif

	action = __free_irq(desc, dev_id);

	if (!action)
		return NULL;

	devname = action->name;
	kfree(action);
	return devname;
}
EXPORT_SYMBOL(free_irq);

注意两点：① 它返回的是之前 request_irq() 传的 devname（不是 name 字段），方便驱动做校验；② 注释明确说了"不能在中断上下文里调用"——它要拿 desc->request_mutex 并等待正在执行的中断结束。

4.4 上半部的分发：handle_irq_event()

驱动注册的 handler 最终在这里被调用：

kernel/irq/handle.c:137-183 __handle_irq_event_percpu

irqreturn_t __handle_irq_event_percpu(struct irq_desc *desc, unsigned int *flags)
{
	irqreturn_t retval = IRQ_NONE;
	unsigned int irq = desc->irq_data.irq;
	struct irqaction *action;

	record_irq_time(desc);

	for_each_action_of_desc(desc, action) {
		irqreturn_t res;

		/*
		 * If this IRQ would be threaded under force_irqthreads, mark it so.
		 */
		if (irq_settings_can_thread(desc) &&
		    !(action->flags & (IRQF_NO_THREAD | IRQF_PERCPU | IRQF_ONESHOT)))
			lockdep_hardirq_threaded();

		trace_irq_handler_entry(irq, action);
		res = action->handler(irq, action->dev_id);
		trace_irq_handler_exit(irq, action, res);

		if (WARN_ONCE(!irqs_disabled(),"irq %u handler %pS enabled interrupts\n",
			      irq, action->handler))
			local_irq_disable();

		switch (res) {
		case IRQ_WAKE_THREAD:
			/*
			 * Catch drivers which return WAKE_THREAD but
			 * did not set up a thread function
			 */
			if (unlikely(!action->thread_fn)) {
				warn_no_thread(irq, action);
				break;
			}

			__irq_wake_thread(desc, action);

			fallthrough;	/* to add to randomness */
		case IRQ_HANDLED:
			*flags |= action->flags;
			break;

		default:
			break;
		}
		// ... （此处约 15 行：累加 retval、统计中断次数）
	}
	// ...
}
  • for_each_action_of_desc() 遍历 desc->action 链表——共享中断时链上有多份 irqaction，逐个问"是不是你的设备"。
  • action->handler(irq, action->dev_id) 就是驱动注册的函数。
  • 返回 IRQ_HANDLED 表示"确实是我的，处理完了"；IRQ_NONE 表示"不是我的"（共享中断时用来告诉控制器别再重发）。
  • 返回 IRQ_WAKE_THREAD 时，内核唤醒该 IRQ 专属的中断线程，由它去执行 action->thread_fn——这就是"线程化中断"：把耗时的活挪出硬中断上下文。
  • 那个 WARN_ONCE(!irqs_disabled(), ...) 是护栏：驱动 handler 里如果错误地开了中断，lockdep 会报警。

4.5 软中断：十个向量与调度

软中断向量定义在 include/linux/interrupt.h：

include/linux/interrupt.h:528-544 软中断向量枚举

enum
{
	HI_SOFTIRQ=0,
	TIMER_SOFTIRQ,

名字表在 kernel/softirq.c，与枚举顺序严格对应：

kernel/softirq.c:59-62 softirq_to_name

const char * const softirq_to_name[NR_SOFTIRQS] = {
	"HI", "TIMER", "NET_TX", "NET_RX", "BLOCK", "IRQ_POLL",

置位与执行：

kernel/softirq.c:456-487 raise_softirq_irqoff / __raise_softirq_irqoff

inline void raise_softirq_irqoff(unsigned int nr)
{
	__raise_softirq_irqoff(nr);

	/*
	 * If we're in an interrupt or softirq, we're done
	 * (this also catches softirq-disabled code). We will
	 * actually run the softirq once we return from
	 * the irq or softirq.
	 *
	 * Otherwise we wake up ksoftirqd to make sure we
	 * schedule the softirq soon.
	 */
	if (!in_interrupt())
		wakeup_softirqd();
}

void raise_softirq(unsigned int nr)
{
	unsigned long flags;

	local_irq_save(flags);
	raise_softirq_irqoff(nr);
	local_irq_restore(flags);
}

void __raise_softirq_irqoff(unsigned int nr)
{
	lockdep_assert_irqs_disabled();
	trace_softirq_raise(nr);
	or_softirq_pending(1UL << nr);
}
  • or_softirq_pending(1UL << nr)：把本 CPU 的软中断待处理位图置位。是"记账"，不是执行。位图本体是 per-CPU 的 irq_stat.__softirq_pending（include/linux/interrupt.h:503），声明在 arch/x86/include/asm/hardirq.h:8。
  • 如果在中断上下文里，就靠 __do_softirq() 在退出时统一执行；否则唤醒 ksoftirqd 线程，让它去执行。
  • 为什么要 ksoftirqd？因为软中断是"可选的延迟"——如果当前进程一直没退出中断上下文，软中断可能饿死。专门有个线程兜底。

4.6 tasklet：__tasklet_schedule()

tasklet 跑在 TASKLET_SOFTIRQ 里。它的调度就是把 tasklet 挂到本 CPU 的链表，再置起 TASKLET_SOFTIRQ：

kernel/softirq.c:505-533 __tasklet_schedule_common / __tasklet_schedule

static void __tasklet_schedule_common(struct tasklet_struct *t,
				      struct tasklet_head __percpu *headp,
				      unsigned int softirq_nr)
{
	struct tasklet_head *head;
	unsigned long flags;

	local_irq_save(flags);
	head = this_cpu_ptr(headp);
	t->next = NULL;
	*head->tail = t;
	head->tail = &(t->next);
	raise_softirq_irqoff(softirq_nr);
	local_irq_restore(flags);
}

void __tasklet_schedule(struct tasklet_struct *t)
{
	__tasklet_schedule_common(t, &tasklet_vec,
				  TASKLET_SOFTIRQ);
}
EXPORT_SYMBOL(__tasklet_schedule);

void __tasklet_hi_schedule(struct tasklet_struct *t)
{
	__tasklet_schedule_common(t, &tasklet_hi_vec,
				  HI_SOFTIRQ);
}
EXPORT_SYMBOL(__tasklet_hi_schedule);
  • local_irq_save(flags)：关中断保护链表操作。因为 tasklet_vec 是 per-CPU 的，中断可能在任意时刻来抢占并调度另一个 tasklet。
  • raise_softirq_irqoff(TASKLET_SOFTIRQ)：置位软中断，稍后由 __do_softirq() 执行。
  • __tasklet_hi_schedule() 挂到 tasklet_hi_vec 并置 HI_SOFTIRQ——优先级更高的那一条队列。软中断执行时 HI_SOFTIRQ 序号最小，先被处理。
  • tasklet_schedule()（include/linux/interrupt.h:681-685）是用户态 API：它先用 test_and_set_bit(TASKLET_STATE_SCHED) 判重，确保同一个 tasklet 不会重复入队。

4.7 工作队列：queue_work() 与 worker_thread()

工作队列是"能睡觉"的下半部。它由若干内核线程（kworker/N:M）执行任务。

include/linux/workqueue.h:504-508 queue_work

static inline bool queue_work(struct workqueue_struct *wq,
			      struct work_struct *work)
{
	return queue_work_on(WORK_CPU_UNBOUND, wq, work);
}

真正干活的是 queue_work_on()：

kernel/workqueue.c:1830-1846 queue_work_on

bool queue_work_on(int cpu, struct workqueue_struct *wq,
		   struct work_struct *work)
{
	bool ret = false;
	unsigned long flags;

	local_irq_save(flags);

	if (!test_and_set_bit(WORK_STRUCT_PENDING_BIT, work_data_bits(work))) {
		__queue_work(cpu, wq, work);
		ret = true;
	}

	local_irq_restore(flags);
	return ret;
}
EXPORT_SYMBOL(queue_work_on);
  • WORK_STRUCT_PENDING_BIT 判重：同一个 work 已经在队列里就返回 false，不会重复执行。
  • local_irq_save() 是为了保证"判重 + 入队"这两步的原子性——否则两个 CPU 同时 queue 同一个 work 就会执行两次。
  • 返回 true 表示"成功排队"。

执行者是内核线程：

kernel/workqueue.c:2857-2925 worker_thread

static int worker_thread(void *__worker)
{
	struct worker *worker = __worker;
	struct worker_pool *pool = worker->pool;

	/* tell the scheduler that this is a workqueue worker */
	set_pf_worker(true);
woke_up:
	raw_spin_lock_irq(&pool->lock);

	/* am I supposed to die? */
	if (unlikely(worker->flags & WORKER_DIE)) {
		raw_spin_unlock_irq(&pool->lock);
		WARN_ON_ONCE(!list_empty(&worker->entry));
		set_pf_worker(false);

		set_task_comm(worker->task, "kworker/dying");
		ida_simple_remove(&pool->worker_ida, worker->id);
		worker_detach_from_pool(worker);
		kfree(worker);
		return 0;
	}

	worker_leave_idle(worker);
recheck:
	/* no more worker necessary? */
	if (!need_more_worker(pool))
		goto sleep;

	/* do we need to manage? */
	if (unlikely(!may_start_working(pool)) && manage_workers(worker))
		goto recheck;
	// ... （此处约 20 行注释：说明 scheduled 列表的并发约定）
	do {
		struct work_struct *work =
			list_first_entry(&pool->worklist,
					 struct work_struct, entry);

		pool->watchdog_ts = jiffies;

		if (likely(!(*work_data_bits(work) & WORK_STRUCT_LINKED))) {
			/* optimization path, not strictly necessary */
			process_one_work(worker, work);
			if (unlikely(!list_empty(&worker->scheduled)))
				process_scheduled_works(worker);
		} else {
			move_linked_works(work, &worker->scheduled, NULL);
			process_scheduled_works(worker);
		}
	} while (keep_working(pool));

	worker_set_flags(worker, WORKER_PREP);
sleep:
	// ... （此处约 20 行：进入空闲、挂到等待队列、睡眠等待唤醒）
}
  • set_pf_worker(true)：告诉调度器"我是工作线程"，这样 schedule() 的行为和普通进程区分开。
  • 主循环就是：从 pool->worklist 取第一个 work，process_one_work() 执行它。
  • 没活干时 need_more_worker() 为假 → goto sleep，线程睡在等待队列上，有新 work 时被唤醒。
  • manage_workers() 是动态并发管理：WQ_UNBOUND 队列在系统繁忙时会自动增加线程数，闲时再缩回去。

4.8 判断上下文：in_interrupt() 与 local_bh_disable()

这两个宏是写内核代码时的"安全带"。

include/linux/preempt.h:80-104 上下文判定宏

#define hardirq_count()	(preempt_count() & HARDIRQ_MASK)
#define softirq_count()	(preempt_count() & SOFTIRQ_MASK)
#define irq_count()	(preempt_count() & (HARDIRQ_MASK | SOFTIRQ_MASK \
				 | NMI_MASK))

/*
 * Are we doing bottom half or hardware interrupt processing?
 *
 * in_irq()       - We're in (hard) IRQ context
 * in_softirq()   - We have BH disabled, or are processing softirqs
 * in_interrupt() - We're in NMI,IRQ,SoftIRQ context or have BH disabled
 * in_serving_softirq() - We're in softirq context
 * in_nmi()       - We're in NMI context
 * in_task()	  - We're in task context
 *
 * Note: due to the BH disabled confusion: in_softirq(),in_interrupt() really
 *       should not be used in new code.
 */
#define in_irq()		(hardirq_count())
#define in_softirq()		(softirq_count())
#define in_interrupt()		(irq_count())
#define in_serving_softirq()	(softirq_count() & SOFTIRQ_OFFSET)
#define in_nmi()		(preempt_count() & NMI_MASK)
#define in_task()		(!(preempt_count() & \
				   (NMI_MASK | HARDIRQ_MASK | SOFTIRQ_OFFSET)))

实现原理很朴素：preempt_count() 这个 per-CPU 变量用不同的位段记录"当前嵌套了几层中断"。进硬中断时硬件/汇编把 HARDIRQ 位加上，进软中断时加 SOFTIRQ 位，关 BH 时加 SOFTIRQ_DISABLE 位。所以 in_interrupt() 就是一次位与运算，代价接近于零。

local_bh_disable() 则是"我这个小临界区里别来软中断插队"：

include/linux/bottom_half.h:1-35 local_bh_disable

/* SPDX-License-Identifier: GPL-2.0 */
#ifndef _LINUX_BH_H
#define _LINUX_BH_H

#include <linux/preempt.h>

#ifdef CONFIG_TRACE_IRQFLAGS
extern void __local_bh_disable_ip(unsigned long ip, unsigned int cnt);
#else
static __always_inline void __local_bh_disable_ip(unsigned long ip, unsigned int cnt)
{
	preempt_count_add(cnt);
	barrier();
}
#endif

static inline void local_bh_disable(void)
{
	__local_bh_disable_ip(_THIS_IP_, SOFTIRQ_DISABLE_OFFSET);
}

extern void _local_bh_enable(void);
extern void __local_bh_enable_ip(unsigned long ip, unsigned int cnt);

static inline void local_bh_enable_ip(unsigned long ip)
{
	__local_bh_enable_ip(ip, SOFTIRQ_DISABLE_OFFSET);
}

static inline void local_bh_enable(void)
{
	__local_bh_enable_ip(_THIS_IP_, SOFTIRQ_DISABLE_OFFSET);
}

#endif /* _LINUX_BH_H */

SOFTIRQ_DISABLE_OFFSET 定义在 include/linux/preempt.h:54：#define SOFTIRQ_DISABLE_OFFSET (2 * SOFTIRQ_OFFSET)。它不是真的关硬件中断，而是把 preempt_count 里"软中断禁用"的计数加上去，让 __do_softirq() 知道自己现在不该跑。

软禁用 vs 硬禁用：local_bh_disable() 只挡住软中断，硬中断照样能打断你；local_irq_disable() 才是真的关 CPU 的中断使能位。前者便宜得多（不碰硬件寄存器），是绝大多数内核代码保护短临界区的首选。

6. 自测

Q1. request_irq() 和 free_irq() 必须成对吗？必须。free_irq() 内部要拿 desc->request_mutex 并等待该 IRQ 上正在执行的中断结束（kernel/irq/manage.c:1882），所以它不能在中断上下文里调用。而且如果 request_irq() 失败（比如 -ENOMEM），驱动必须自己清理已申请的硬件资源。
Q2. 共享中断（IRQF_SHARED）时，多个 handler 都会被调用吗？都会调用。__handle_irq_event_percpu() 遍历 desc->action 链表，把每个 action->handler 都调一遍。每个 handler 要通过检查 dev_id 判断"这个中断是不是我的"，不是就返回 IRQ_NONE。这就是为什么共享中断必须传非空 dev_id——内核没法靠返回值区分设备。
Q3. tasklet 和 workqueue 到底怎么选？看要不要睡眠和要不要并行。要睡眠或要并行（同一份工作拆给多个线程）→ workqueue。仅仅是"收个尾"、很快、不睡 → tasklet。而且注意：tasklet 跑在软中断上下文，不能调 sleep()、不能拿互斥锁（可睡眠的锁），只能拿自旋锁。
Q4. in_interrupt() 返回真时，为什么不能调用 mutex_lock()？因为可睡眠的互斥锁在拿不到锁时会调用 schedule() 把自己挂起。而中断处理还没做完，CPU 一旦切走，另一个进程可能正在操作同一份数据（比如驱动的 ring buffer），造成数据竞争。正确做法是用 spinlock_t（不可睡眠的锁）。
Q5. local_bh_disable() 和 local_irq_disable() 有什么区别？local_bh_disable() 只禁止软中断在本 CPU 上运行——它只是给 preempt_count 加一个偏移量，不碰硬件；硬中断依然能打断你。local_irq_disable() 才是真的关掉 CPU 的中断使能标志（IF），代价更大（要写硬件寄存器）。前者用来保护短小的临界区，后者用来做整个中断上下文的切换。
Q6. 为什么 /proc/interrupts 里同一个中断在不同 CPU 上的计数差那么多？因为中断亲和性（irq_set_affinity）决定了该 IRQ 由哪些 CPU 处理。内核默认会把中断负载均衡，但如果你的进程绑在特定 CPU 上，或者手动改过 /proc/irq/<N>/smp_affinity_list，就会出现倾斜。计数严重不均是负载不均的信号。
Q7. 十个软中断里为什么 RCU_SOFTIRQ 要放在最后？因为 RCU 的回调可能需要执行较重的操作，如果放在高位就总是被推迟。放在最后（序号最大）意味着它优先级最低、最晚被处理；SOFTIRQ_STOP_IDLE_MASK 就是专门为它定义的——在 CPU 即将进入 idle 时，RCU 软中断仍然会被执行以保证 grace period 能推进。
