🚪 系统调用：用户态走进内核的那道门

一条 syscall 指令把 6 个寄存器里的参数变成内核函数调用，再把 -errno 塞回 ax · 预计阅读 26 分钟

1. 它在解决什么问题

银行柜台。你在营业厅（用户态）可以随便走动、自己数钱、填单子，但你不能直接走进金库（内核态）。要取钱你必须走到柜台窗口，把身份证和一本书面的申请单递进去，柜员（内核）核对后办业务，把结果和回执递回给你。窗口是唯一的合法接口，柜台里面的规则不需要你知道，你也改不了。

CPU 硬件就是这么设计的。x86_64 有四个特权级（ring 0..3），Linux 只用 ring 0（内核）和 ring 3（用户）。用户态代码不能执行 cli/hlt、不能改 CR3（页表基址）、不能访问内核地址空间。想读文件、发网络包、创建进程，必须主动触发一次“受控的降级进入”：这条指令就是 syscall（老式 CPU 用 int 0x80）。

所以系统调用（system call）的本质是：用户态与内核态之间唯一被审查的接口。它既要足够快（Linux 每秒可能发生几百万次），又要足够安全（用户传进来的一切都是不可信数据，必须校验）。这两个要求塑造了整个实现：寄存器传参、固定入口、查表分发、返回值用负值编码错误。

理解一条 write() 从用户代码到 vfs_write 的完整路径，你就理解了“进内核”的全部秘密：硬件做了什么、汇编入口保存了什么、C 代码怎么查表、参数怎么到函数里、错误怎么回传。

3.2 参数寄存器与返回值

x86_64 System V ABI 里函数参数用 rdi、rsi、rdx、rcx、r8、r9，但系统调用不用 rcx——因为 syscall 指令硬件会用 rcx 保存返回地址。所以第 4 个参数改放 r10。这也解释了为什么内核里 SYSCALL_DEFINE6 最多 6 个参数。

参数序号寄存器说明
调用号rax如 write 是 1
第 1 个rdifd
第 2 个rsibuf
第 3 个rdxcount
第 4 个r10（不是 rcx！）
第 5 个r8
第 6 个r9
返回值rax成功是结果值，失败是负 errno
syscall 指令只做三件硬件动作：把 RIP 存入 RCX、把 RFLAGS 存入 R11、把 RIP 设为 MSR IA32_LSTAR 里的地址，同时把 CS 切到内核段（CPL=0）。它不会保存其他寄存器，也不会切栈——切栈是内核汇编自己做的（movq PER_CPU_VAR(cpu_current_top_of_stack), %rsp）。

3.3 调用号表怎么来的

arch/x86/entry/syscalls/syscall_64.tbl 是人类可读的清单，构建时被脚本转成 asm/syscalls_64.h，里面全是 __SYSCALL_COMMON(nr, sym) 或 __SYSCALL_64(nr, sym) 宏调用。然后 arch/x86/entry/syscall_64.c 两次 include 这个文件：第一次生成函数声明，第二次生成表项初始化。

syscall_64.tbl            syscalltbl.sh           syscalls_64.h
0  common  read  sys_read   ────────────►  __SYSCALL_COMMON(0, sys_read)
1  common  write sys_write  ────────────►  __SYSCALL_COMMON(1, sys_write)
                                                 │
                                                 ▼
                        syscall_64.c 两次 #include
                        第一次: extern long __x64_sys_read(...)
                        第二次: [0] = __x64_sys_read, [1] = __x64_sys_write, ...

4. 源码走读

4.1 表项：数字 → 函数名

arch/x86/entry/syscalls/syscall_64.tbl:11-12 read / write 的编号

0	common	read			sys_read
1	common	write			sys_write

四列依次是：编号、ABI（common/64/x32）、用户可见名字、内核符号名。common 表示 64 位和 x32 共用；64 表示只给原生 64 位。

4.2 生成 sys_call_table

arch/x86/entry/syscall_64.c:14-26 表的构造

#define __SYSCALL_64(nr, sym) extern long __x64_##sym(const struct pt_regs *);
#include <asm/syscalls_64.h>
#undef __SYSCALL_64

#define __SYSCALL_64(nr, sym) [nr] = __x64_##sym,

asmlinkage const sys_call_ptr_t sys_call_table[__NR_syscall_max+1] = {
	/*
	 * Smells like a compiler bug -- it doesn't work
	 * when the & below is removed.
	 */
	[0 ... __NR_syscall_max] = &__x64_sys_ni_syscall,
#include <asm/syscalls_64.h>
};
  • __SYSCALL_COMMON(nr, sym) 会在 #include 之前被定义成 __SYSCALL_64（源码第 11 行），所以 common 与 64 项都走同一路。
  • 第一次 include 只声明函数原型，让第二个 include 里能写 [nr] = __x64_sys_xxx。
  • [0 ... __NR_syscall_max] = &__x64_sys_ni_syscall 是 GNU 扩展（指定范围初始化），把所有槽先填成 sys_ni_syscall（返回 -ENOSYS），然后表项里的 [nr] 覆盖它。这样即使某个架构没实现某调用，用户也不会跳到空指针。
  • const 与 asmlinkage 让表放在 .rodata：内核代码不能改它（防 rootkit）；asmlinkage 在 x86_64 上基本是空宏，历史遗留的“从栈上传参”标记。

4.3 汇编入口：entry_SYSCALL_64

arch/x86/entry/entry_64.S:95-120 entry_SYSCALL_64

SYM_CODE_START(entry_SYSCALL_64)
	UNWIND_HINT_EMPTY

	swapgs
	/* tss.sp2 is scratch space. */
	movq	%rsp, PER_CPU_VAR(cpu_tss_rw + TSS_sp2)
	SWITCH_TO_KERNEL_CR3 scratch_reg=%rsp
	movq	PER_CPU_VAR(cpu_current_top_of_stack), %rsp

SYM_INNER_LABEL(entry_SYSCALL_64_safe_stack, SYM_L_GLOBAL)

	/* Construct struct pt_regs on stack */
	pushq	$__USER_DS				/* pt_regs->ss */
	pushq	PER_CPU_VAR(cpu_tss_rw + TSS_sp2)	/* pt_regs->sp */
	pushq	%r11					/* pt_regs->flags */
	pushq	$__USER_CS				/* pt_regs->cs */
	pushq	%rcx					/* pt_regs->ip */
SYM_INNER_LABEL(entry_SYSCALL_64_after_hwframe, SYM_L_GLOBAL)
	pushq	%rax					/* pt_regs->orig_ax */

	PUSH_AND_CLEAR_REGS rax=$-ENOSYS

	/* IRQs are off. */
	movq	%rax, %rdi
	movq	%rsp, %rsi
	call	do_syscall_64		/* returns with IRQs disabled */
  • swapgs：用户态的 %gs 指向线程 TLS，内核态的 %gs 指向 percpu 数据。这条指令交换两者，让下一条就能读 PER_CPU_VAR。返回时还要再 swapgs 一次。
  • movq %rsp, PER_CPU_VAR(cpu_tss_rw + TSS_sp2)：syscall 没保存用户栈指针，所以先临时塞进 TSS 的 sp2 槽，等会儿 pushq 到 pt_regs 的 sp 字段里。
  • SWITCH_TO_KERNEL_CR3：KPTI（内核页表隔离）开启时切到内核 CR3；关闭时是空操作。这是 Meltdown 缓解措施的成本。
  • movq PER_CPU_VAR(cpu_current_top_of_stack), %rsp：切到当前 task 的内核栈顶。这个 percpu 值在上下文切换时被更新（__switch_to 里写 TSS_sp0 与 cpu_current_top_of_stack）。
  • 然后按 struct pt_regs 的布局依次压 ss、sp、flags、cs、ip、orig_ax。orig_ax 保存原始调用号，用于 restart_syscall 与 ptrace。
  • PUSH_AND_CLEAR_REGS rax=$-ENOSYS：压入 r15..rdi 全部通用寄存器（形成完整 pt_regs），同时把 rax 先置成 -ENOSYS（万一后面路径失败，返回值天然是“未实现”），并把 rdi/rsi 等寄存器清零以防内核数据泄漏到用户可见位置（Spectre 缓解）。
  • movq %rax, %rdi：按 SysV 调用约定，第一个参数是调用号；%rsp 是 pt_regs 指针，作为第二个参数。注意这里 %rax 是从 pt_regs 里重新载入的（宏返回后 rax 已是 orig_ax 的值）。

4.4 do_syscall_64：查表分发

arch/x86/entry/common.c:39-57 do_syscall_64

__visible noinstr void do_syscall_64(unsigned long nr, struct pt_regs *regs)
{
	nr = syscall_enter_from_user_mode(regs, nr);

	instrumentation_begin();
	if (likely(nr < NR_syscalls)) {
		nr = array_index_nospec(nr, NR_syscalls);
		regs->ax = sys_call_table[nr](regs);
#ifdef CONFIG_X86_X32_ABI
	} else if (likely((nr & __X32_SYSCALL_BIT) &&
			  (nr & ~__X32_SYSCALL_BIT) < X32_NR_syscalls)) {
		nr = array_index_nospec(nr & ~__X32_SYSCALL_BIT,
					X32_NR_syscalls);
		regs->ax = x32_sys_call_table[nr](regs);
#endif
	}
	instrumentation_end();
	syscall_exit_to_user_mode(regs);
}
  • syscall_enter_from_user_mode：在真正调内核函数之前做准备——恢复中断、检查 TIF_WORK_SYSCALL_ENTER（ptrace 单步、seccomp 过滤、审计）。如果 seccomp 拦截，它会把 nr 改成 __NR_seccomp 或直接返回错误。下一篇的 seccomp 就挂在这里。
  • array_index_nospec(nr, NR_syscalls)：Spectre v1 缓解。虽然前面已检查 nr < NR_syscalls，但 CPU 可能推测执行到越界地址；这个宏在越界时把索引归零，让推测执行读到合法表项。
  • sys_call_table[nr](regs)：所有 __x64_sys_* 都接受一个 const struct pt_regs * 参数，返回 long。这就是为什么用户参数要先从 regs 里“解包”，而不是直接当 C 参数传。
  • regs->ax = ...：返回值直接写回 pt_regs 的 ax 槽。返回用户态时 POP_REGS 会把它装回 %rax。错误码就是负数，例如 -EBADF 是 -9。
  • syscall_exit_to_user_mode：退出前处理 TIF_WORK_SYSCALL_EXIT（如 TIF_SIGPENDING → 投递信号、TIF_NOTIFY_RESUME → task_work）。这就是“系统调用返回时检查信号”的位置。

4.5 SYSCALL_DEFINE 宏：从 regs 到 C 参数

include/linux/syscalls.h:213-224 入口宏

#define SYSCALL_DEFINE1(name, ...) SYSCALL_DEFINEx(1, _##name, __VA_ARGS__)
#define SYSCALL_DEFINE2(name, ...) SYSCALL_DEFINEx(2, _##name, __VA_ARGS__)
#define SYSCALL_DEFINE3(name, ...) SYSCALL_DEFINEx(3, _##name, __VA_ARGS__)
/* ... 此处省略 DEFINE4~6 与 DEFINE_MAXARGS ... */

#define SYSCALL_DEFINEx(x, sname, ...)				\
	SYSCALL_METADATA(sname, x, __VA_ARGS__)			\
	__SYSCALL_DEFINEx(x, sname, __VA_ARGS__)
  • _##name 把 write 变成 _write，拼出符号 __x64_sys_write / __do_sys_write。
  • SYSCALL_METADATA 生成 ftrace 元数据（syscall 名字表），供 trace-cmd/perf 显示可读名字。
  • __VA_ARGS__ 是 (type1, name1, type2, name2, ...) 形式，宏用 __MAP 把它展开成函数参数列表。

include/linux/syscalls.h:236-246 __SYSCALL_DEFINEx

#ifndef __SYSCALL_DEFINEx
#define __SYSCALL_DEFINEx(x, name, ...)					\
	__diag_push();							\
	__diag_ignore(GCC, 8, "-Wattribute-alias",			\
		      "Type aliasing is used to sanitize syscall arguments");\
	asmlinkage long sys##name(__MAP(x,__SC_DECL,__VA_ARGS__))	\
		__attribute__((alias(__stringify(__se_sys##name))));	\
	ALLOW_ERROR_INJECTION(sys##name, ERRNO);			\
	static inline long __do_sys##name(__MAP(x,__SC_DECL,__VA_ARGS__));\
	asmlinkage long __se_sys##name(__MAP(x,__SC_LONG,__VA_ARGS__));	\
	asmlinkage long __se_sys##name(__MAP(x,__SC_LONG,__VA_ARGS__))	\
	{								\
		long ret = __do_sys##name(__MAP(x,__SC_CAST,__VA_ARGS__));\
		__MAP(x,__SC_TEST,__VA_ARGS__);				\
		__PROTECT(x, ret,__MAP(x,__SC_ARGS,__VA_ARGS__));	\
		return ret;						\
	}								\
	__diag_pop();							\
	static inline long __do_sys##name(__MAP(x,__SC_DECL,__VA_ARGS__))
#endif /* __SYSCALL_DEFINEx */
  • sys_write 是 __se_sys_write 的别名（alias 属性），保持旧 ABI 符号存在。
  • __se_sys_write 的参数类型是 __SC_LONG（全部转成 long），因为从寄存器拿来的值就是 64 位；然后 __SC_CAST 强转回声明类型再调 __do_sys_write。这一步是为了正确处理“用户传了 32 位 int 但寄存器是 64 位”的符号扩展问题（宏注释里说的 sign-extend）。
  • __SC_TEST 用 BUILD_BUG_ON 检查用户传来的指针类型是否带 __user 注解——忘写 __user 编译就报错，强制开发者标注。
  • __PROTECT（x86 上是 asmlinkage_protect）确保返回值不被参数寄存器污染。
  • 所以 SYSCALL_DEFINE3(write, ...) 展开后，实际执行体是一个 static inline long __do_sys_write(unsigned int fd, const char __user *buf, size_t count)，前面包一层从 pt_regs 解包的汇编/内联桩。

4.6 真正的实现：write 只有三行

fs/read_write.c:1051-1054 SYSCALL_DEFINE3(write)

SYSCALL_DEFINE3(write, unsigned int, fd, const char __user *, buf,
		size_t, count)
{
	return ksys_write(fd, buf, count); /* 直接调用内核write实现 */
}

内核 syscall 实现层的惯例是：syscall 函数只做参数解包与转发，真正逻辑在 ksys_xxx（kernel syscall）里，这样内核内部代码也能调用它而不必构造 pt_regs。

fs/read_write.c:1015-1038 ksys_write

ssize_t ksys_write(unsigned int fd, const char __user *buf, size_t count)
{
	struct fd f = fdget_pos(fd);
	ssize_t ret = -EBADF;

	if (f.file) {
		loff_t pos, *ppos = file_ppos(f.file);
		/* 处理文件位置指针：获取当前位置或使用NULL */
		if (ppos) {
			pos = *ppos; /* 复制当前文件位置 */
			ppos = &pos; /* 使用本地变量避免并发修改 */
		}
		/* 调用VFS层写入函数执行实际写入操作 */
		ret = vfs_write(f.file, buf, count, ppos);
		/* 写入成功后更新文件的当前位置 */
		if (ret >= 0 && ppos)
			f.file->f_pos = pos;
		/* 释放文件描述符引用和位置锁 */
		fdput_pos(f);
	}

	return ret;
}
  • fdget_pos(fd)：把整数 fd 解析成 struct fd（本质是 struct file * + flags）。-EBADF（= -9）是默认返回值，非法 fd 时 f.file 为 NULL，函数直接返回 -9。
  • file_ppos()：只有“可定位”的文件（普通文件）才返回 &f_pos；管道、socket 返回 NULL，表示“没有偏移概念”。
  • ppos = &pos 让 vfs_write 写本地副本，成功后再回写 f_pos——配合 fdget_pos 拿到的文件位置锁，避免两个进程同时 append 时算错偏移。
  • vfs_write 会再做一次 access_ok() 校验用户缓冲区在用户地址范围内（不能指向内核地址），然后调 file->f_op->write_iter。这就是“用户传的指针全部不可信”的第一道关。
  • 返回 ret 一路传回，最终写进 regs->ax。成功是写入字节数（≥0），失败是负值。

4.7 未实现的调用

kernel/sys_ni.c:19-23 sys_ni_syscall

/*
 * Non-implemented system calls get redirected here.
 */
asmlinkage long sys_ni_syscall(void)

表里所有没被填充的槽都指向它，所以用户调一个不存在的调用号会拿到 -ENOSYS（-38），libc 转成 errno = ENOSYS，syscall() 返回 -1。这比跳空指针安全得多。

5. 动手验证

实验一：strace 看 write 的原始参数。

$ strace -e trace=write echo hello
write(1, "hello\n", 6)                   = 6
hello
+++ exited with 0 +++

1 是 fd（stdout），"hello\n" 是 buf，6 是 count，= 6 是 regs->ax 的返回值。如果你用 strace -e trace=write -xx，buf 会以十六进制显示原始字节。

实验二：看调用号。

$ strace -e trace=write -e raw=write echo hi 2>&1 | head -2
write(0x1, 0x7ffd..., 0x3)              = 0x3

-e raw= 显示未解码的参数值。write 在 x86_64 上是 1，可用 ausyscall --dump | grep write 或读 /usr/include/asm/unistd_64.h 确认。

实验三：错误返回是负 errno。

$ strace -e trace=write python3 -c 'import os; os.write(999, b"x")' 2>&1 | tail -2
write(999, "x", 1)                      = -1 EBADF (Bad file descriptor)

内核返回 -9，strace 把它解码成 EBADF。libc 的 write() 包装会把 -9 存进 errno 并返回 -1。

实验四：用 syscall(2) 直接调用、绕过 libc 封装。

$ cat > /tmp/sc.c <<'EOF'
#include <unistd.h>
#include <sys/syscall.h>
#include <stdio.h>
int main(void) {
    long r = syscall(SYS_getpid);        /* getpid 其实走 vDSO，但这里演示 */
    printf("pid=%ld\n", r);
    long w = syscall(SYS_write, 1, "raw\n", 4);
    printf("write returned %ld\n", w);
    return 0;
}
EOF
$ cc -o /tmp/sc /tmp/sc.c && strace -e trace=getpid,write /tmp/sc

你会看到 syscall() 里没有 printf 那一层的额外调用，直接落到 write(1, "raw\n", 4)。注意 getpid 在现代 glibc 上走 vDSO，不会出现在 strace 输出里——这正好说明“不是所有 libc 函数都会陷入内核”。

实验五：自己加一个系统调用（在 qemu 里做）。 需要一份可编译的 5.10 内核。步骤：

1) 在 arch/x86/entry/syscalls/syscall_64.tbl 末尾加一行：
   548	common	mysyscall		sys_mysyscall
   （548 是当时未占用的号，可用 scripts/check-syscall.sh 之类确认）

2) 在 kernel/sys.c 末尾加实现：
   SYSCALL_DEFINE1(mysyscall, int, x)
   {
       pr_info("mysyscall called with %d\n", x);
       return x * 2;
   }

3) make ARCH=x86_64 menuconfig 保持默认，make -j$(nproc)

实验六：用 eBPF 观测系统调用而不编译内核（更常用）。

$ sudo bpftrace -e 'tracepoint:syscalls:sys_enter_write { @[comm] = count(); }'

@[sshd]: 3

tracepoint:syscalls:sys_enter_write 就在 do_syscall_64 调内核函数前触发的 tracepoint 上。sys_exit_write 里能读到返回值。用 bpftrace 观测不需要重启内核，是生产环境排查系统调用问题的标准手段。

6. 自测

Q1. 为什么系统调用的第 4 个参数用 r10，而普通函数用 rcx？syscall 指令硬件约定用 RCX 保存用户态的 RIP（返回地址）、用 R11 保存 RFLAGS。如果参数也放在 rcx，进入内核时原值就被覆盖了。所以 System V ABI 里第 4 个参数（rcx）在 syscall 场景让位给 r10。
Q2. swapgs 到底在换什么？它交换 IA32_GS_BASE 与 IA32_KERNEL_GS_BASE 两个 MSR。用户态 %gs 基址指向线程的 TLS 块；内核态需要 %gs 指向 percpu 区（才能读 current_task、cpu_current_top_of_stack）。进入内核时 swap 一次，返回用户态前再 swap 回去。
Q3. 为什么 do_syscall_64 里要调 array_index_nospec()？防止 Spectre v1 推测执行绕过边界检查。虽然 C 代码里已经 if (nr < NR_syscalls)，但 CPU 可能在你还没完成检查时就去取 sys_call_table[nr]（nr 是恶意大的值）。宏会把越界索引变成 0，让推测读到的也是合法表项。
Q4. SYSCALL_DEFINE3(write) 展开后，真正干活的是哪个函数？是 static inline long __do_sys_write(unsigned int fd, const char __user *buf, size_t count)。外面还有 __se_sys_write 负责把 pt_regs 里的 64 位值做符号扩展后强转成声明类型，以及 __x64_sys_write 负责从 struct pt_regs * 解包。分层的目的是把“ABI 解码”和“业务逻辑”解耦。
Q5. 内核返回 -EBADF，用户看到的是什么？用户看到 write() 返回 -1，errno = EBADF (9)。libc 的包装函数检查返回值：如果 rax 在 -4095..-1 范围内，就取负存进 errno 并返回 -1；否则原样返回。内核永远不返回“假成功”，所以负值编码是可靠的。
