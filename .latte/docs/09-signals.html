📣 信号：内核敲你门的门铃

一条 64 位位图记录"谁还没被处理"，一次栈帧构造让用户态代码在指定地址醒来 · 预计阅读 28 分钟

1. 它在解决什么问题

你在厨房煮面，水开了，锅开始尖叫。你不需要盯着锅——你只是听到了一个通知，然后关火。门铃也是这样：邮递员按一下门铃就走了，他不会等你开门，更不会替你开门。这个"异步通知"的机制就是信号。

操作系统里的问题是：进程 A 怎么告诉进程 B "出事了"，而 B 可能正忙着别的事、可能暂时没空处理、可能已经死了？POSIX 给出的方案是信号（signal）。发送方（kill()）只负责"投递"，不关心对方什么时候处理；接收方可以捕获（写处理函数）、可以忽略（SIG_IGN）、可以暂时屏蔽（挂起），也可以干脆用默认动作（终止、停止、转储 core）。

从 OS 视角看，信号是内核提供的进程间异步通知机制，它和管道、消息队列这类 IPC 的区别在于：管道是同步的——写端必须等读端来收；信号是异步的——发完即走，接收方在"下一个方便的时刻"被打断。信号还携带额外信息（struct siginfo），比如"是谁杀的"、"在哪条指令上出的错"、"孩子是怎么死的"。

还有一个关键认知：信号不是硬件中断。中断是 CPU 的硬件机制，目标是"打断 CPU 此刻正在执行的东西"；信号是内核的软件机制，目标是"打断某个进程"。二者都会导致"控制流被重定向"，但拦截点、屏蔽方式、上下文保存方式完全不同。本篇讲信号，第 10 篇讲中断。

一句话总结：发送阶段只做"记账"（置位 pending + 挂队列），投递阶段才决定"这一瞬间要不要打断你"。这两段代码分别住在 kernel/signal.c 的 __send_signal() 和 get_signal() 里。

3.2 三张表 + 一个队列

每个线程（task）身上挂着三样跟信号有关的东西，都定义在 include/linux/sched/signal.h 与 include/linux/signal_types.h：

结构位置作用
task->blocked每个线程私有屏蔽字：哪些信号暂时不要给我
task->pending每个线程私有只发给本线程的待处理信号（位图 + sigqueue 链表）
task->signal->shared_pending整个线程组共享用 kill(-pgid) 之类发给全组的信号
sighand->action[_NSIG]线程组共享每个信号一份的 struct k_sigaction：处理函数、flags、附加屏蔽字

注意"动作表是线程组共享的，屏蔽字和私有 pending 是每线程独立的"这个不对称——这正是 POSIX 规定的行为，也是多线程程序里最容易踩坑的地方。

3.3 SIGKILL 与 SIGSTOP 为什么特殊

内核头文件里写得很直白（include/linux/signal.h:345）：

 * SIGKILL and SIGSTOP cannot be caught, blocked, or ignored.

原因有三层，代码里都能找到对应：

  1. 不能捕获：设置动作的入口 do_sigaction() 直接拒绝——如果信号属于 SIG_KERNEL_ONLY_MASK（只有 SIGKILL 和 SIGSTOP），返回 -EINVAL。
  2. 不能屏蔽：rt_sigprocmask() 在写入前把这两个位从用户给的掩码里抠掉，所以你 sigprocmask(SIG_BLOCK, &{SIGKILL}, NULL) 之后查 SigBlk 会发现 SIGKILL 根本没被设上。
  3. 不能忽略：do_sigaction() 同样拒绝对它们设置 SIG_IGN；即便绕过 API 直接改内核数据，get_signal() 里的默认动作分支对它们也只会终止/停止。

为什么要留这两个"后门"？因为它们是管理员和内核的救命绳：进程陷入死循环、内存彻底损坏、连 SIGTERM 都不理的守护进程，kill -9 是唯一能把它从内核里拽出来的办法。而 SIGSTOP 保证调试器（gdb）随时能把失控的进程按在原地。

3.5 SIGCHLD 与 wait

子进程退出时，内核在 exit_notify() 里调用 do_notify_parent(tsk, SIGCHLD) 给父进程发一个 SIGCHLD。SIGCHLD 的默认动作是"忽略"——它纯粹是个"你该来收尸了"的提醒，真正取走退出状态的是 wait()/waitpid() 系统调用。

如果父进程一直不 wait()，子进程就会变成僵尸：进程表里的条目还在（为了让父进程知道它的退出码），但已经不算占内存了。僵尸堆积会耗尽 PID 空间，这是服务器上"进程数爆了"的一个经典原因。

常见坑：把 SIGCHLD 设成 SIG_IGN 后，子进程不会留下僵尸——内核会直接自动回收。这条规则在 POSIX 里是明确的，Linux 在 do_notify_parent() 里实现：psig->action[SIGCHLD-1].sa.sa_handler == SIG_IGN 时设置 autoreap = true。

4. 源码走读

4.1 struct sigaction：用户态 ABI 与内核态

用户态看到的结构定义在 arch/x86/include/uapi/asm/signal.h（x86_64 分支）：

arch/x86/include/uapi/asm/signal.h:118-123 struct sigaction (x86_64)

struct sigaction {
	__sighandler_t sa_handler;
	unsigned long sa_flags;
	__sigrestore_t sa_restorer;
	sigset_t sa_mask;		/* mask last for extensibility */
};
  • sa_handler：处理函数地址。两个特殊值：SIG_DFL(0) 表示用默认动作，SIG_IGN(1) 表示彻底忽略。
  • sa_flags：行为开关，常用的有 SA_SIGINFO（处理函数多收两个参数）、SA_RESTART（系统调用自动重启）、SA_ONESHOT（执行一次后恢复默认）、SA_NODEFER（处理期间不自动屏蔽自己）。
  • sa_restorer：用户态代码里的一小段 trampoline，作用是执行 rt_sigreturn 把控制权交还内核。这字段是 x86_64 ABI 强制的，内核在 __setup_rt_frame() 里会检查 SA_RESTORER 标志，缺了就直接返回 -EFAULT。
  • sa_mask：执行处理函数期间额外屏蔽哪些信号。内核在 do_sigaction() 里会强制把 SIGKILL/SIGSTOP 从这里面抠掉。

内核内部另有一份 struct sigaction（include/linux/signal_types.h:35-47），字段顺序按架构可调，并额外包了一层 struct k_sigaction：

include/linux/signal_types.h:35-54 struct sigaction / struct k_sigaction

struct sigaction {
#ifndef __ARCH_HAS_IRIX_SIGACTION
	__sighandler_t	sa_handler;
	unsigned long	sa_flags;
#else
	unsigned int	sa_flags;
	__sighandler_t	sa_handler;
#endif
#ifdef __ARCH_HAS_SA_RESTORER
	__sigrestore_t sa_restorer;
#endif
	sigset_t	sa_mask;	/* mask last for extensibility */
};

struct k_sigaction {
	struct sigaction sa;
#ifdef __ARCH_HAS_KA_RESTORER
	__sigrestore_t ka_restorer;
#endif
};

为什么要两层？因为某些架构（如 mips、alpha、sparc）历史上把 sa_flags 放在 sa_handler 前面，__ARCH_HAS_IRIX_SIGACTION 就是这个开关。struct k_sigaction 则是给那些"用户态的 sa_restorer"和"内核自己记的 restorer"分开放的内核包装。

4.2 send_signal()：入口与"强制"语义

这是对外的一层包装，负责决定这次信号是不是"强制的"（force）。强制的意思是：即使目标是内核线程、或者目标来自更外层的 PID 命名空间，也必须送达。

kernel/signal.c:1405-1439 send_signal

static int send_signal(int sig, struct kernel_siginfo *info, struct task_struct *t,
			enum pid_type type)
{
	/* Should SIGKILL or SIGSTOP be received by a pid namespace init? */
	bool force = false;

	if (info == SEND_SIG_NOINFO) {
		/* Force if sent from an ancestor pid namespace */
		force = !task_pid_nr_ns(current, task_active_pid_ns(t));
	} else if (info == SEND_SIG_PRIV) {
		/* Don't ignore kernel generated signals */
		force = true;
	} else if (has_si_pid_and_uid(info)) {
		/* SIGKILL and SIGSTOP is special or has ids */
		struct user_namespace *t_user_ns;

		rcu_read_lock();
		t_user_ns = task_cred_xxx(t, user_ns);
		if (current_user_ns() != t_user_ns) {
			kuid_t uid = make_kuid(current_user_ns(), info->si_uid);
			info->si_uid = from_kuid_munged(t_user_ns, uid);
		}
		rcu_read_unlock();

		/* A kernel generated signal? */
		force = (info->si_code == SI_KERNEL);

		/* From an ancestor pid namespace? */
		if (!task_pid_nr_ns(current, task_active_pid_ns(t))) {
			info->si_pid = 0;
			force = true;
		}
	}
	return __send_signal(sig, info, t, type, force);
}
  • SEND_SIG_NOINFO / SEND_SIG_PRIV 是两个"魔法指针值"，用来表示"没有额外信息"或"内核私有信号"，省掉一次 kernel_siginfo 的拷贝。
  • 跨越 PID 命名空间发信号时，force 会被置真：容器里的进程不能靠"忽略信号"来抗住外层发来的 SIGKILL。
  • info->si_uid 会被翻译到目标进程的用户命名空间去，避免容器内看到外层的 uid。

4.3 __send_signal()：真正的"记账"

核心工作只有四步：预处理 → 去重 → 分配队列节点 → 置位 pending。

kernel/signal.c:1259-1373 __send_signal

static int __send_signal(int sig, struct kernel_siginfo *info, struct task_struct *t,
			enum pid_type type, bool force)
{
	struct sigpending *pending;
	struct sigqueue *q;
	int override_rlimit;
	int ret = 0, result;

	assert_spin_locked(&t->sighand->siglock);

	result = TRACE_SIGNAL_IGNORED;
	if (!prepare_signal(sig, t, force))
		goto ret;

	pending = (type != PIDTYPE_PID) ? &t->signal->shared_pending : &t->pending;
	/*
	 * Short-circuit ignored signals and support queuing
	 * exactly one non-rt signal, so that we can get more
	 * detailed information about the cause of the signal.
	 */
	result = TRACE_SIGNAL_ALREADY_PENDING;
	if (legacy_queue(pending, sig))
		goto ret;

	result = TRACE_SIGNAL_DELIVERED;
	/*
	 * Skip useless siginfo allocation for SIGKILL and kernel threads.
	 */
	if ((sig == SIGKILL) || (t->flags & PF_KTHREAD))
		goto out_set;
	// ... （此处约 70 行：__sigqueue_alloc() 分配节点、填充 siginfo、按 RLIMIT_SIGPENDING 判定是否丢弃）
out_set:
	signalfd_notify(t, sig);
	sigaddset(&pending->signal, sig);
	// ... （此处约 30 行：处理多进程信号的延迟投递、complete_signal()）
ret:
	trace_signal_generate(sig, info, t, type != PIDTYPE_PID, result);
	return ret;
}
  • pending 的选择：发给单个线程（PIDTYPE_PID）放私有 pending，发给进程组/会话放共享 pending。
  • legacy_queue() 只做一件事：return (sig < SIGRTMIN) && sigismember(&signals->signal, sig);——传统信号重复投递会被合并，实时信号则会排队。
  • SIGKILL 跳过 sigqueue 分配：它没有"原因"要说，直接置位就行。
  • 最后 sigaddset(&pending->signal, sig) 才是"记账"本身——它置的是位图，不是链表。
  • 整个函数都在 t->sighand->siglock 自旋锁保护下（第一行的 assert_spin_locked 就是自检）。

4.4 get_signal()：取出一个该处理的信号

投递阶段的主角。它反复从 pending 里"挑一个未被屏蔽的信号"，然后按它的动作分派。

kernel/signal.c:3124-3158 get_signal（核心分派循环）

		/*
		 * Signals generated by the execution of an instruction
		 * need to be delivered before any other pending signals
		 * so that the instruction pointer in the signal stack
		 * frame points to the faulting instruction.
		 */
		signr = dequeue_synchronous_signal(&ksig->info);  // 优先处理同步信号(如SIGSEGV、SIGFPE等)
		if (!signr)
			signr = dequeue_signal(current, &current->blocked, &ksig->info);  // 从信号队列取出下一个未被阻塞的信号

		if (!signr)
			break; /* will return 0 */  // 没有信号需要处理，退出循环

		if (unlikely(current->ptrace) && signr != SIGKILL) {  // 被调试进程的信号需要特殊处理
			signr = ptrace_signal(signr, &ksig->info);  // 通知调试器，可能修改或阻止信号
			if (!signr)
				continue;  // 调试器阻止了信号，继续处理下一个
		}

		ka = &sighand->action[signr-1];  // 获取该信号的处理动作结构体

		/* Trace actually delivered signals. */
		trace_signal_deliver(signr, &ksig->info, ka);  // 追踪信号传递事件

		if (ka->sa.sa_handler == SIG_IGN) /* Do nothing.  */  // 信号被设置为忽略
			continue;
		if (ka->sa.sa_handler != SIG_DFL) {  // 有自定义信号处理器
			/* Run the handler.  */
			ksig->ka = *ka;  // 保存信号动作，准备执行用户处理器

			if (ka->sa.sa_flags & SA_ONESHOT)  // SA_ONESHOT标志：执行一次后恢复默认
				ka->sa.sa_handler = SIG_DFL;

			break; /* will return non-zero "signr" value */  // 跳出循环，返回给用户态执行处理器
		}
  • 同步信号优先：dequeue_synchronous_signal() 先取 SIGSEGV/SIGFPE/SIGILL 这类"由当前指令引起"的信号，因为只有它才能保证栈帧里的 IP 指向出错的那条指令。
  • dequeue_signal(current, &current->blocked, ...) 的第二个参数就是屏蔽字：被屏蔽的信号留在 pending 里不动，函数返回 0。
  • ka = &sighand->action[signr-1]——注意下标是 signr-1，因为信号编号从 1 开始，数组下标从 0 开始。
  • SIG_IGN → 丢弃并继续；自定义 handler → 拷贝一份 ksig->ka 后跳出循环；SIG_DFL → 落到后面的默认动作分支。
  • 循环结束还没取到信号时，get_signal() 返回 false，arch_do_signal() 就直接返回用户态。

kernel/signal.c:3245-3249 get_signal（收尾）

	spin_unlock_irq(&sighand->siglock);

	ksig->sig = signr;
	return ksig->sig > 0;
}

返回 true 表示"有一个信号要投递"，调用者据此去造栈帧。

4.5 setup_rt_frame()：在用户栈上造一个"返回现场"

这是信号能"像函数调用一样"跑起来的关键：内核在用户栈上写出一个 struct rt_sigframe，里面保存了被打断时的全部寄存器，然后把 rip 改成处理函数地址、rsp 改成帧地址。处理函数返回时执行 rt_sigreturn，内核再按帧把寄存器原样恢复。

arch/x86/kernel/signal.c:683-704 setup_rt_frame

static int
setup_rt_frame(struct ksignal *ksig, struct pt_regs *regs)
{
	int usig = ksig->sig;
	sigset_t *set = sigmask_to_save();
	compat_sigset_t *cset = (compat_sigset_t *) set;

	/* Perform fixup for the pre-signal frame. */
	rseq_signal_deliver(ksig, regs);

	/* Set up the stack frame */
	if (is_ia32_frame(ksig)) {
		if (ksig->ka.sa.sa_flags & SA_SIGINFO)
			return ia32_setup_rt_frame(usig, ksig, cset, regs);
		else
			return ia32_setup_frame(usig, ksig, cset, regs);
	} else if (is_x32_frame(ksig)) {
		return x32_setup_rt_frame(ksig, cset, regs);
	} else {
		return __setup_rt_frame(ksig->sig, ksig, set, regs);
	}
}

原生 x86_64 走 __setup_rt_frame()：

arch/x86/kernel/signal.c:439-513 __setup_rt_frame（x86_64 版本）

static int __setup_rt_frame(int sig, struct ksignal *ksig,
			    sigset_t *set, struct pt_regs *regs)
{
	struct rt_sigframe __user *frame;
	void __user *fp = NULL;
	unsigned long uc_flags;

	/* x86-64 should always use SA_RESTORER. */
	if (!(ksig->ka.sa.sa_flags & SA_RESTORER))
		return -EFAULT;

	frame = get_sigframe(&ksig->ka, regs, sizeof(struct rt_sigframe), &fp);
	uc_flags = frame_uc_flags(regs);

	if (!user_access_begin(frame, sizeof(*frame)))
		return -EFAULT;

	/* Create the ucontext.  */
	unsafe_put_user(uc_flags, &frame->uc.uc_flags, Efault);
	unsafe_put_user(0, &frame->uc.uc_link, Efault);
	unsafe_save_altstack(&frame->uc.uc_stack, regs->sp, Efault);

	/* Set up to return from userspace.  If provided, use a stub
	   already in userspace.  */
	unsafe_put_user(ksig->ka.sa.sa_restorer, &frame->pretcode, Efault);
	unsafe_put_sigcontext(&frame->uc.uc_mcontext, fp, regs, set, Efault);
	unsafe_put_sigmask(set, frame, Efault);
	user_access_end();
	// ... （此处约 40 行：填 siginfo、按 SA_SIGINFO 决定处理函数签名）
	/* Set up registers for signal handler */
	regs->di = sig;
	/* In case the signal handler was declared without prototypes */
	regs->ax = 0;

	/* This also works for non SA_SIGINFO handlers because they expect the
	   next argument after the signal number on the stack. */
	regs->si = (unsigned long)&frame->info;
	regs->dx = (unsigned long)&frame->uc;
	regs->ip = (unsigned long) ksig->ka.sa.sa_handler;

	regs->sp = (unsigned long)frame;
	// ... （此处约 15 行：设置 CS/SS 为用户态段寄存器）
	return 0;

Efault:
	user_access_end();
	return -EFAULT;
}
  • SA_RESTORER 检查：x86_64 ABI 要求用户态必须提供 sa_restorer，内核把它写进帧的 pretcode 字段。处理函数"返回"到那里就等于执行了 rt_sigreturn。
  • get_sigframe() 决定帧放在哪：默认在当前用户栈往下长（红区之外），如果设过 sigaltstack（SA_ONSTACK）就放在备用栈上。
  • 寄存器约定：rdi=信号号，rsi=&siginfo，rdx=&ucontext——这正好是 SA_SIGINFO 处理函数 void handler(int, siginfo_t*, void*) 的三个参数。没开 SA_SIGINFO 时只有 rdi 有效，另两个参数靠栈传递。
  • regs->ip = sa_handler 与 regs->sp = frame 就是"跳转"的两步——内核返回用户态时，CPU 就从处理函数开始执行了。
  • unsafe_put_sigcontext() 保存通用寄存器；unsafe_put_sigmask() 保存"进入处理函数时的屏蔽字"，供 sigreturn 恢复。
关于 do_signal()：在 5.10 之前的内核里有个统一的 do_signal() 负责整个投递过程。它在 5.10 被拆成了两半：通用部分留在 kernel/signal.c 的 get_signal()（返回"有信号要投递"），架构相关部分下沉到 arch/x86/kernel/signal.c 的 arch_do_signal()。所以在本仓库里搜 do_signal 只能搜到 5.10 之前的写法——现在对应的是下面这两个函数。

arch/x86/kernel/signal.c:807-833 arch_do_signal

void arch_do_signal(struct pt_regs *regs)
{
	struct ksignal ksig;

	if (get_signal(&ksig)) {
		/* Whee! Actually deliver the signal.  */
		handle_signal(&ksig, regs);
		return;
	}

	/* Did we come from a system call? */
	if (syscall_get_nr(current, regs) >= 0) {
		/* Restart the system call - no handlers present */
		switch (syscall_get_error(current, regs)) {
		case -ERESTARTNOHAND:
		case -ERESTARTSYS:
		case -ERESTARTNOINTR:
			regs->ax = regs->orig_ax;
			regs->ip -= 2;
			break;

		case -ERESTART_RESTARTBLOCK:
			regs->ax = get_nr_restart_syscall(regs);
			regs->ip -= 2;
			break;
		}
	}
	// ...
}

regs->ip -= 2 就是"回退到 syscall 指令重新执行"——x86_64 的 syscall 指令正好 2 字节，这样重新执行一次就等于把系统调用重做一遍。

4.6 SA_RESTART：系统调用到底重启不重启

上面 arch_do_signal() 里那套 -ERESTARTSYS 逻辑，处理的是"没有处理函数、信号被默认动作消化掉"的情况。真正有处理函数时，逻辑在 handle_signal() 里：

arch/x86/kernel/signal.c:715-735 handle_signal（系统调用重启判定）

	/* Are we from a system call? */
	if (syscall_get_nr(current, regs) >= 0) {
		/* If so, check system call restarting.. */
		switch (syscall_get_error(current, regs)) {
		case -ERESTART_RESTARTBLOCK:
		case -ERESTARTNOHAND:
			regs->ax = -EINTR;
			break;

		case -ERESTARTSYS:
			if (!(ksig->ka.sa.sa_flags & SA_RESTART)) {
				regs->ax = -EINTR;
				break;
			}
			fallthrough;
		case -ERESTARTNOINTR:
			regs->ax = regs->orig_ax;
			regs->ip -= 2;
			break;
		}
	}
  • -ERESTARTSYS：这个系统调用可以重启。有 SA_RESTART → 走 fallthrough，恢复原调用号并 ip -= 2，重新执行 syscall 指令（用户态根本感觉不到中断过）；没有 → regs->ax = -EINTR，用户态的 read() 返回 -1 并置 errno=EINTR。
  • -ERESTARTNOHAND：不可重启（典型是 execve），只能返回 EINTR。
  • -ERESTARTNOINTR：无条件重启（典型是 poll/select），不看 SA_RESTART。

4.7 屏蔽字：sigprocmask() 与 SIGKILL/SIGSTOP 的剥离

kernel/signal.c:3484-3509 sigprocmask

int sigprocmask(int how, sigset_t *set, sigset_t *oldset)
{
	struct task_struct *tsk = current;
	sigset_t newset;

	/* Lockless, only current can change ->blocked, never from irq */
	if (oldset)
		*oldset = tsk->blocked;

	switch (how) {
	case SIG_BLOCK:
		sigorsets(&newset, &tsk->blocked, set);  // 阻塞新信号：newset = blocked ∪ set
		break;
	case SIG_UNBLOCK:
		sigandnsets(&newset, &tsk->blocked, set);  // 解除阻塞：newset = blocked ∩ ~set
		break;
	case SIG_SETMASK:
		newset = *set;  // 直接设置新的信号掩码
		break;
	default:
		return -EINVAL;
	}

	__set_current_blocked(&newset);
	return 0;
}

这是内核内部版本，可以屏蔽 SIGKILL（注释里明说了）。真正给用户态用的是 rt_sigprocmask()，它多做一步"消毒"：

kernel/signal.c:3585-3613 sys_rt_sigprocmask

SYSCALL_DEFINE4(rt_sigprocmask, int, how, sigset_t __user *, nset,
		sigset_t __user *, oset, size_t, sigsetsize)
{
	sigset_t old_set, new_set;
	int error;

	/* XXX: Don't preclude handling different sized sigset_t's.  */
	if (sigsetsize != sizeof(sigset_t))
		return -EINVAL;

	old_set = current->blocked;

	if (nset) {
		if (copy_from_user(&new_set, nset, sizeof(sigset_t)))
			return -EFAULT;
		sigdelsetmask(&new_set, sigmask(SIGKILL)|sigmask(SIGSTOP));

		error = sigprocmask(how, &new_set, NULL);
		if (error)
			return error;
	}

	if (oset) {
		if (copy_to_user(oset, &old_set, sizeof(sigset_t)))
			return -EFAULT;
	}

	return 0;
}

sigdelsetmask(&new_set, sigmask(SIGKILL)|sigmask(SIGSTOP)) 这一行就是"SIGKILL/SIGSTOP 不可屏蔽"的实现：用户传给内核的掩码里这两个位会被强行清零，所以 /proc/<pid>/status 的 SigBlk 里永远看不到它们。

4.8 /proc/<pid>/status 里的五张位图

内核把这几张表直接暴露给用户态：

fs/proc/array.c:250-263 collect_sigign_sigcatch

static void collect_sigign_sigcatch(struct task_struct *p, sigset_t *sigign,
				    sigset_t *sigcatch)
{
	struct k_sigaction *k;
	int i;

	k = p->sighand->action;
	for (i = 1; i <= _NSIG; ++i, ++k) {
		if (k->sa.sa_handler == SIG_IGN)
			sigaddset(sigign, i);
		else if (k->sa.sa_handler != SIG_DFL)
			sigaddset(sigcatch, i);
	}
}

fs/proc/array.c:279-301 task_sig（打印五张表）

	if (lock_task_sighand(p, &flags)) {
		pending = p->pending.signal;
		shpending = p->signal->shared_pending.signal;
		blocked = p->blocked;
		collect_sigign_sigcatch(p, &ignored, &caught);
		num_threads = get_nr_threads(p);
		// ...
		unlock_task_sighand(p, &flags);
	}

	seq_put_decimal_ull(m, "Threads:\t", num_threads);
	seq_put_decimal_ull(m, "\nSigQ:\t", qsize);
	seq_put_decimal_ull(m, "/", qlim);

	/* render them all */
	render_sigset_t(m, "\nSigPnd:\t", &pending);
	render_sigset_t(m, "ShdPnd:\t", &shpending);
	render_sigset_t(m, "SigBlk:\t", &blocked);
	render_sigset_t(m, "SigIgn:\t", &ignored);
	render_sigset_t(m, "SigCgt:\t", &caught);
字段来源含义
SigPndp->pending.signal本线程私有的待处理信号（已投递、还没送达）
ShdPndp->signal->shared_pending.signal整个线程组共享的待处理信号
SigBlkp->blocked屏蔽字：被暂时挂起的信号
SigIgn遍历 action[]被显式设为 SIG_IGN 的信号
SigCgt遍历 action[]被设为自定义处理函数的信号

这五个字段是 16 进制的位图，第 N 位对应信号 N。位序是从低位往高位排的：SigCgt 的最低位是 SIGHUP(1)，第二个位是 SIGINT(2)。

5.2 观察一个正在睡觉的进程被信号打断

$ sleep 300 &
$ echo $!          # 记住 PID
$ cat /proc/$!/status | grep -E 'SigPnd|ShdPnd|SigBlk|SigIgn|SigCgt'

5.3 写一个用 sigaction 捕获 SIGINT、并正确重启被打断系统调用的程序

下面是完整可编译的程序。它演示了两件事：SA_RESTART 让阻塞的 read() 自动重启（用户态看不见 EINTR），以及不带 SA_RESTART 时 read() 会返回 -1/EINTR。

/* sigint_demo.c - 演示用 sigaction 捕获 SIGINT，以及 SA_RESTART 如何
 *                 让被信号打断的阻塞系统调用自动重启
 * 编译: gcc -O2 -o sigint_demo sigint_demo.c
 * 用法: ./sigint_demo            (带 SA_RESTART)
 *       ./sigint_demo norestart   (不带 SA_RESTART)
 */
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <errno.h>
#include <signal.h>
#include <unistd.h>
#include <sys/types.h>

static volatile sig_atomic_t hits = 0;
static int pipefd[2];

static void on_sigint(int signo)
{
	char c = 'X';
	(void)signo;
	hits++;
	write(pipefd[1], &c, 1);   /* write() 是 async-signal-safe 的 */
}

int main(int argc, char **argv)
{
	struct sigaction sa;
	char buf[64];
	int use_restart = (argc < 2 || strcmp(argv[1], "norestart") != 0);
	ssize_t n;

	if (pipe(pipefd) == -1) { perror("pipe"); return 1; }

	memset(&sa, 0, sizeof(sa));
	sa.sa_handler = on_sigint;
	sigemptyset(&sa.sa_mask);
	sa.sa_flags = use_restart ? SA_RESTART : 0;
	if (sigaction(SIGINT, &sa, NULL) == -1) { perror("sigaction"); return 1; }

	printf("pid=%d  SA_RESTART=%s\n", (int)getpid(), use_restart ? "开" : "关");
	printf("主线程即将阻塞在 read() 上；1 秒后子进程发 SIGINT\n");
	printf("你也可以在另一个终端手动执行: kill -INT %d\n", (int)getpid());
	fflush(stdout);

	/* 造一个"外部事件"：子进程 1 秒后给父进程发 SIGINT */
	if (fork() == 0) {
		sleep(1);
		kill(getppid(), SIGINT);
		_exit(0);
	}

	for (;;) {
		n = read(pipefd[0], buf, sizeof(buf));   /* 没有数据 → 阻塞 */
		if (n < 0 && errno == EINTR) {
			printf("[main] read() 返回 -1，errno=EINTR（系统调用被打断）\n");
			if (!use_restart)
				printf("[main] 没有 SA_RESTART，需要自己重试 read()\n");
			continue;
		}
		printf("[main] read() 返回 %zd，buf[0]='%c'（系统调用被自动重启后拿到数据）\n",
		       n, n > 0 ? buf[0] : '?');
		break;
	}
	printf("[main] 退出，handler 被调用 %d 次\n", (int)hits);
	return 0;
}

运行与预期输出（带 SA_RESTART）：

$ ./sigint_demo
pid=12345  SA_RESTART=开
主线程即将阻塞在 read() 上；1 秒后子进程发 SIGINT
你也可以在另一个终端手动执行: kill -INT 12345
[main] read() 返回 1，buf[0]='X'（系统调用被自动重启后拿到数据）
[main] 退出，handler 被调用 1 次

不带 SA_RESTART 时：

$ ./sigint_demo norestart
pid=12346  SA_RESTART=关
主线程即将阻塞在 read() 上；1 秒后子进程发 SIGINT
你也可以在另一个终端手动执行: kill -INT 12346
[main] read() 返回 -1，errno=EINTR（系统调用被打断）
[main] 没有 SA_RESTART，需要自己重试 read()
[main] read() 返回 1，buf[0]='X'（系统调用被自动重启后拿到数据）
[main] 退出，handler 被调用 1 次
两段输出的差别就是 SA_RESTART 的全部意义。带 SA_RESTART 时，用户态看不到 EINTR——内核把 syscall 指令重做了一遍，read() 直接返回了 handler 写进管道的那 1 个字节。不带时，用户态必须自己写 if (errno == EINTR) continue; 重试。写生产代码时，如果用的是可重启的系统调用（read/write/accept），加上 SA_RESTART 可以省掉大量样板代码。
注意 handler 里只能调用 async-signal-safe 函数。处理函数运行在"被中断的那个上下文"上，随时可能被再次打断。本例中 handler 只用了 write()（内核保证安全）和给 volatile sig_atomic_t 赋值——这两类操作在信号处理函数里是安全的。printf()、malloc() 都不是。

5.4 用 strace 看清系统调用被重启

$ strace -f -e trace=read,rt_sigaction ./sigint_demo 2>&1 | head -20

你会看到 rt_sigaction(SIGALRM, ...)，以及 read(3, ...) 被中断后再次出现（重启），而不是返回 -1 ERESTART。这正是 handle_signal() 里 regs->ip -= 2 的效果。

5.5 SIGCHLD 与 wait()：观察僵尸进程

# 终端 1：父进程 fork 一个子进程后不 wait
$ cat > zombie.c <<'EOF'
#include <stdio.h>
#include <unistd.h>
#include <sys/wait.h>
int main(void) {
	if (fork() == 0) { _exit(42); }     /* 子进程立刻退出 */
	sleep(30);                          /* 父进程不 wait，30 秒后退出 */
	return 0;
}
EOF
$ gcc -o zombie zombie.c && ./zombie &

# 终端 2：
$ ps -o pid,ppid,stat,cmd | grep zombie
    PID    PPID STAT CMD
   12346   12345 Z    ./zombie      ← Z 就是僵尸

STAT 列的 Z 表示僵尸：子进程已退出，但父进程没调 wait()，内核只好留着它的退出码（42）。等父进程退出后，僵尸被 init 收养并回收。

用 wait() 就能立刻收尸：

# 终端 1
$ cat > reaper.c <<'EOF'
#include <stdio.h>
#include <unistd.h>
#include <sys/wait.h>
int main(void) {
	pid_t p = fork();
	if (p == 0) { _exit(42); }
	int st = 0;
	pid_t r = waitpid(p, &st, 0);      /* 阻塞等待子进程 */
	printf("reaped pid=%d, exited=%d code=%d\n", r, WIFEXITED(st), WEXITSTATUS(st));
	return 0;
}
EOF
$ gcc -o reaper reaper.c && ./reaper
reaped pid=12378, exited=1 code=42

waitpid() 返回时，st 里打包了退出状态：WIFEXITED(st) 判断是不是正常退出，WEXITSTATUS(st) 取退出码。这些宏和 do_wait() 里的 wait_task_zombie() 是配套的。

6. 自测

Q1. 为什么 kill -9 一定能杀掉进程，而 kill -TERM 可能不行？因为 SIGKILL 属于 SIG_KERNEL_ONLY_MASK（include/linux/signal.h:416）。do_sigaction() 拒绝为它设置处理函数，rt_sigprocmask() 也会把它的位从屏蔽字里抠掉，get_signal() 里它只有"终止"一种结局。所以进程没有任何机会拦截它——这正是内核保留的"不可抗力"后门。
Q2. sigprocmask(SIG_BLOCK, ...) 之后，进程还会不会收到被屏蔽的信号？会收到，只是不会投递。信号照样进 pending 位图（SigPnd 会显示它），只是 get_signal() 里的 dequeue_signal(current, &current->blocked, ...) 会跳过被屏蔽的位。等你 sigprocmask(SIG_UNBLOCK, ...) 后，它会立刻被投递——所以"屏蔽"不是"丢弃"。
Q3. SA_RESTART 到底是谁在起作用，内核还是 libc？内核。handle_signal()（arch/x86/kernel/signal.c:724-733）检查 sa_flags 里的 SA_RESTART：有就把 regs->ax 恢复成原调用号、regs->ip -= 2 让 CPU 重新执行 syscall 指令；没有就设 regs->ax = -EINTR。libc 只是把内核给的 errno 转成 -1 返回。
Q4. 多线程程序里，一个线程 fork() 出来的子进程，收到 SIGINT 会怎样？子进程只继承调用 fork 的那个线程的屏蔽字（其他线程的屏蔽字不继承），并且执行 execve 时会重置为默认。另一个容易忽略的点：fork() 出来的子进程里，pthread_create() 创建的线程并不存在，只剩调用 fork 的那个线程。
Q5. 为什么 /proc/<pid>/status 里的 SigBlk 永远看不到 SIGKILL 和 SIGSTOP？因为 sys_rt_sigprocmask()（kernel/signal.c:3600）在写入前执行了 sigdelsetmask(&new_set, sigmask(SIGKILL)|sigmask(SIGSTOP))，用户给的掩码里这两位被强制清零。内核内部版 sigprocmask() 才允许屏蔽它们（给内核线程用），用户态的 rt_sigprocmask() 是它的"消毒版"。
Q6. 把 SIGCHLD 设成 SIG_IGN 之后，子进程还会不会变成僵尸？不会。内核在 do_notify_parent()（kernel/signal.c:2424-2448）里检测到父进程把 SIGCHLD 设成 SIG_IGN（或设了 SA_NOCLDWAIT）时，会把 autoreap 置真，子进程直接被回收而不留僵尸。这条规则是 POSIX 要求的。
