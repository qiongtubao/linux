💽 ext4：磁盘上的文件系统

从超级块到 extent 树，看文件如何铺在硬盘上、崩溃后如何不丢账 · 预计阅读 10 分钟

1. 它在解决什么问题

硬盘本质是一大段编号的扇区，没有“文件”这个概念。就像一间所有货架从 0 编到 N 的仓库，谁来存放都得自己记“东西在第几排”。文件系统就是在裸仓库上画出货架目录、登记本与储物规则的那套制度，ext4 是 Linux 上最常见的一本账。

它要解决四件事：空间怎么分——块组把大盘切成小块，各组位图与 inode 表就近存放，寻道更短；文件怎么记——inode 存大小/权限/数据位置，目录记“名字→inode 号”；大文件怎么省——extent 用“一段连续区间”代替一长串指针；崩溃怎么办——jbd2 写前日志先记再改。此外它还用延迟分配攒大块、用 htree 让百万文件的目录也能快速查找。

2. 核心名词

术语英文一句话解释
超级块superblock盘上 1024 字节起的总账：块大小、块组参数、魔数 0xEF53。
块组block group把磁盘切成等大小的管理单位，各带位图、inode 表、组描述符。
位图bitmap每 bit 表示一个块/inode 是否占用，分配时找 0 位。
extentextent“逻辑起点 + 长度 + 物理起点”三元组，代表一段连续块。
extent 树extent tree以 extent 为叶子的浅 B 树，根节点嵌在 inode 的 i_block[]。
写前日志jbd2先写日志区并提交，再写回原位；崩溃时重放或丢弃。
延迟分配delallocwrite() 只标脏页，回写时才真正分配磁盘块。
htreehashed tree目录项按名字哈希分块，用浅树二分定位，避免线性扫描。

3. 整体结构

块号  0      1       2        3        4       5..N
   ┌──────┬──────┬────────┬────────┬──────┬───────────┐
   │ boot │超级块│组描述符│块位图  │inode │ inode 表  │
   │      │(1024)│ (GDT)  │(1块)   │位图  │ (N块)     │
   └──────┴──────┴────────┴────────┴──────┴───────────┘
                              ↑ 每 bit = 1 块
                    其后是数据块（文件内容/目录块/extent 树块）

超级块给出全局参数；组描述符表每项（struct ext4_group_desc）记录本组块位图块号、inode 位图块号、inode 表起始块与空闲计数。分配时先挑组（尽量靠近父目录），再在位图里找 0 位。

inode（struct ext4_inode，fs/ext4/ext4.h:767）固定 256 字节，含 i_mode/i_uid/i_size/i_links_count 与 i_block[60]。开了 EXT4_EXTENTS_FL 时 i_block[] 整块当 extent 树根，否则是老式直接/间接块指针。

i_block[60]（extent 模式）
┌─────────────────────────────────────────┐
│ header: magic=f30a, entries, max, depth │  12 字节
├─────────────────────────────────────────┤
│ extent[0]: lblk=0   len=128 pblk=2048   │  depth=0 时
│ extent[1]: lblk=128 len=64  pblk=8192   │  叶子直接在 inode 里
└─────────────────────────────────────────┘
depth>0 时改为 extent_idx，指向下一层的树块

extent vs 间接块：老式每个 4KB 指针块存 1024 个块号，1GB 文件要 256 个指针块、读一个字节要跳三四层；extent 用一个三元组描述“连续 128 块”，记录本身就带连续性，顺序读几乎不用寻道。

jbd2：元数据修改都在事务里。“要改的块副本写入日志区 → 写提交块（带校验，表示这组修改完整）→ 才写回原位”。崩溃恢复时找最后一条完整提交重放，不完整的丢弃。日志区是 inode 8，ext4 通过 ext4_journal_start/stop 参与。

延迟分配：ext4_da_write_begin 只把页挂进页缓存并在内存 extent status tree 记一条 delayed，不占磁盘块；ext4_writepages 回写时才调 ext4_map_blocks 真正分配。htree：小目录是一块里顺序排的目录项；超过一块后改成 dx_root，按名字哈希在 dx_entry{hash, block} 中二分定位叶子块。

4.2 逻辑块 → 物理块：ext4_map_blocks

fs/ext4/inode.c:492-538 ext4_map_blocks（节选）

	if (unlikely(map->m_lblk >= EXT_MAX_BLOCKS))
		return -EFSCORRUPTED;

	/* Lookup extent status tree firstly */
	if (!(EXT4_SB(inode->i_sb)->s_mount_state & EXT4_FC_REPLAY) &&
	    ext4_es_lookup_extent(inode, map->m_lblk, NULL, &es)) {
		if (ext4_es_is_written(&es) || ext4_es_is_unwritten(&es)) {
			map->m_pblk = ext4_es_pblock(&es) + map->m_lblk - es.es_lblk;
			map->m_flags |= ext4_es_is_written(&es) ?
					EXT4_MAP_MAPPED : EXT4_MAP_UNWRITTEN;
			retval = es.es_len - (map->m_lblk - es.es_lblk);
			if (retval > map->m_len) retval = map->m_len;
			map->m_len = retval;
		} else if (ext4_es_is_delayed(&es) || ext4_es_is_hole(&es)) {
			map->m_pblk = 0;	/* 空洞或延迟块：无物理块 */
			// ... 同样按 es_len 截断 m_len
		} else {
			BUG();
		}
		goto found;
	}
	// ... 省略：未命中时遍历磁盘 extent 树 / 旧式间接块；
	//            带 EXT4_GET_BLOCKS_CREATE 时真正分配并回填

这是 ext4 的地址簿总入口。先查内存中的 extent status tree，因为延迟分配的“预留但未分配”信息只在这里，磁盘树里还没有。命中 written 直接算出物理块；命中 delayed/hole 返回 m_pblk=0；未命中才读磁盘 extent 树。

三处判断：脏页比例过高（ext4_nonda_switch）时退化为非延迟分配，否则未分配脏页会积压太多；符号链接走快速路径；fs-verity 不可延迟。grab_cache_page_write_begin 找到或创建页缓存页并锁住，交给 generic_perform_write 去 copy_from_user。此时没有分配磁盘块——带 CREATE 的 ext4_map_blocks 要到回写才调用。

4.4 回写：ext4_writepages

fs/ext4/inode.c:2634-2680 ext4_writepages（节选）

	if (!mapping->nrpages || !mapping_tagged(mapping, PAGECACHE_TAG_DIRTY))
		goto out_writepages;          /* 没脏页，直接返回 */

	if (ext4_should_journal_data(inode)) {
		ret = generic_writepages(mapping, wbc);   /* data=journal 模式 */
		goto out_writepages;
	}
	// ... 省略 abort 检查、inline data 清理
	if (wbc->range_cyclic) {
		writeback_index = mapping->writeback_index;
		mpd.first_page = writeback_index;
		mpd.last_page = -1;
	} else {
		mpd.first_page = wbc->range_start >> PAGE_SHIFT;
		mpd.last_page = wbc->range_end >> PAGE_SHIFT;
	}
	blk_start_plug(&plug);
	mpd.do_map = 0;
	ret = mpage_prepare_extent_to_map(&mpd);    /* 聚成 extent 再分配 */
	ext4_io_submit(&mpd.io_submit);             /* 统一发 bio */

四个要点：先看 DIRTY 标记，无脏页不建事务；range_cyclic 实现循环回写，从上次停下的 writeback_index 继续扫；blk_start_plug 把这段期间的 bio 攒起来一次下发，给块层合并机会；mpage_prepare_extent_to_map 把连续脏页聚成 extent 再分配——延迟分配“一次挑大段连续块”的落点。

ext4 用 buffer_head 把一页按块大小切开管理。bio_start/bio_end 是本次 bio 覆盖的字节范围，可能只覆盖页的一部分。只有页上所有 async_write 都清掉、没有别的 bio 还在写这部分（under_io == 0）才 end_page_writeback——这个“最后一个人关灯”的计数是回写正确性的关键。

4.6 htree 根块

fs/ext4/namei.c:221-236 struct dx_root

struct dx_root
{
	struct fake_dirent dot;      char dot_name[4];
	struct fake_dirent dotdot;   char dotdot_name[4];
	struct dx_root_info {
		__le32 reserved_zero;
		u8 hash_version;
		u8 info_length;      /* 8 */
		u8 indirect_levels;  /* 0 = 叶子就在本块 */
		u8 unused_flags;
	} info;
	struct dx_entry	entries[];   /* {hash, block}，按 hash 升序 */
};

开头的 dot/dotdot 让不认识 htree 的工具仍能当普通目录读；info_length=8 自校验。ext4_dx_find_entry 对目标名字算哈希，在 entries[] 二分找到 hash ≤ 目标 的最后一项，跳进对应目录块继续。

5. 动手验证

造镜像看超级块与组描述符（不动本机磁盘）：

dd if=/dev/zero of=/tmp/ext4.img bs=1M count=64
mkfs.ext4 -b 4096 /tmp/ext4.img
dumpe2fs -h /tmp/ext4.img | head -30

预期：Filesystem magic number: 0xEF53、Block size: 4096、Blocks per group: 32768、Journal inode: 8。去掉 -h 还会打印每组的 Block bitmap at、Inode bitmap at、Inode table at，正是 bg_* 三项。

用 debugfs 读 inode 与 extent：

debugfs -w -R "write /etc/hostname big.txt" /tmp/ext4.img
debugfs -R "stat <big.txt>" /tmp/ext4.img

EXTENTS: 段每行是 (逻辑块):(长度):(物理块)，与上面的 ASCII 图一致；若显示 BLOCKS: 列表则说明该文件未开 extent。

看连续性：

fallocate -l 200M /tmp/frag.bin
filefrag -v /tmp/frag.bin | head -15

每行一条 extent。延迟分配生效时 200MB 往往只有极少数、每段很长的 extent。日志：tune2fs -l /tmp/ext4.img | grep -i journal 看日志大小与 inode；用 data=journal 挂载对比——所有数据也走日志，更安全但更慢。

6. 自测

Q1. i_block[60] 存什么？开 extent 时是 extent 树根（4 条 extent 或 1 个索引，eh_magic=0xf30a）；否则是 12 个直接指针加单/双/三重间接块指针。
Q2. 延迟分配为什么减少碎片？write() 只标脏页；回写时聚成 extent 后一次性挑大段连续空间，而不是每次写一点就抢块。
Q3. jbd2 崩溃恢复靠什么判断有效性？每个事务末尾有带校验的提交块；恢复时只重放提交块完整的事务，之后的区块丢弃。
Q4. ext4_map_blocks 为什么先查 extent status tree？延迟分配、未写（unwritten）等信息只存在内存树里；命中可省一次磁盘树遍历。
Q5. htree 比线性目录快在哪？按名字哈希在 dx_entry 数组二分定位叶子块，代价 O(log n) 次块读，而非扫描整目录的所有目录项。
