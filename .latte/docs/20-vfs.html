📂 VFS：文件系统的统一接口层

让 ext4、procfs、tmpfs 都接受同一套 open/read/write · 预计阅读 9 分钟

1. 它在解决什么问题

墙上的插座有两孔、三孔、圆头、方头，每添一件电器就重新布线，日子没法过，于是买个万能插排：正面孔位固定，背面接谁都行。VFS（Virtual File System）就是内核里的这个插排，是系统调用与具体文件系统之间的转接头。

ext4 的数据在硬盘块里，procfs 的内容由内核现算，tmpfs 全在内存。没有 VFS，read() 得先判断 fd 背后是谁再写一长串分支；有了 VFS，read() 只认 file->f_op->read_iter 这个函数指针，指向谁由各文件系统注册。所以 VFS 只提供一套统一数据结构与一组指针表，本身不存数据，只做路由、缓存和权限检查——它是接口层，不是文件系统。

2. 核心名词

术语英文一句话解释
超级块super_block一个已挂载的文件系统实例：块大小、根 dentry、操作表。
索引节点inode文件本身（不含名字）：大小、权限、时间、数据块位置。
目录项dentry“名字→inode”的映射，路径查找的缓存节点，组成目录树。
文件对象file一次打开：fd 指向它，记录偏移 f_pos 与打开模式。
挂载点mount point把另一文件系统根“嫁接”到某目录，用 vfsmount 描述。
硬链接/软链接hard / sym link前者多个目录项共享一个 inode；后者是存路径字符串的独立文件。
目录项缓存dcache把“名字→dentry”结果留在内存，路径查找不必每次读盘。

3. 整体结构

super_block（/dev/sda1 上的 ext4）
 └ s_root ─► dentry("/") ─► dentry("home") ─► dentry("a.txt")
                              │                  │
                              ▼                  ▼
                          inode(目录)        inode(文件)
进程 fd ─► struct file ─ f_inode ───────────────┘
                        f_op ─► ext4_file_operations

四对象各管一段：super_block 管“哪个文件系统”，inode 管“哪个文件”，dentry 管“叫什么、在哪”，file 管“这次打开”。同一文件被两进程打开只有一个 inode、两个 file；同一 inode 可有多个 dentry（硬链接），由 i_nlink 计数。四张操作表是 VFS 的合同：super_operations（sb->s_op：分配/写回/驱逐 inode）、inode_operations（i_op：lookup/create/mkdir/rename）、file_operations（f_op：read_iter/write_iter/mmap/fsync）、dentry_operations（d_op：d_revalidate/d_hash）。

路径查找把名字树变成 dentry 链：从根逐段推进，先查 dcache，未命中才调父目录 i_op->lookup 读盘；若某 dentry 是挂载点，查找跳到新文件系统的 s_root。软链接由 get_link 取回路径串，交回 link_path_walk 继续解析，最多 40 层。

4. 源码走读

4.1 超级块与 inode

include/linux/fs.h:1416-1433 struct super_block（节选）

struct super_block {
	dev_t			s_dev;		/* 按设备号可查 */
	unsigned long		s_blocksize;
	struct file_system_type	*s_type;
	const struct super_operations	*s_op;
	unsigned long		s_magic;	/* ext4 为 0xEF53 */
	struct dentry		*s_root;	/* 路径查找起点 */
	struct rw_semaphore	s_umount;
	int			s_count;
	atomic_t		s_active;
};

s_dev 让 get_super() 找到它；s_op 是文件系统级操作；s_root 是查找起点；s_magic 即 statfs 报的类型码。

		const unsigned int i_nlink;
		unsigned int __i_nlink;
	};
	dev_t			i_rdev;

stat 的字段都能对上：i_ino→Inode，i_mode→权限，i_nlink→Links，i_size→Size，三时间→Access/Modify/Change。dentry（dcache.h:89）带 d_name、d_parent、d_op 和 d_inode（NULL 即“负目录项”，表示查过磁盘确认不存在）；file（fs.h:916）带 f_path、f_inode、f_op、f_pos。

4.2 路径查找

fs/namei.c:2106-2148 link_path_walk（节选）

	nd->flags |= LOOKUP_PARENT;
	for(;;) {
		const char *link; u64 hash_len; int type;
		err = may_lookup(nd);       /* 目录需有 x 权限 */
		if (err) return err;
		hash_len = hash_name(nd->path.dentry, name);  /* 长度+哈希 */
		type = LAST_NORM;
		if (name[0] == '.') switch (hashlen_len(hash_len)) {
			case 2:
				if (name[1] == '.') { type = LAST_DOTDOT; nd->flags |= LOOKUP_JUMPED; }
				break;
			case 1: type = LAST_DOT;
		}
		nd->last.hash_len = hash_len;  nd->last.name = name;  nd->last_type = type;
		// ... 省略：跳过 '/'、符号链接栈、walk_component
	}

fs/namei.c:1842-1859 walk_component（节选）

	dentry = lookup_fast(nd, &inode, &seq);   /* RCU 查 dcache，无锁 */
	if (unlikely(!dentry))
		dentry = lookup_slow(&nd->last, nd->path.dentry, nd->flags);
	return step_into(nd, flags, dentry, inode, seq);  /* 推进 nd->path */

hash_name 一次算出长度与哈希供 dcache 用；./.. 单独标记，因为 .. 可能跨挂载点回父文件系统。lookup_fast 走 __d_lookup_rcu，只用 seqlock（d_seq）校验、不加锁；未命中才 lookup_slow，加 inode 共享锁调 i_op->lookup 读盘并 d_add。

4.3 open 与 read

fs/open.c:1280-1302 do_sys_openat2（节选）

	tmp = getname(filename);                /* 路径拷进内核 */
	fd = get_unused_fd_flags(how->flags);   /* 先占 fd 号 */
	if (fd >= 0) {
		struct file *f = do_filp_open(dfd, tmp, &op);
		if (IS_ERR(f)) { put_unused_fd(fd); fd = PTR_ERR(f); }
		else { fsnotify_open(f); fd_install(fd, f); }  /* fd → file */
	}

先占号再打开，避免打开成功才发现没 fd 可用。path_openat（fs/namei.c:3349）循环 link_path_walk+open_last_lookups（必要时 i_op->create 或展开软链接），最后由 do_dentry_open 设 f->f_op = inode->i_fop 并调文件系统的 .open。

fs/read_write.c:675-700 vfs_read（节选）

	if (!(file->f_mode & FMODE_READ)) return -EBADF;
	if (unlikely(!access_ok(buf, count))) return -EFAULT;
	ret = rw_verify_area(READ, file, pos, count);   /* 文件锁 */
	if (count > MAX_RW_COUNT) count = MAX_RW_COUNT;
	if (file->f_op->read)
		ret = file->f_op->read(file, buf, count, pos);
	else if (file->f_op->read_iter)
		ret = new_sync_read(file, buf, count, pos);  /* 包成 iov_iter */

统一前置检查：打开方式、用户指针、文件锁、单次长度上限，然后分派。vfs_write（:869）对称，多了 file_start_write/end_write，与只读挂载、文件系统冻结协调。现代文件系统一般只实现 read_iter/write_iter，因为 iov_iter 能描述多个不连续用户缓冲区。

4.4 挂载入口

get_fs_type()（fs/filesystems.c:266）按名字在全局链表找 file_system_type，找不到就 request_module("fs-ext4") 加载模块。块设备文件系统随后走 mount_bdev()（fs/super.c:1835）：blkdev_get_by_path 以 FMODE_EXCL 独占打开设备（防两个文件系统同写一块盘），sget 查/建超级块，再调 fill_super（ext4 是 ext4_fill_super）解析盘上超级块、填好 s_root。

5. 动手验证

mkdir -p /tmp/vfsdemo && cd /tmp/vfsdemo
echo hello > a.txt; ln a.txt a_hard.txt; ln -s a.txt a_soft.txt
stat a.txt a_hard.txt a_soft.txt

a.txt 与 a_hard.txt 的 Inode 相同、Links: 2；a_soft.txt 类型为 symbolic link，大小为 5（目标串长度），独立 inode，readlink 输出 a.txt。再观察缓存与独立偏移：

cat /proc/sys/fs/dentry-state      # nr_dentry / nr_unused
cat /proc/mounts | head -5         # 每行 = 一个 super_block + vfsmount
exec 3< a.txt; exec 4< a.txt
cat /proc/self/fdinfo/3 /proc/self/fdinfo/4   # pos 各自独立

两个 fd 的 pos 互不影响，因为是两个 struct file；但 f_inode 相同。若由 fork 继承，则共享同一 file，pos 联动。

6. 自测

Q1. 一个文件被两进程同时打开，几个 inode、几个 file？一个 inode、两个 file；若 fd 由 fork 继承，则共享同一 file，f_pos 也共享。
Q2. 硬链接与软链接的结构差别？硬链接：两个 dentry 的 d_inode 指向同一 inode，i_nlink++；软链接：独立 inode 存路径串，get_link 取回后交回 link_path_walk。
Q3. dcache 命中与未命中各走哪条路？命中 lookup_fast（RCU+seqlock，无锁）；未命中 lookup_slow，加 inode 共享锁调 i_op->lookup。
