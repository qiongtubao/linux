🔌 26-socket 套接字层

一个 fd 背后站着 socket / sock / proto 三层对象；讲清门面如何把 write/connect 变成协议函数调用 · 约 10 分钟

1. 它在解决什么问题

去银行办事你不会翻金库保险柜，而在柜台窗口递单子：窗口对所有业务一样，材料转交后台。socket 层就是内核网络的柜台。

应用的世界极简单：fd = socket(AF_INET, SOCK_STREAM, 0) 拿到整数，之后 read/write/close 它，和普通文件无区别。但底层要区分 TCP 还是 UDP、IPv4 还是 Unix 域、数据落到哪个对象——差异全被门面吞掉。

为什么不让应用直接调 TCP？同一套 API 要服务几十个协议族与三种语义（流、数据报、裸包），逐组合写系统调用会让头文件爆炸。于是内核把"协议无关的门面"（socket 层）与"协议相关的腿"（proto_ops、proto）拆开——经典门面/腿部设计。

从进程看，socket 最终就是一个 struct file：挂在 sockfs 伪文件系统上，天然复用 VFS 的 file_operations。"网络 I/O 像文件 I/O"是刻意设计。

2. 核心名词

术语英文一句话解释
门面对象struct socket协议无关，一个 socket 对应一个 fd，只记类型、状态、所属 file。
协议对象struct sock协议相关的重对象，存收发队列、端口、状态机；TCP 实例是 tcp_sock。
门面腿struct proto_opsbind/connect/sendmsg 函数表，按地址族+类型挑选。
协议腿struct protoclose/sendmsg/recvmsg 函数表，由 TCP/UDP 实现。
协议族工厂net_proto_family按 family 号注册，.create 指向 inet_create。
地址族/类型AF_INET / SOCK_STREAMIPv4 地址族 / 流式语义（type 传 0 时默认即 TCP）。
IPv4 扩展struct inet_sock内嵌 sock，另加端口、IP 选项、TTL 等字段。
内核侧创建sock_create_kern内核自己造 socket（NFS 等用），不占 fd 表。
数据包对象sk_buff承载"一个包"，协议头逐层插入/剥离，只挪指针不拷贝。
Nagle 算法Nagle把小段攒起来再发的合并策略；TCP_NODELAY 关掉它换低延迟。
socketpairsocketpair(2)一次创建两个互连 socket，多用于 Unix 域 IPC。

3. 整体结构

fd=3 → struct file (f_op = socket_file_ops)
          └→ struct socket
                ├── ops ─→ inet_stream_ops (.sendmsg = inet_sendmsg)
                └── sk  ─→ inet_sock { struct sock sk; ... } → tcp_sock
                     sk_prot ─→ tcp_prot (.sendmsg = tcp_sendmsg)

__sys_socket → sock_create → __sock_create
  ├ security_socket_create      LSM 第一道闸
  ├ sock_alloc()                在 sockfs 造 inode 并取出 socket
  ├ net_families[AF_INET] → inet_family_ops.create
  └ inet_create：查 inetsw[type] → 取 ops+prot → sk_alloc → sock_init_data
末尾 sock_map_fd → fd_install，返回整数 fd

三层职责：socket 对齐用户态接口、持 ops 与 sk；sock 是协议状态之家；proto 是无状态函数表，告诉 sock 层"该调谁"。socket(AF_INET, SOCK_STREAM, 0) 的 0 表示"用该类型默认协议"——inetsw_array 把 SOCK_STREAM 首项写成 IPPROTO_TCP，所以默认得到 TCP。

4. 源码走读

4.1 门面：struct socket 与 proto_ops

include/linux/net.h:116-128

struct socket {
	socket_state		state;
	short			type;
	unsigned long		flags;
	struct file		*file;
	struct sock		*sk;
	const struct proto_ops	*ops;
	struct socket_wq	wq;
};

state 只是粗状态（SS_UNCONNECTED/CONNECTED），TCP 精细状态在 sk->sk_state；ops 是多态开关：SOCK_STREAM 装 inet_stream_ops，SOCK_DGRAM 装 inet_dgram_ops；wq 是 poll/epoll 睡眠的等待队列。proto_ops（net.h:139 起）是一张动作清单：release/bind/connect/socketpair/accept/getname/poll/ioctl/sendmsg/recvmsg，外加 owner 模块引用计数，防调函数时驱动被卸载。

4.2 协议腿：proto 与 sock

include/net/sock.h:1127-1161

struct proto {	/* 注释原文：socket layer -> transport layer interface */
	void	(*close)(struct sock *sk, long timeout);
	int	(*connect)(struct sock *sk, struct sockaddr *uaddr, int addr_len);
	struct sock *(*accept)(struct sock *sk, int flags, int *err, bool kern);
	int	(*sendmsg)(struct sock *sk, struct msghdr *msg, size_t len);
	int	(*recvmsg)(struct sock *sk, struct msghdr *msg, size_t len,
			   int noblock, int flags, int *addr_len);
	// ... 省略 pre_connect/disconnect/setsockopt/sendpage 等
};

协议对象 struct sock（include/net/sock.h:347 起）首个成员必须是 sock_common：TIME_WAIT 的"死 socket"只复用这块头部做哈希与地址比较，前面插字段会让偏移错位。它用一串 #define 把 __sk_common.skc_xxx 变短名，所以 sk_state 就是 skc_state。TCP 实例 tcp_prot（net/ipv4/tcp_ipv4.c:2762）把 .sendmsg=tcp_sendmsg、.connect=tcp_v4_connect、.backlog_rcv=tcp_v4_do_rcv 绑好。

4.3 socket()：__sys_socket

net/socket.c:1540-1565

int __sys_socket(int family, int type, int protocol)
{
	struct socket *sock;
	int flags;

	BUILD_BUG_ON(SOCK_CLOEXEC != O_CLOEXEC);
	// ... 另三个 BUILD_BUG_ON 保证位掩码不冲突
	flags = type & ~SOCK_TYPE_MASK;
	if (flags & ~(SOCK_CLOEXEC | SOCK_NONBLOCK))
		return -EINVAL;
	type &= SOCK_TYPE_MASK;
	// ... SOCK_NONBLOCK 与 O_NONBLOCK 数值不同则换算

	retval = sock_create(family, type, protocol, &sock);
	if (retval < 0)
		return retval;
	return sock_map_fd(sock, flags & (O_CLOEXEC | O_NONBLOCK));
}

BUILD_BUG_ON 是编译期自检，保证 SOCK_* 与 O_* 数值一致；SOCK_NONBLOCK/SOCK_CLOEXEC 藏在 type 高位，必须先剥出，低 4 位才是真类型。sock_map_fd（net/socket.c:426）三步：占 fd → sock_alloc_file → fd_install，先占 fd 再建 file，回滚路径最短。

4.4 工厂：__sock_create → inet_create

net/socket.c:1422-1438, 1461-1468

	err = security_socket_create(family, type, protocol, kern);
	if (err) return err;
	sock = sock_alloc();
	if (!sock) { /* net_warn_ratelimited(...) */ return -ENFILE; }
	sock->type = type;
	// ... net_families[family] 为空时 request_module("net-pf-%d", family)
	if (!try_module_get(pf->owner)) goto out_release;
	rcu_read_unlock();
	err = pf->create(net, sock, protocol, kern);

sock_alloc() 不是 kmalloc：在 sockfs 上 new_inode_pseudo，再用 SOCKET_I(inode) 反推 socket——每个 socket 天生有 inode。RCU 只保护表查找，调 pf->create 前必须放掉（可能睡眠），故用模块引用计数钉住工厂。

net/ipv4/af_inet.c:265-285, 314-317

lookup_protocol:	rcu_read_lock();
	list_for_each_entry_rcu(answer, &inetsw[sock->type], list) {
		if (protocol == answer->protocol) {
			if (protocol != IPPROTO_IP) break;
		} else if (IPPROTO_IP == protocol) {	/* type 传 0：取默认协议 */
			protocol = answer->protocol; break;
		} else if (IPPROTO_IP == answer->protocol) break;
		err = -EPROTONOSUPPORT;
	}
	// ... 失败时 request_module("net-pf-2-proto-...") 重试
	sock->ops = answer->ops;	/* 门面腿 */
	answer_prot = answer->prot;	/* 协议腿 */
	rcu_read_unlock();

链表里第一个匹配 type 的项胜出，注册项同时带两套函数表；随后 sk_alloc(..., answer_prot, kern) 按协议 slab 分配，sock_init_data 把 sock->sk 与 sk_set_socket 双向绑定。SOCK_RAW 且 kern=0 时还需 ns_capable(CAP_NET_RAW)，否则 -EPERM（af_inet.c:309-312）。

4.5 门面腿实例：inet_stream_ops

net/ipv4/af_inet.c:1037-1055

const struct proto_ops inet_stream_ops = {
	.family		= PF_INET,   .owner = THIS_MODULE,
	.release	= inet_release,   .bind = inet_bind,
	.connect	= inet_stream_connect,   .socketpair = sock_no_socketpair,

.socketpair = sock_no_socketpair 说明 TCP 不支持 socketpair（返回 -EOPNOTSUPP）；.poll = tcp_poll 说明 epoll 等的是 TCP 队列状态。

4.6 bind 与 sendmsg：一次调用的两跳

net/socket.c:1682-1703

	sock = sockfd_lookup_light(fd, &err, &fput_needed);
	if (sock) {
		err = move_addr_to_kernel(umyaddr, addrlen, &address);
		if (!err)
			err = security_socket_bind(sock, (struct sockaddr *)&address, addrlen);
		if (!err)
			err = sock->ops->bind(sock, (struct sockaddr *)&address, addrlen);
		fput_light(sock->file, fput_needed);
	}
	return err;

顺序固定：查 fd → 拷地址 → LSM → ops->bind。move_addr_to_kernel 是 copy_from_user 的封装，防畸形容错 addrlen 撑爆内核栈。

net/socket.c:688-696 · net/ipv4/af_inet.c:829-837

int sock_sendmsg(struct socket *sock, struct msghdr *msg)
{
	int err = security_socket_sendmsg(sock, msg, msg_data_left(msg));
	return err ?: sock_sendmsg_nosec(sock, msg);	/* 转 ops->sendmsg */
}
// ... inet_sendmsg 内：
	if (unlikely(inet_send_prepare(sk))) return -EAGAIN;
	return INDIRECT_CALL_2(sk->sk_prot->sendmsg, tcp_sendmsg, udp_sendmsg,
			       sk, msg, size);

INDIRECT_CALL_2 是给分支预测器的提示：先比较指针是否等于 tcp_sendmsg，相等就直调，省一次间接跳转，语义等价。

4.7 socketpair 与内核侧 socket

	if (unlikely(err < 0)) goto out;

	if (unlikely(err < 0)) { sock_release(sock1); goto out; }

// ... 内核侧版本，只差 kern 位：
int sock_create(int f, int t, int p, struct socket **res)
{ return __sock_create(current->nsproxy->net_ns, f, t, p, res, 0); }
int sock_create_kern(struct net *net, int f, int t, int p, struct socket **res)
{ return __sock_create(net, f, t, p, res, 1); }

Unix 域实现只让两个 sock 互记 peer 并置已连接（net/unix/af_unix.c:1416-1434）：unix_peer(ska)=skb; unix_peer(skb)=ska;，数据不碰网卡，直接入对端队列。kern 位则标记 sk_kern_sock、决定网络命名空间引用计数，并让 SOCK_RAW 的 CAP_NET_RAW 检查放行——内核对象没有"进程身份"，故留单独入口。

顺带一句 sk_buff：网络栈里"一个包"的搬运工，带一段线性缓冲区，每层用 skb_push 插头、__skb_pull 剥头，只挪指针不复制（细节见第 27 篇）。

#   bind(3, {sa_family=AF_INET, sin_port=htons(9), sin_addr=inet_addr("127.0.0.1")}, 16) = 0
ss -ltnp   # 监听 TCP；ss -tanp 看全部连接；netstat -tnlp 列一致

socketpair 两个 fd 号不同，send 后 recv 立刻返回，因为内核里两 sock 已互为 peer；strace -e trace=socketpair 会看到一次 socketpair(AF_UNIX, SOCK_STREAM, 0, [3, 4]) 吐两个 fd。

ss 列含义：典型行 LISTEN 0 128 127.0.0.1:8888 0.0.0.0:* users:("python3",fd=3)。State 来自 sk->sk_state；Recv-Q 是已收未读字节（接收队列长度）；Send-Q 是已发未 ACK 字节，监听态则是 backlog 上限；Local/Peer 来自 inet_sport/saddr 与 inet_dport/daddr；users 是反查 inode→file→fd 表得到的持有者。

TCP_NODELAY：tcpdump -i lo -A port 9001 一边跑，另一边 setsockopt(IPPROTO_TCP, TCP_NODELAY, 1) 后连发三个 1 字节。设了 NODELAY 时三个包各自立刻发出；不设时后段可能攒进下一段"捎带"，一个报文里看到多个 x。

6. 自测

Q1. 为什么 struct sock 首个成员必须是 sock_common？inet_timewait_sock 只复用这块头部做哈希与地址比较；前面插字段会让偏移错位，sk_daddr 等宏读到错误内存。
Q2. socket() 的 type 高位标志怎么处理？__sys_socket 先 type & ~SOCK_TYPE_MASK 剥出 CLOEXEC/NONBLOCK，再取低 4 位作真类型。
Q3. proto_ops 与 proto 都有 sendmsg，为何两份？门面腿收 struct socket* 做通用检查，协议腿收 struct sock* 做真正协议工作，inet_sendmsg 是翻译器。
Q4. socket(AF_INET, SOCK_STREAM, 0) 的 0 是什么意思？即 IPPROTO_IP 通配，让 inet_create 在 inetsw 链表挑第一个匹配 type 的项，即 IPPROTO_TCP。
Q5. 为何 /proc/<pid>/fd 显示 socket:[inode]？socket 寄居 sockfs 伪文件系统：sock_alloc 先造 inode 再取出 socket，fd 指向该 inode，内核态只能显示 inode 号。
