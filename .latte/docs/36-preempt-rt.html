⏱️ PREEMPT_RT 与抢占模型

救护车为什么必须比货车先走：内核可抢占性的代价与实现 · 预计阅读 20 分钟

1. 它在解决什么问题

城市按“平均车速最高”来调度红绿灯：大货车优先放行，谁排队谁走。平时吞吐确实最高，可急救车鸣笛冲过来，还得排在两辆货车后面——等多久没人事先知道。实时性要求换一套规则：高优先级任务一出现，最多几十微秒内必须放行，而且每次波动要小。

内核里，“决定下一个谁跑”由调度器完成（见 07 篇），但决定不等于立刻发生。如果 CPU 正在内核里执行一段不许打断的代码，更高优先级的任务只能干等，这段等待就是调度延迟。两个指标：延迟是事件到任务真正开始运行的时间，抖动是多次延迟之间的波动。机械臂、刹车、交易网关在意“最坏那次”和抖动，平均值毫无意义。

阻碍低延迟的就三类东西：内核临界区不可抢占（别人抱着锁跑长循环）、关中断太久（事件进不来）、自旋锁忙等加优先级反转（高优先级给低优先级持有者陪跑）。本篇按这三条线讲 preempt_count、四种抢占模型、中断线程化、rtmutex 与优先级继承。

2. 核心名词

术语英文一句话解释
抢占preemption内核主动打断当前任务，把 CPU 让给更该跑的，而不是等它自己让出。
延迟 / 抖动latency / jitter事件到任务启动的时间 / 该时间的波动幅度。
硬实时hard real-time超时即失败（刹车、飞控）；软实时只是体验变差（音视频）。
抢占计数preempt_count每 CPU 一个整数，记录“当前有几层不许抢占/正在处理中断”，为 0 才可能抢占。
重调度标志NEED_RESCHED“有人该跑了”的标志；x86 上折进 preempt_count 最高位。
自旋锁spinlock拿不到就原地循环等待的锁，持锁期间禁止抢占，所以不能睡。
实时互斥锁rtmutex带优先级继承的睡眠锁，RT 上替代普通 spinlock。
优先级继承priority inheritance低优先级持锁者临时借用等待者的高优先级，避免被中优先级插队。
中断线程化threaded IRQ中断处理函数搬进内核线程 irq/N-name，可被调度、可被抢占。
软中断softirq中断下半部，在“中断上下文”延迟执行；RT 上交给 ksoftirqd/N。
迁移禁用migrate_disable只禁任务换 CPU；普通内核里等价于 preempt_disable。
基准工具cyclictest反复“睡 N 微秒再醒”，测实际唤醒延迟（rt-tests 包）。

3. 整体结构

3.1 四种抢占模型

模型是 kernel/Kconfig.preempt 里的一个 choice，编译期定死：

配置项典型用途行为
CONFIG_PREEMPT_NONE服务器只有主动睡眠/调用 schedule() 才让出，吞吐最高、延迟最差。
CONFIG_PREEMPT_VOLUNTARY桌面在长循环里插“自愿抢占点”（cond_resched()），延迟变小、吞吐略降。
CONFIG_PREEMPT桌面/嵌入式内核态也可抢占，只要 preempt_count == 0；在 preempt_enable() 处检查。
CONFIG_PREEMPT_RT硬实时再把 spinlock 换 rtmutex、强制中断线程化，除极少数核心路径外全部可抢占。

3.2 preempt_count 的位图

它不是布尔值，而是 32 位整数切成几段，每段一个“嵌套深度”：

31        24 23     20 19      16 15             8 7            0
┌──────────┬──────────┬──────────┬────────────────┬──────────────┐
│ NEED_    │  NMI     │ HARDIRQ  │   SOFTIRQ      │   PREEMPT    │
│ RESCHED  │  4 bit   │  4 bit   │   8 bit        │    8 bit     │
│0x80000000│0x00f00000│0x000f0000│   0x0000ff00   │  0x000000ff  │
└──────────┴──────────┴──────────┴────────────────┴──────────────┘
   ↑ 反相位：不需要调度时反而置 1        ↑ 关抢占/关下半部都使低 8 位 +1

3.3 PREEMPT_RT 做的四件事

  • 自旋锁换睡眠锁：spin_lock() 拿不到时不再忙等，而是睡进 rt_mutex，让出 CPU 并带优先级继承；真正不能睡的短路径改用 raw_spinlock_t。
  • 中断线程化：硬中断处理函数变成内核线程 irq/N-name，按 SCHED_FIFO 排队，可被更高优先级抢占。
  • 软中断交给线程：ksoftirqd/N 本就是每 CPU 内核线程（kernel/softirq.c:722-738），RT 让它以实时优先级运行，长软中断不再无限占用 CPU。
  • 拆长临界区：需要“别换 CPU”的地方改用 migrate_disable()，把抢占还给调度器。

3.4 优先级继承链

无 PI：H(10) ──等锁──► L(90) 持锁 ──被──► M(50) 抢占
                        │
                        └─► H 实际被 M 间接阻塞（时长不可预期）

有 PI：H(10) ──等锁──► L(90) 持锁
                        │ rt_mutex_adjust_prio_chain()
                        ▼
                      L 的 prio 提升到 10
                        │
                        ▼
                      M(50) 抢不动 L → L 快速放锁 → H 立即运行
                        │
                        ▼
                      放锁后 L 降回 90（deboost）

4. 源码走读

4.1 位定义与抢占触发点

include/linux/preempt.h:24-35 preempt_count 位布局

 *         PREEMPT_MASK:	0x000000ff
 *         SOFTIRQ_MASK:	0x0000ff00
 *         HARDIRQ_MASK:	0x000f0000
 *             NMI_MASK:	0x00f00000
 * PREEMPT_NEED_RESCHED:	0x80000000
 */
#define PREEMPT_BITS	8
#define SOFTIRQ_BITS	8
#define HARDIRQ_BITS	4
#define NMI_BITS	4
  • 低 8 位是抢占深度：preempt_disable() 加一，最多 256 层。
  • 8-15 位是软中断 / 关下半部的深度；16-19 是硬中断；20-23 是 NMI。
  • 因此 in_interrupt() 等价于“高 16 位里有非零段”，in_task() 只看中断段、不看抢占位（include/linux/preempt.h:80-103）。

抢占真正发生的地方是宏 preempt_enable()：

include/linux/preempt.h:185-191 preempt_enable

#ifdef CONFIG_PREEMPTION
#define preempt_enable() \
do { \
	barrier(); \
	if (unlikely(preempt_count_dec_and_test())) \
		__preempt_schedule(); \
} while (0)

barrier() 防止编译器把临界区内外的代码重排到计数之外；preempt_count_dec_and_test() 在 !CONFIG_PREEMPT_COUNT 时是空操作，所以 NONE/VOLUNTARY 模型完全零开销——这才是它们吞吐更高的原因。入口函数做最后一道把关：

kernel/sched/core.c:5800-5812 preempt_schedule

asmlinkage __visible void __sched notrace preempt_schedule(void)
{
	/*
	 * If there is a non-zero preempt_count or interrupts are disabled,
	 * we do not want to preempt the current task. Just return..
	 */
	if (likely(!preemptible()))
		return;

	preempt_schedule_common();
}

preemptible() 定义为 preempt_count() == 0 && !irqs_disabled()（同文件 183 行），一句话涵盖两个前提。通过后进入 preempt_schedule_common()（kernel/sched/core.c:5766-5793），那里先 preempt_disable_notrace() 防止函数跟踪器递归，再 __schedule(true)，循环至 need_resched() 为假。

x86 的特殊设计：PREEMPT_NEED_RESCHED = 0x80000000，且不需要调度时该位反而置 1（arch/x86/include/asm/preempt.h:12-26）。这样计数递减到 0 就同时表示“可抢占且该抢占”，preempt_enable() 热路径少一次读。对外 preempt_count() 始终把最高位掩掉，驱动看到的仍是“0 表示可抢占”。

4.2 migrate_disable：只禁迁移

include/linux/preempt.h:325-338 migrate_disable

/**
 * migrate_disable - Prevent migration of the current task
 *
 * Maps to preempt_disable() which also disables preemption. Use
 * migrate_disable() to annotate that the intent is to prevent migration,
 * but not necessarily preemption.
 *
 * Can be invoked nested like preempt_disable() and needs the corresponding
 * number of migrate_enable() invocations.
 */
static __always_inline void migrate_disable(void)
{
	preempt_disable();
}

per-CPU 数据只要求“任务别换 CPU”，没要求“不许被打断”。普通内核图省事，把两件事合成一个宏；注释里“not necessarily preemption”就是提醒：RT 上它会单独记迁移计数，把抢占还给调度器。普通内核里它是语义超集（禁得更多），但正确，所以需要 per-CPU 语义的代码（如 BPF 每 CPU 映射，include/linux/filter.h:596）可以提前这样写。

4.3 中断线程化：irq_thread

线程化后，硬中断只做“确认 + 唤醒”，真正干活的是内核线程：

kernel/irq/manage.c:1150-1181 irq_thread（节选）

static int irq_thread(void *data)
{
	struct callback_head on_exit_work;
	struct irqaction *action = data;
	struct irq_desc *desc = irq_to_desc(action->irq);
	irqreturn_t (*handler_fn)(struct irq_desc *desc,
			struct irqaction *action);

	if (force_irqthreads && test_bit(IRQTF_FORCED_THREAD,
					&action->thread_flags))
		handler_fn = irq_forced_thread_fn;
	else
		handler_fn = irq_thread_fn;
	// ... 省略 init_task_work / irq_thread_check_affinity
	while (!irq_wait_for_interrupt(action)) {
		irqreturn_t action_ret;

		irq_thread_check_affinity(desc, action);

		action_ret = handler_fn(desc, action);
		if (action_ret == IRQ_WAKE_THREAD)
			irq_wake_secondary(desc, action);

		wake_threads_waitq(desc);
	}
  • irq_wait_for_interrupt()（同文件 937-959 行）先 set_current_state(TASK_INTERRUPTIBLE) 再忙 test_and_clear_bit(IRQTF_RUNTHREAD)，没标志才 schedule()。先置状态后检查是防丢唤醒的经典顺序。
  • force_irqthreads 由启动参数 threadirqs 打开（同文件 27-33 行）；IRQTF_FORCED_THREAD 表示该 action 是被强制转换的。
    • <
  • irq_forced_thread_fn() 先 local_bh_disable() 再调原函数（1070-1083 行），兼容老驱动的隐式假设；显式线程化的中断走 irq_thread_fn()，允许睡眠。
  • 线程由 setup_irq_thread() 用 kthread_create(irq_thread, …) 创建，名字 irq/%d-%s，随后 sched_set_fifo(t)（1308-1330 行）。
  • 准入规则在 irq_setup_forced_threading()：IRQF_NO_THREAD|IRQF_PERCPU|IRQF_ONESHOT 跳过，其余把 handler 挪进 thread_fn（1219-1250 行）。注意 manage.c:27 的 !defined(CONFIG_PREEMPT_RT)——RT 下中断本来就全线程化。

4.4 rtmutex：睡着的锁 + 优先级继承

struct rt_mutex 只有三样东西：raw_spinlock_t wait_lock、按优先级排序的等待者红黑树、owner 指针（include/linux/rtmutex.h:30-43）。入队与提升逻辑：

kernel/locking/rtmutex.c:950-1002 task_blocks_on_rt_mutex（节选）

	raw_spin_lock(&task->pi_lock);
	waiter->task = task;
	waiter->lock = lock;
	waiter->prio = task->prio;
	waiter->deadline = task->dl.deadline;

	/* Get the top priority waiter on the lock */
	if (rt_mutex_has_waiters(lock))
		top_waiter = rt_mutex_top_waiter(lock);
	rt_mutex_enqueue(lock, waiter);

	task->pi_blocked_on = waiter;

	raw_spin_unlock(&task->pi_lock);

	if (!owner)
		return 0;

	raw_spin_lock(&owner->pi_lock);
	if (waiter == rt_mutex_top_waiter(lock)) {
		rt_mutex_dequeue_pi(owner, top_waiter);
		rt_mutex_enqueue_pi(owner, waiter);

		rt_mutex_adjust_prio(owner);
		if (owner->pi_blocked_on)
			chain_walk = 1;
	} else if (rt_mutex_cond_detect_deadlock(waiter, chwalk)) {
		chain_walk = 1;
	}
  • 两把锁分工：lock->wait_lock 保护等待队列，task->pi_lock 保护“阻塞在什么锁上”及每任务的继承树 pi_waiters。
  • 只有 rt_mutex_top_waiter()（锁上优先级最高的等待者）才需要把优先级传给持有者；更低者传了也无意义。
  • owner->pi_blocked_on 非空说明持有者自己也在等另一把锁，于是 chain_walk = 1，沿链继续上溯——由 rt_mutex_adjust_prio_chain()（447 行起）完成，链深上限 max_lock_depth = 1024（377 行），超限返回 -EDEADLK。
  • 真正改优先级是 rt_mutex_setprio()（kernel/sched/core.c:5970 起）：取 __rt_effective_prio()，相同则提前返回，否则重排调度类并记录 p->pi_top_task 供解锁时降级。
RT 上 spinlock_t 变 rtmutex，但 raw_spinlock_t 保留自旋语义（include/linux/spinlock_types.h:71-83）。读 RT 代码最常踩的坑就是分不清 spin_lock 与 raw_spin_lock——前者在 RT 允许睡，后者不许。
上游合并状态：本仓库 5.10 主线只有 rtmutex 与 CONFIG_PREEMPT_RT 选项（kernel/Kconfig.preempt:58-74），完整 RT 补丁集仍是树外补丁，2024 年才合入主线 v6.12。

5. 动手验证

① 当前内核是哪种模型。模型编译进内核，运行时可查：

$ zgrep -E 'CONFIG_PREEMPT(_NONE|_VOLUNTARY|_RT)?=' /proc/config.gz
# 没有 /proc/config.gz 时：grep PREEMPT /boot/config-$(uname -r)
CONFIG_PREEMPT=y          # NONE/RT 同理

② 看中断线程长什么样。

$ ps -eo pid,cls,rtprio,comm | grep -E 'irq/|ksoftirqd'
 12  FF      50 irq/16-xhci_hcd     # FF = SCHED_FIFO
 18  TS       - ksoftirqd/2          # TS = SCHED_OTHER（普通内核）
$ cat /proc/interrupts | head -3    # 行尾名字即线程名

加 threadirqs 启动参数后，几乎所有中断都以 irq/ 开头；RT 内核默认如此。

③ 用 cyclictest 量延迟（rt-tests 包，需要 root 以设 SCHED_FIFO）：

# cyclictest -m -Sp90 -i200 -h400 -n -D 30s
T: 0 ( 1234) P:90 I:200 C:150000 Min:  12 Act:  18 Avg:  19 Max:  85

Min/Act/Avg 是常态，Max 才是硬实时关心的“最坏一次”：-m 锁内存、-S 每线程独立计时、-i200 睡 200μs、-h400 直方图到 400μs。Max 从几十微秒跳到几千，说明有长临界区、关中断太久或虚拟化/SMI 偷时间。

④ 定位元凶。latencytop 按调用栈聚合延迟，接口 /proc/latency_stats（需 CONFIG_LATENCYTOP，kernel/Makefile:99）：

# cd /sys/kernel/debug/tracing
# echo function_graph > current_tracer
# echo 1 > options/funcgraph-irqs
# echo '*spin_lock*' > set_graph_function && cat trace | head -30

funcgraph-irqs 会在图上标出 IRQ 开关与抢占计数变化，直接看到某段代码是否长时间不可抢占。

6. 自测

Q1. preempt_count 为 0 就一定能抢占吗？不。还要中断已开启（preemptible() 的两个条件），并且 NEED_RESCHED 真的有效；三者同时满足，preempt_enable() 或中断返回路径才会进 preempt_schedule()。
Q2. 为什么 RT 不是直接删掉自旋锁，而是换成 rtmutex？因为很多临界区真的不能睡（在中断上下文，或保护调度器自身），它们用 raw_spinlock_t 保留自旋。RT 只把“任务上下文里可以睡”的那部分换成 rtmutex，并靠优先级继承保证持锁者尽快被唤醒。
Q3. 优先级继承解决“低优先级跑得慢”吗？不。它解决的是中优先级插队：把持锁者有效优先级抬到等待者水平，使 M 抢不动它，从而尽快放锁。
Q4. migrate_disable 与 preempt_disable 差在哪？per-CPU 数据只要求不换 CPU。普通内核把两者合并（include/linux/preempt.h:335-338），RT 分开：迁移禁了、抢占还在，于是拿到 per-CPU 数据后仍可被更高优先级任务抢占。
Q5. 中断线程化后上半部还做什么？只做读状态、清中断源、置 IRQTF_RUNTHREAD 唤醒 irq/… 线程；耗时、可能睡眠的处理逻辑在 thread_fn 里，可按优先级排队并被抢占。
