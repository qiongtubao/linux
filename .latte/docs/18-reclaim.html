♻️ 内存回收：direct reclaim、kswapd 与 LRU 的取舍

内存不够时，内核必须从"已经分配出去的页"里挑一些扔掉，问题是扔谁、什么时候扔、扔之前要不要先写到磁盘 · 预计阅读 45 分钟

1. 它在解决什么问题

前面两讲讲了"怎么给"：缺页时分配物理页，mmap 时建立映射。但内存管理还有另一半——怎么收。想象一家图书馆：书架是有限的，借出去的书不可能无限增加。当有人来借书而书架满了，管理员必须做两件事之一——要么把暂时没人看的书先搬到后面的储藏室（这就是换出到 swap），要么把纯粹是复印出来的、谁都没在借的副本扔掉（这就是回收文件缓存）。管理员还必须挑对要处理的 book：把热门书搬走，下次有人借就得跑一趟仓库，得不偿失；把冷门书扔掉则毫无损失。

Linux 的策略和这个比喻高度一致。物理内存被划分成 active/inactive × anon/file 四条 LRU 链表（第 3.1 节详述）：active 表示"最近还在用"，inactive 表示"最近没用"；anon 是匿名页（没有文件后备，换出要写 swap），file 是文件页（页缓存里的内容，换出只是扔掉，因为磁盘上还有）。回收时，内核优先从 inactive 链表下手，因为那里的页最"冷"。

回收由两条路径触发，二者分工明确：

  • 直接回收（direct reclaim）：某个进程申请内存时发现空闲页不够了，它自己停下来去回收。好处是不浪费任何内存（省下的正好给自己用），坏处是这个进程被卡住了——用户态表现为程序卡顿、延迟飙升。生产环境里"应用突然变慢"经常就是撞上了 direct reclaim。
  • 后台回收（kswapd）：一个专门的内核线程，平时就常驻。它盯着各个 zone 的水位线，一旦空闲页低于"低水位"，就主动醒来回收，把空闲页补回"高水位"，然后睡下。好处是回收的延迟被提前了，大多数情况下应用根本不会撞上 direct reclaim。

如果两条路都救不回来——内存全满、swap 也满、回收也回收不出东西了——就只剩最后一招：OOM（Out Of Memory，杀进程）。内核用 oom_badness() 给每个进程打分，杀掉那个"最该杀"的（占用内存最多、且价值最低的）。

本文按"LRU 链表怎么组织 → 怎么决定扔哪些（swappiness）→ 两条回收路径的代码 → 水位线与唤醒 → swap 的角色 → OOM 判定 → 怎么看监控数据"这条线讲。

3. 整体结构

3.1 四条 LRU 链表

每个 NUMA 节点（pg_data_t）下有 4 条可回收链表 + 1 条不可回收链表。链表的排列顺序不是随意的，源码里有明确注释要求：

include/linux/mmzone.h:246-257 enum lru_list

enum lru_list {
	LRU_INACTIVE_ANON = LRU_BASE,
	LRU_ACTIVE_ANON = LRU_BASE + LRU_ACTIVE,
	LRU_INACTIVE_FILE = LRU_BASE + LRU_FILE,
	LRU_ACTIVE_FILE = LRU_BASE + LRU_FILE + LRU_ACTIVE,
	LRU_UNEVICTABLE,
	NR_LRU_LISTS
};

#define for_each_lru(lru) for (lru = 0; lru < NR_LRU_LISTS; lru++)

#define for_each_evictable_lru(lru) for (lru = 0; lru <= LRU_ACTIVE_FILE; lru++)

结构图：

  每个 NUMA 节点（pg_data_t）：

  +--------------------------------------------------+
  |  LRU_INACTIVE_ANON   冷匿名页（堆、栈、堆外 malloc）|
  |        ^  新页先进 inactive，被访问则升到 active      |
  |        |                                            |
  |        v  长期不用则被回收（写 swap 或直接释放）      |
  |  LRU_ACTIVE_ANON     热匿名页                        |
  +--------------------------------------------------+
  |  LRU_INACTIVE_FILE   冷文件页（页缓存里的旧文件内容）  |
  |        ^  读文件产生，第二次访问才升到 active          |
  |        |                                            |
  |        v  回收 = 直接丢弃（磁盘上还有副本）           |
  |  LRU_ACTIVE_FILE     热文件页                        |
  +--------------------------------------------------+
  |  LRU_UNEVICTABLE     不可回收：mlock 的页、正在写的页  |
  +--------------------------------------------------+

三条重要规则：① 新分配的页先进 INACTIVE，只有被再次访问才升到 ACTIVE——这样可以避免"刚分配的页"因为一次访问就被误判为热页；② 回收只从 INACTIVE 开始，ACTIVE 里的页要先"降级"（deactivate）才可能被回收；③ 文件页回收最"便宜"（丢弃即可，磁盘上有副本），匿名页回收最"贵"（要写 swap，有 IO 成本）——这个成本差异就是 swappiness 要平衡的核心。

3.3 水位线：什么时候该动手

每个 zone 有三个水位：

  可用内存（free）
     ^
     |
  high +---------------------------------+  <- kswapd 睡到这里（回收目标）
     |  \
  low  +---+-----------------------------+  <- 跌破：唤醒 kswapd
     |  \
  min  +---+-----------------------------+  <- 跌破：分配者自己也得参与回收
     |
     +-----------------------------------+
       0

  /proc/zoneinfo 里的 low/high/min 就是这三个值

对应源码里的三个宏（include/linux/mmzone.h:314-316）：

#define min_wmark_pages(z) (z->_watermark[WMARK_MIN] + z->watermark_boost)
#define low_wmark_pages(z) (z->_watermark[WMARK_LOW] + z->watermark_boost)
#define high_wmark_pages(z) (z->_watermark[WMARK_HIGH] + z->watermark_boost)

kswapd 的目标是把空闲内存补到 high 水位（而不是刚好够用），这样下次分配就不会紧张。分配者只有在跌破 min 水位时才会自己参与 direct reclaim。

3.4 swap 在其中的角色

匿名页（堆、栈）没有"磁盘上的副本"，要回收必须先把内容写到 swap，这就是"换出"。文件页可以直接扔（因为磁盘上就是它的副本）。所以：

  • 有 swap 时：匿名页可以被回收（写 swap），系统能撑住更大的内存占用；代价是 swap 读写有 IO 延迟，而且换出的页再访问时会有"换入延迟"。
  • 无 swap 时：匿名页不能被回收——写了也白写（may_swap 被置 0 或 swap 页数为 0）。此时系统只能回收文件页；如果文件页也不够，OOM 就会来得很快。

这就解释了 swappiness 的意义：swappiness=0 表示"尽量别动匿名页"（适合数据库这种想把数据留在内存里的场景），swappiness=100 表示"随便换"。默认值 60 是一种折中。

3.5 OOM：最后的选择

回收失败且内存仍然不足时，分配者会触发 OOM 处理：内核遍历所有进程，用 oom_badness() 打分，选分数最高的杀掉，释放它的内存，然后重试分配。打分主要看三样：RSS（常驻内存）+ swap 占用 + 页表占用，再叠加 oom_score_adj 的调整。

  OOM Killer 的选择流程：

  for_each_process(p)
        |
        v
    oom_badness(p, totalpages)
        |
        +-- p 被标记为不可杀（oom_score_adj = -1000）-> 跳过
        +-- 分数 = RSS + swap + pgtables + oom_score_adj 调整
        |
        v
    保留分数最高的那个进程
        |
        v
    oom_kill_process() -> 杀掉它 -> 释放它的内存

你可以用 /proc/[pid]/oom_score 看某个进程当前的分数（不用等 OOM 发生，这个值平时就能查）。

4. 源码走读

4.1 get_scan_count()：每条 LRU 该扫多少

回收的第一个决策是"这次回收，匿名页和文件页各出多少力"。这个决策由 get_scan_count() 做出，核心是 swappiness 加权的比例计算。

mm/vmscan.c:2586-2612 get_scan_count

	 * The amount of pressure we put on each LRU is inversely
	 * proportional to the cost of reclaiming each list, as
	 * determined by the share of pages that are refaulting, times
	 * the relative IO cost of bringing back a swapped out
	 * anonymous page vs reloading a filesystem page (swappiness).
	 *
	 * Although we limit that influence to ensure no list gets
	 * left behind completely: at least a third of the pressure is
	 * applied, before swappiness.
	 *
	 * With swappiness at 100, anon and file have equal IO cost.
	 */
	total_cost = sc->anon_cost + sc->file_cost;
	anon_cost = total_cost + sc->anon_cost;
	file_cost = total_cost + sc->file_cost;
	total_cost = anon_cost + file_cost;

	ap = swappiness * (total_cost + 1);
	ap /= anon_cost + 1;

	fp = (200 - swappiness) * (total_cost + 1);
	fp /= file_cost + 1;

	fraction[0] = ap;
	fraction[1] = fp;
	denominator = ap + fp;
out:

逐行拆解：anon_cost / file_cost 是内核统计的"最近把这两类页回收出去之后，它们又被重新访问（refault）的比例"。refault 越高，说明回收这两类页不划算（刚收走又要读回来），所以 cost 高、以后少收一点。

然后是 swappiness 加权：ap（anon 的权重）= swappiness × ...，fp（file 的权重）= (200 - swappiness) × ...。注意 file 那边的系数是 200 而不是 100——这是为了让"即使 swappiness=0，也仍然保留约 1/3 的压力给 file 链表"（注释里的 "at least a third of the pressure"），避免匿名页完全不被回收导致 OOM。

最终每条 LRU 扫多少页在 2672-2709 行算出来：

		scan >>= sc->priority;

		switch (scan_balance) {
		case SCAN_EQUAL:
			/* Scan lists relative to size */
			break;
		case SCAN_FRACT:
			/*
			 * Scan types proportional to swappiness and
			 * their relative recent reclaim efficiency.
			 */
			scan = mem_cgroup_online(memcg) ?
			       div64_u64(scan * fraction[file], denominator) :
			       DIV64_U64_ROUND_UP(scan * fraction[file],
						  denominator);
			break;
		case SCAN_FILE:
		case SCAN_ANON:
			/* Scan one type exclusively */
			if ((scan_balance == SCAN_FILE) != file)
				scan = 0;
			break;
		default:
			/* Look ma, no brain */
			BUG();
		}

		nr[lru] = scan;

四个 scan_balance 模式：SCAN_EQUAL（按链表大小等比）、SCAN_FRACT（按 swappiness 比例，默认路径）、SCAN_FILE / SCAN_ANON（只扫其中一类）。scan >>= sc->priority 是优先级机制：sc->priority 从 0 开始，每一轮回收失败就 +1（最大 12），每加 1 扫描量减半。这是"越回收不到，越要少扫一点，避免 CPU 空转"的保护。

4.2 shrink_lruvec()：真正逐条链表去扫

mm/vmscan.c:2727-2757 shrink_lruvec

static void shrink_lruvec(struct lruvec *lruvec, struct scan_control *sc)
{
	unsigned long nr[NR_LRU_LISTS];
	unsigned long targets[NR_LRU_LISTS];
	unsigned long nr_to_scan;
	enum lru_list lru;
	unsigned long nr_reclaimed = 0;
	unsigned long nr_to_reclaim = sc->nr_to_reclaim;
	struct blk_plug plug;
	bool scan_adjusted;

	get_scan_count(lruvec, sc, nr);

	/* Record the original scan target for proportional adjustments later */
	memcpy(targets, nr, sizeof(nr));

	/*
	 * Global reclaiming within direct reclaim at DEF_PRIORITY is a normal
	 * event that can occur when there is little memory pressure e.g.
	 * multiple streaming readers/writers. Hence, we do not abort scanning
	 * when the requested number of pages are reclaimed when scanning at
	 * DEF_PRIORITY on the assumption that the fact we are direct
	 * reclaiming implies that kswapd is not keeping up and it is best to
	 * do a batch of work at once. For memcg reclaim one check is made to
	 * abort proportional reclaim if either the file or anon lru has already
	 * dropped to zero at the first pass.
	 */
	scan_adjusted = (!cgroup_reclaim(sc) && !current_is_kswapd() &&
			 sc->priority == DEF_PRIORITY);

	blk_start_plug(&plug);

get_scan_count() 填的是"计划扫多少"，targets 保存一份原始计划（后面要按比例修正）。scan_adjusted 这段注释解释了一个精妙的取舍：处于 DEF_PRIORITY（默认优先级）的全局 direct reclaim，即使已经回收够数了也继续扫——因为"能进 direct reclaim"本身就说明 kswapd 没跟上，多扫一点比来回触发更划算。

mm/vmscan.c:2760-2782 shrink_lruvec（主循环）

		unsigned long nr_anon, nr_file, percentage;
		unsigned long nr_scanned;

		for_each_evictable_lru(lru) {
			if (nr[lru]) {
				nr_to_scan = min(nr[lru], SWAP_CLUSTER_MAX);
				nr[lru] -= nr_to_scan;

				nr_reclaimed += shrink_list(lru, nr_to_scan,
							    lruvec, sc);
			}
		}

		cond_resched();

		if (nr_reclaimed < nr_to_reclaim || scan_adjusted)
			continue;

每次循环处理 4 条链表，每条最多取 SWAP_CLUSTER_MAX（默认 32 页）个，避免一次做太多导致长时间不调度；shrink_list() 才是真正逐页尝试回收的地方（文件页直接丢弃，匿名页写 swap）。cond_resched() 是必要的礼貌：回收是重 CPU 的活，不能霸占 CPU 不让别的进程跑。

4.3 shrink_node()：节点级的调度

mm/vmscan.c:3003-3026 shrink_node

static void shrink_node(pg_data_t *pgdat, struct scan_control *sc)
{
	struct reclaim_state *reclaim_state = current->reclaim_state;
	unsigned long nr_reclaimed, nr_scanned;
	struct lruvec *target_lruvec;
	bool reclaimable = false;
	unsigned long file;

	target_lruvec = mem_cgroup_lruvec(sc->target_mem_cgroup, pgdat);

again:
	memset(&sc->nr, 0, sizeof(sc->nr));

	nr_reclaimed = sc->nr_reclaimed;
	nr_scanned = sc->nr_scanned;

	/*
	 * Determine the scan balance between anon and file LRUs.
	 */
	spin_lock_irq(&pgdat->lru_lock);
	sc->anon_cost = target_lruvec->anon_cost;
	sc->file_cost = target_lruvec->file_cost;
	spin_unlock_irq(&pgdat->lru_lock);

shrink_node() 是"一个 NUMA 节点一次回收"的调度者：先取出 anon_cost / file_cost（供 get_scan_count() 用），决定要不要把某些 active 页"降级"到 inactive（may_deactivate），然后调 shrink_node_memcgs() 真正扫描。

mm/vmscan.c:3176-3193 shrink_node（收尾与重试）

	if (!current_is_kswapd() && current_may_throttle() &&
	    !sc->hibernation_mode &&
	    test_bit(LRUVEC_CONGESTED, &target_lruvec->flags))
		wait_iff_congested(BLK_RW_ASYNC, HZ/10);

	if (should_continue_reclaim(pgdat, sc->nr_reclaimed - nr_reclaimed,
				    sc))
		goto again;

	/*
	 * Kswapd gives up on balancing particular nodes after too
	 * many failures to reclaim anything from them and goes to
	 * sleep. On reclaim progress, reset the failure counter. A
	 * successful direct reclaim run will revive a dormant kswapd.
	 */
	if (reclaimable)
		pgdat->kswapd_failures = 0;
}

should_continue_reclaim() 判断"要不要再来一轮"（高阶分配、碎片化场景需要更多回收）；wait_iff_congested() 是IO 拥塞时的刹车——如果块设备已经忙不过来了，回收再多也是白费（写 swap 反而更堵），不如先等等。最后 pgdat->kswapd_failures = 0 是"回收有进展就把失败计数清零"，kswapd 连续失败太多次就会放弃这个节点去睡觉。

4.4 kswapd 的回收目标：水位线

mm/vmscan.c:3948-3970 kswapd_shrink_node

static bool kswapd_shrink_node(pg_data_t *pgdat,
			       struct scan_control *sc)
{
	struct zone *zone;
	int z;

	/* Reclaim a number of pages proportional to the number of zones */
	sc->nr_to_reclaim = 0;
	for (z = 0; z <= sc->reclaim_idx; z++) {
		zone = pgdat->node_zones + z;
		if (!managed_zone(zone))
			continue;

		sc->nr_to_reclaim += max(high_wmark_pages(zone), SWAP_CLUSTER_MAX);
	}

	/*
	 * Historically care was taken to put equal pressure on all zones but
	 * now pressure is applied based on node LRU order.
	 */
	shrink_node(pgdat, sc);

nr_to_reclaim += high_wmark_pages(zone) 这一行就是 kswapd 的行为定义：它要把每个 zone 的空闲内存补到高水位。高水位通常远大于"分配所需"，所以 kswapd 一次回收的量往往比 direct reclaim 大得多——它是在"提前准备"。

4.5 wakeup_kswapd()：什么时候叫醒后台线程

mm/vmscan.c:4441-4484 wakeup_kswapd

void wakeup_kswapd(struct zone *zone, gfp_t gfp_flags, int order,
		   enum zone_type highest_zoneidx)
{
	pg_data_t *pgdat;
	enum zone_type curr_idx;

	if (!managed_zone(zone))
		return;

	if (!cpuset_zone_allowed(zone, gfp_flags))
		return;

	pgdat = zone->zone_pgdat;
	curr_idx = READ_ONCE(pgdat->kswapd_highest_zoneidx);

	if (curr_idx == MAX_NR_ZONES || curr_idx < highest_zoneidx)
		WRITE_ONCE(pgdat->kswapd_highest_zoneidx, highest_zoneidx);

	if (READ_ONCE(pgdat->kswapd_order) < order)
		WRITE_ONCE(pgdat->kswapd_order, order);

	if (!waitqueue_active(&pgdat->kswapd_wait))
		return;

	/* Hopeless node, leave it to direct reclaim if possible */
	if (pgdat->kswapd_failures >= MAX_RECLAIM_RETRIES ||
	    (pgdat_balanced(pgdat, order, highest_zoneidx) &&
	     !pgdat_watermark_boosted(pgdat, highest_zoneidx))) {
		/*
		 * There may be plenty of free memory available, but it's too
		 * fragmented for high-order allocations.  Wake up kcompactd
		 * and rely on compaction_suitable() to determine if it's
		 * needed.  If it fails, it will defer subsequent attempts to
		 * ratelimit its work.
		 */
		if (!(gfp_flags & __GFP_DIRECT_RECLAIM))
			wakeup_kcompactd(pgdat, order, highest_zoneidx);
		return;
	}

	trace_mm_vmscan_wakeup_kswapd(pgdat->node_id, highest_zoneidx, order,
				      gfp_flags);
	wake_up_interruptible(&pgdat->kswapd_wait);
}

这个函数由页分配器在慢路径上调用。三种情况会不叫 kswapd：① kswapd 已经醒着（waitqueue_active 为假，说明它正在干活）；② 这个节点已经"没救了"（kswapd_failures 太多次失败），那就交给 direct reclaim 硬碰硬；③ 节点其实已经平衡了（pgdat_balanced() 检查水位线是否已达标）——此时可能真正的问题是碎片而非内存不足，所以转去唤醒 kcompactd 做内存整理。

4.6 try_to_free_pages()：直接回收的入口

mm/vmscan.c:3652-3693 try_to_free_pages

unsigned long try_to_free_pages(struct zonelist *zonelist, int order,
				gfp_t gfp_mask, nodemask_t *nodemask)
{
	unsigned long nr_reclaimed;
	struct scan_control sc = {
		.nr_to_reclaim = SWAP_CLUSTER_MAX,
		.gfp_mask = current_gfp_context(gfp_mask),
		.reclaim_idx = gfp_zone(gfp_mask),
		.order = order,
		.nodemask = nodemask,
		.priority = DEF_PRIORITY,
		.may_writepage = !laptop_mode,
		.may_unmap = 1,
		.may_swap = 1,
	};

	/*
	 * scan_control uses s8 fields for order, priority, and reclaim_idx.
	 * Confirm they are large enough for max values.
	 */
	BUILD_BUG_ON(MAX_ORDER > S8_MAX);
	BUILD_BUG_ON(DEF_PRIORITY > S8_MAX);
	BUILD_BUG_ON(MAX_NR_ZONES > S8_MAX);

	/*
	 * Do not enter reclaim if fatal signal was delivered while throttled.
	 * 1 is returned so that the page allocator does not OOM kill at this
	 * point.
	 */
	if (throttle_direct_reclaim(sc.gfp_mask, zonelist, nodemask))
		return 1;

	set_task_reclaim_state(current, &sc.reclaim_state);
	trace_mm_vmscan_direct_reclaim_begin(order, sc.gfp_mask);

	nr_reclaimed = do_try_to_free_pages(zonelist, &sc);

	trace_mm_vmscan_direct_reclaim_end(nr_reclaimed);
	set_task_reclaim_state(current, NULL);

	return nr_reclaimed;
}

scan_control sc 这个初始化块就是"回收策略面板"：may_unmap = 1（可以丢弃文件页）、may_swap = 1（可以写 swap）、may_writepage = !laptop_mode（笔记本模式下不写 swap，避免磨损 SSD）、priority = DEF_PRIORITY（初始优先级 12）。throttle_direct_reclaim() 是直接的限流：如果这个进程被标记为"被 throttle 的"，直接返回，避免它占用太多 CPU 做回收。

4.7 oom_badness()：该杀谁

mm/oom_kill.c:201-239 oom_badness

long oom_badness(struct task_struct *p, unsigned long totalpages)
{
	long points;
	long adj;

	if (oom_unkillable_task(p))
		return LONG_MIN;

	p = find_lock_task_mm(p);
	if (!p)
		return LONG_MIN;

	/*
	 * Do not even consider tasks which are explicitly marked oom
	 * unkillable or have been already oom reaped or the are in
	 * the middle of vfork
	 */
	adj = (long)p->signal->oom_score_adj;
	if (adj == OOM_SCORE_ADJ_MIN ||
			test_bit(MMF_OOM_SKIP, &p->mm->flags) ||
			in_vfork(p)) {
		task_unlock(p);
		return LONG_MIN;
	}

	/*
	 * The baseline for the badness score is the proportion of RAM that each
	 * task's rss, pagetable and swap space use.
	 */
	points = get_mm_rss(p->mm) + get_mm_counter(p->mm, MM_SWAPENTS) +
		mm_pgtables_bytes(p->mm) / PAGE_SIZE;
	task_unlock(p);

	/* Normalize to oom_score_adj units */
	adj *= totalpages / 1000;
	points += adj;

	return points;
}

打分公式：分数 = RSS + swap 占用 + 页表页数 + oom_score_adj 调整量。三档保护：oom_unkillable_task()（内核线程等）、oom_score_adj == OOM_SCORE_ADJ_MIN（即 -1000，完全免疫）、MMF_OOM_SKIP（已被标记为 OOM 牺牲品）。最后 adj *= totalpages / 1000 把 oom_score_adj 归一化到"页数"的量纲，这样它才能和 RSS 直接相加。

调试技巧：cat /proc/[pid]/oom_score 平时就能看到该进程当前的分数；echo -500 > /proc/[pid]/oom_score_adj 可以降低某进程被杀的概率（值越低越安全），+1000 则让它优先被杀。

5. 动手验证

5.1 看回收统计：/proc/vmstat

$ grep -E "pgscan|pgsteal|pgrefill|pgactivate|pgdeactivate" /proc/vmstat
pgscan_kswapd 1234567
pgscan_direct 234567
pgscan_anon 987654
pgscan_file 913113
pgsteal_kswapd 1100000
pgsteal_direct 200000
pgsteal_anon 800000
pgsteal_file 921113
pgrefill 55000
pgactivate 1234567
pgdeactivate 432100

读法：

  • pgscan_* = 扫描掉的页数（内核检查过、认为可以回收的页）。
  • pgsteal_* = 真正回收掉的页数。
  • pgscan_kswapd / pgsteal_kswapd 来自后台线程；pgscan_direct / pgsteal_direct 来自直接回收。
  • 效率 = pgsteal / pgscan。这个比值越接近 1 越好；如果 pgscan 很大而 pgsteal 很小，说明扫了很多页但收不动（页被钉住了、或者 refault 太频繁）。
  • pgscan_direct 持续增长是危险信号——说明应用正在被直接回收拖慢。

做一次前后对比，回收活动就看得见：

$ grep pgscan_direct /proc/vmstat; free -m
$ sudo dd if=/dev/zero of=/tmp/big bs=1M count=2000 oflag=direct
$ grep -E "pgscan|pgsteal" /proc/vmstat; free -m

写 2 GB 文件会撑大页缓存，触发回收；pgscan_kswapd 会明显上涨，而 pgscan_direct 通常涨得不多（说明 kswapd 跟上了）。

5.2 看水位线：/proc/zoneinfo

$ cat /proc/zoneinfo | head -30
Node 0, zone      DMA
  pages free     1024
        min      45
        low      58
        high     72
  ...
  pagesets
  cpu: 0
              count: 0
              high: 0
              low: 0
              free: 12345

min/low/high 就是水位线（单位：页）。free 是当前空闲页数。你可以这样观察 kswapd 的行为：

$ watch -n 1 'grep -A5 "^Node 0, zone      DMA" /proc/zoneinfo'

当 free 跌到 low 以下，kswapd 会被唤醒开始回收，free 会回升到 high 附近——这就是"后台回收把水位补满"的直观证据。

5.3 看 LRU 链表长度

$ grep -E "^(active|inactive|unevictable)" /proc/vmstat

nr_inactive_anon 23456
nr_active_file 34567
nr_inactive_file 4567
nr_unevictable 123
nr_zone_unevictable 0
nr_zone_write_pending 0

nr_inactive_anon 和 nr_inactive_file 就是两条 inactive 链表的长度——它们是"待回收的库存"。如果 nr_inactive_file 长期为 0，说明文件页缓存全被访问成 active 了，这时一旦内存紧张就没有便宜的页可收。

5.4 实验：drop_caches 丢页缓存

$ free -m
              total        used        free      shared  buff/cache   available
Mem:          15887        3210        2456         312        10221        11500

$ sudo sync && sudo echo 1 > /proc/sys/vm/drop_caches
$ free -m
              total        used        free      shared  buff/cache   available
Mem:          15887        3210        12677         312            0        11500

echo 1 的含义是"只丢 dentry/inode 缓存和页缓存，不丢 swap"。对应的其他取值：

值含义
0什么都不做（默认）
1释放页缓存（page cache）和 dentry/inode 缓存
2额外释放 swap 里的缓存
31 + 2

预期输出：buff/cache 从 10 GB 掉到接近 0，free 相应增加，而 used 和 available 基本不变（因为 available 本来就把可回收的页缓存算进去了）。

做性能测试时常用这个来"清干净再跑"，避免前一次运行的文件缓存干扰结果。注意：必须先 sync，否则脏页还没落盘就被丢弃可能造成数据丢失（内核会写警告）。

5.5 实验：观察 OOM 评分

$ cat /proc/self/oom_score
$ cat /proc/self/oom_score_adj
0
$ sleep 1000 &
$ cat /proc/$(pgrep sleep | head -1)/oom_score
2
$ echo -1000 > /proc/$(pgrep sleep | head -1)/oom_score_adj
$ cat /proc/$(pgrep sleep | head -1)/oom_score
0

把 oom_score_adj 设为 -1000 后，该进程的 oom_score 变成 0，意味着 OOM 时它永远不会被选中。这是给关键进程（数据库、监控代理）上"免死金牌"的实用手段。

5.6 实验：制造 swap 压力

$ free -m
$ sudo fallocate -l 2G /swapfile
$ sudo chmod 600 /swapfile && sudo mkswap /swapfile && sudo swapon /swapfile
$ free -m
$ sudo sysctl vm.swappiness=100
$ # 然后跑一个吃内存的程序，观察 SwapUsed 上涨
$ cat /proc/meminfo | grep -E "SwapTotal|SwapFree|Active\(anon\)|Inactive\(anon\)"

把 swappiness 调高后，匿名页更容易被换出，SwapUsed 会上涨；同时 Active(anon) / Inactive(anon) 的分布也会变化。这能直观看出 swappiness 对回收行为的影响。

$ qemu-system-x86_64 -kernel bzImage -m 256 -append "console=ttyS0" -nographic

6. 自测

Q1. direct reclaim 和 kswapd 的区别是什么？什么时候会用到哪一种？direct reclaim 是申请内存的进程自己停下来做回收（同步、阻塞，把延迟直接打在用户态）；kswapd 是每 NUMA 节点一个的后台内核线程，按水位线提前回收。正常情况下 kswapd 会把空闲内存维持在 high 水位，应用不该撞上 direct reclaim。只有当分配速度太快、kswapd 跟不上（比如突发大额分配、或者高阶分配需要连续大块内存）时，才会退化成 direct reclaim。生产环境里 pgscan_direct 持续增长就是"应用正在被回收拖慢"的信号。
Q2. 为什么回收优先从 inactive 链表开始，而不是 active？因为 active 表示"最近还在被访问"，收走它几乎必然导致马上 refault（重新从磁盘读回来），白折腾。inactive 里的页已经一段时间没被碰过，收走的概率高、代价低。另外新分配的页先进 inactive、第二次访问才升到 active，就是为了避免"刚分配的页"因为一次访问就被当成热页保护起来。不过内核并不禁止回收 active——只是要先做"降级"（deactivate），而且优先级更低。
Q3. swappiness=0 是不是就等于"完全不换出匿名页"？不是。0 表示"几乎不主动换出匿名页"，但 get_scan_count() 的公式里 file 那边的系数是 200 - swappiness，源码注释明确说：即使 swappiness=0，也仍然保留大约三分之一的压力给 file 链表，目的是保证匿名页最终仍能被回收（否则一旦文件页也不够，系统会直接 OOM 而没有任何渐进过程）。所以 swappiness=0 是"强烈倾向不换出"，不是"绝对不换出"。
Q4. pgscan 很大但 pgsteal 很小，说明什么？说明回收效率低：内核扫描了很多页，但真正能收走的很少。常见原因有：① 页面被 mlock 或被引用固定，属于 unevictable；② 页正在被写（脏页回收要等写回）；③ refault 过于频繁——刚收走的页马上又被访问，说明选错了回收对象，或者工作集已经超过了物理内存能承载的规模（这时候要加内存或减工作集，调参数没用）。
Q5. 为什么 Linux 5.10 的 LRU 只有四条链表？新内核不是有 MGLRU 吗？Linux 5.10 只有经典的 active/inactive × anon/file 四条链表（加上 unevictable），用简单的时钟近似算法维护。MGLRU（Multi-Generation LRU）是 6.1 才合入主线的改进方案，它用"代际（generation）"来区分"高频访问的页"和"刚被换出又换入的页"，在负载不均衡时表现更好。本仓库是 5.10，源码里没有 lru_gen、MGLRU 这些符号，读到新内核文章里的 MGLRU 时不要对号入座。
