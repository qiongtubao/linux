🗄️ Page Cache：文件内容的页缓存

把读过的文件页留在内存里，让第二次读盘变成一次内存拷贝 · 预计阅读 10 分钟

1. 它在解决什么问题

图书馆的书在几十米外的书库，阅览室就在手边。每次查一句话都跑去书库取书，一天走断腿。聪明的做法是把刚翻过的书页复印一份留在阅览室，下次直接看，只有第一次要跑一趟。Linux 的 page cache（页缓存）就是这间阅览室：内存是复印夹，磁盘是书库。

没有页缓存，read() 每次都发磁盘 IO；程序 A 刚读过 /etc/passwd，程序 B 再读还得再读盘。有了页缓存，文件内容按 4KB 一页缓存在内存，以“inode + 页号”为键；命中就 memcpy 到用户缓冲区，未命中才分配页、读盘、入缓存。第二次读同一文件几乎纯内存操作，这就是“系统越跑越快”的原因。

写也如此：延迟写把修改只写进页缓存并标 dirty，write() 立刻返回；回写线程再批量刷盘，磁盘因此能做顺序合并。代价是掉电可能丢最近几秒数据——fsync() 就是“马上送去书库装订”。

2. 核心名词

术语英文一句话解释
页缓存page cache内存中缓存“文件内容页”的区域，按 inode + 页偏移索引。
地址空间address_space一个 inode 的页缓存容器；每个 inode 内嵌一个 i_data。
XArrayXArray5.10 中替代 radix tree 的稀疏数组，按页索引直接查页，带标记。
页索引index / pgoff_t文件内页号，等于 偏移 >> 12。
脏页dirty page内容比磁盘新、尚未写回的缓存页，被 XArray 的 DIRTY 标记标出。
回写writeback把脏页写回磁盘，由 kworker 与脏页阈值节流。
预读readahead读到某页时顺带把后几页也读进缓存，随机 IO 变顺序 IO。
缺页page fault访问 mmap 的文件页但页表无映射时触发，由 filemap_fault 填页。

3. 整体结构

struct inode                     struct page
 ├ i_mapping ─┐                  ┌ index = 文件内页号
 └ i_data ────┴─► address_space  │ mapping ─► address_space
                   ├ i_pages: XArray ─► [0][1]...[N]  ← 标记 DIRTY/WRITEBACK
                   ├ nrpages
                   ├ writeback_index
                   └ a_ops ─► readpage / writepages / write_begin / direct_IO

写路径：write() → generic_perform_write 调 a_ops->write_begin 拿到一个锁住的缓存页 → 从用户空间拷贝 → write_end 标记 dirty → 返回。页内容在内存，磁盘位置还是旧的，等回写。

读路径：read() → generic_file_buffered_read 用 find_get_page 查 XArray → 命中且 PageUptodate 就拷贝；否则分配页、调 a_ops->readpage 读盘、add_to_page_cache_lru 入缓存。mmap 缺页走 filemap_fault，与 read 共享同一份页缓存，所以 read() 一定读到 mmap 写过的内容。

4. 源码走读

4.1 address_space 与 XArray

include/linux/fs.h:451-466 struct address_space

struct address_space {
	struct inode		*host;
	struct xarray		i_pages;      /* 页缓存本体：index → struct page */
	gfp_t			gfp_mask;
	struct rb_root_cached	i_mmap;    /* 映射本文件的所有 VMA */
	struct rw_semaphore	i_mmap_rwsem;
	unsigned long		nrpages;
	pgoff_t			writeback_index;   /* 循环回写的起点 */
	const struct address_space_operations *a_ops;
	unsigned long		flags;
};

5.10 已把老式 radix tree 换成 XArray：i_pages 是可稀疏的“大数组”，用页索引直接定位，空槽不占内存。标记位 PAGECACHE_TAG_DIRTY/WRITEBACK（定义为 XA_MARK_0/1）让“找出所有脏页”不必遍历全树。a_ops 是页级操作表，ext4 的 writepages/readpage/write_begin 都在里面。

4.2 找页或造页：pagecache_get_page

mm/filemap.c:1842-1872 pagecache_get_page（节选）

	struct page *page;
repeat:
	page = find_get_entry(mapping, index);   /* 查 XArray，取引用 */
	if (xa_is_value(page))                   /* swap 影子条目视为没有 */
		page = NULL;
	if (!page)
		goto no_page;
	if (fgp_flags & FGP_LOCK) {
		if (fgp_flags & FGP_NOWAIT) {
			if (!trylock_page(page)) { put_page(page); return NULL; }
		} else
			lock_page(page);
		if (unlikely(page->mapping != mapping)) {   /* 期间被截断 */
			unlock_page(page);  put_page(page);  goto repeat;
		}
	}
no_page:  /* FGP_CREAT 时在此分配页并 add_to_page_cache_lru */

这是页缓存的统一取页口。FGP_LOCK 保证调用者拿到独占页（读写互斥）；mapping != mapping 是截断竞争检查，页被截断后不能再使用；FGP_CREAT 时走“分配 + 插入 + 挂 LRU”慢路径。

4.3 新页入缓存：add_to_page_cache_lru

mm/filemap.c:932-949 add_to_page_cache_lru

	__SetPageLocked(page);                 /* 先锁页再入表 */
	ret = __add_to_page_cache_locked(page, mapping, offset, gfp_mask, &shadow);
	if (unlikely(ret))
		__ClearPageLocked(page);
	else {
		WARN_ON_ONCE(PageActive(page));
		if (!(gfp_mask & __GFP_WRITE) && shadow)
			workingset_refault(page, shadow);   /* 统计“刚回收又读回” */
		lru_cache_add(page);               /* 加入 LRU，可被回收 */
	}

顺序不可乱：锁页 → 插入 XArray。插入时若发现同 index 已有页就返回 -EEXIST，调用方丢弃自己这页改用已有的。lru_cache_add 把页挂上 LRU，让 kswapd 在内存紧张时能找到并回收——缓存页可丢弃，但脏页被丢弃前必须先回写。

4.4 缓冲读与读盘

mm/filemap.c:2613-2638 generic_file_read_iter（开头）

	size_t count = iov_iter_count(iter);
	ssize_t retval = 0;
	if (!count)
		goto out;                 /* 0 字节读直接返回 */
	if (iocb->ki_flags & IOCB_DIRECT) {   /* O_DIRECT 绕过缓存 */
		// ... 省略：范围检查、filemap_write_and_wait_range、
		//     mapping->a_ops->direct_IO 与迭代器回退
	}
	retval = generic_file_buffered_read(iocb, iter, retval);
out:
	return retval;

缓冲读的核心循环按页推进；未命中时：

mm/filemap.c:2492-2503 generic_file_buffered_read 内读盘

		ClearPageError(page);
		/* Start the actual read. The read will unlock the page. */
		error = mapping->a_ops->readpage(filp, page);
		if (unlikely(error)) {
			if (error == AOP_TRUNCATED_PAGE) {
				put_page(page);  error = 0;  goto find_page;  /* 被截断，重查 */
			}
			goto readpage_error;
		}
		// ... 省略 lock_page_killable 等待 IO、检查 PageUptodate

注释“read will unlock the page”很关键：readpage 提交 IO 后返回，IO 完成时由 bio 回调把页标 Uptodate 并解锁；读线程在 lock_page_killable 上等。于是“一个页只读一次盘，其他线程等锁”成立。

4.5 缓冲写：write_begin / write_end

mm/filemap.c:3417-3446 generic_perform_write（节选）

	do {
		unsigned long offset = (pos & (PAGE_SIZE - 1));
		unsigned long bytes = min_t(unsigned long, PAGE_SIZE - offset,
						iov_iter_count(i));
again:
		if (unlikely(iov_iter_fault_in_readable(i, bytes))) {
			status = -EFAULT;  break;      /* 用户页不可读，提前失败 */
		}
		if (fatal_signal_pending(current)) {
			status = -EINTR;  break;
		}
		status = a_ops->write_begin(file, mapping, pos, bytes, flags,
						&page, &fsdata);   /* 拿到锁住的页 */
		if (unlikely(status < 0))
			break;
		// ... 省略：copy_from_user、write_end 标 dirty、更新 pos/written
	} while (iov_iter_count(i));

写以页为单位循环。先 fault_in_readable 把用户页触进来，避免持页锁时再缺页死锁；write_begin 负责定位缓存页并可能预留磁盘块（ext4 延迟分配的入口就在这里）；write_end 在拷贝后标 dirty 并解锁。

4.6 缺页填页：filemap_fault

mm/filemap.c:2826-2862 filemap_fault（节选）

	pgoff_t offset = vmf->pgoff;      /* 缺页的文件内页号 */
	max_off = DIV_ROUND_UP(i_size_read(inode), PAGE_SIZE);
	if (unlikely(offset >= max_off))
		return VM_FAULT_SIGBUS;       /* 访问越界 → SIGBUS */
	page = find_get_page(mapping, offset);
	if (likely(page) && !(vmf->flags & FAULT_FLAG_TRIED)) {
		fpin = do_async_mmap_readahead(vmf, page);
	} else if (!page) {
		count_vm_event(PGMAJFAULT);   /* 统计“主缺页” */
		ret = VM_FAULT_MAJOR;
		fpin = do_sync_mmap_readahead(vmf);
retry_find:
		page = pagecache_get_page(mapping, offset,
					  FGP_CREAT|FGP_FOR_MMAP, vmf->gfp_mask);
		// ... 省略 lock_page、截断重查、!PageUptodate 时读盘

缺页与 read() 用同一份缓存：命中只建 PTE（次要缺页，极廉价），未命中才造页并预读。这解释了为什么 cat 读过的文件 mmap 再访问几乎零 IO。

4.7 脏页、回写与 meminfo

脏页会被回写线程扫到：wb_workfn → do_writepages → mapping->a_ops->writepages（ext4 是 ext4_writepages）。/proc/meminfo 的数字来自全局页状态：

fs/proc/meminfo.c:62,89-91 页面计数出口

	show_val_kb(m, "Cached:         ", cached);
	...
	show_val_kb(m, "Dirty:          ",
		    global_node_page_state(NR_FILE_DIRTY));
	show_val_kb(m, "Writeback:      ",
		    global_node_page_state(NR_WRITEBACK));

Cached 约等于 page cache + tmpfs；Dirty 是等待回写的字节数；Writeback 是正在 IO 中的字节数。回写节流参数：/proc/sys/vm/dirty_background_ratio（达到后唤醒后台回写）、dirty_ratio（达到后写进程自身被阻塞）、dirty_expire_centisecs（脏页最久多久必须回写）。

5. 动手验证

实验一：缓存增长与丢弃。

grep -E 'Cached|Dirty|Writeback' /proc/meminfo
cat /usr/bin/* > /dev/null 2>&1 || true      # 制造大量冷读
grep Cached /proc/meminfo                     # 明显上升
sync; echo 3 > /proc/sys/vm/drop_caches       # 需 root，实验环境
grep Cached /proc/meminfo                     # 明显下降

echo 1 只丢页缓存，2 丢 dentry/inode 缓存，3 都丢。清空后重读同一文件变慢，说明之前命中缓存。

实验二：脏页与回写。

dd if=/dev/zero of=/tmp/dirty.bin bs=1M count=256
watch -n1 'grep -E "Dirty|Writeback" /proc/meminfo'

dd 结束瞬间 Dirty 可达数百 MB；数秒内先升 Writeback 再回落。加 conv=fsync 则 dd 返回时已是 Dirty≈0。

实验三：命中率。/usr/bin/time -v cat bigfile 比较首次与再次；或对比 /proc/diskstats 前后 sectors 读——第二次读同一文件，磁盘读计数基本不变。

6. 自测

Q1. 5.10 里页缓存用什么索引？为什么？XArray（i_pages）。它以页索引直接定位、可稀疏、支持 DIRTY/WRITEBACK 标记批量查找，比旧 radix tree 省锁。
Q2. add_to_page_cache_lru 为什么先锁页再插入？插入后其他线程可能立即查到并使用；不锁会读到半初始化页。插入失败（已有同 index 页）则丢弃自己这页。
Q3. read() 命中与未命中分别做什么？命中且 PageUptodate：直接拷贝；未命中：分配页、a_ops->readpage 读盘、入缓存，等锁后拷贝。
Q4. 脏页不 fsync 会怎样？留在缓存数秒后由后台回写；此时掉电会丢这部分修改。fsync 强制立即写回并等 IO 完成。
Q5. mmap 与 read() 为什么看到同一份数据？两者都以 address_space->i_pages 为唯一数据源：read 拷贝页内容，缺页把同一页映射进页表。
