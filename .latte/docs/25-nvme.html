⚡ NVMe：PCIe 上的块设备驱动

绕过 SATA 控制器，让 SSD 直接对着一圈环形队列发命令 · 预计阅读 10 分钟

1. 它在解决什么问题

老式 SATA 硬盘的协议是给“磁头 + 盘片”设计的：一次只能挂一个命令、一次搬一小段数据，还得由主板上的 AHCI 控制器转手。SSD 没有磁头，随机读只要几微秒，却被这条“单车道、带红绿灯”的路卡死。于是业界把 SSD 直接挂上 PCIe 总线，并新写了一套协议——NVMe（Non-Volatile Memory Express）。

它的思路像快餐店的点餐台：柜台前有多个窗口（队列），每个窗口各排一条队；你把订单小票放进窗口的传送带（提交队列 SQ），按一下铃（doorbell），后厨做完把成品放到取餐口（完成队列 CQ），再按一下铃通知你取走。窗口有几十个、每条队能排几百单，所以成千上万个 IO 能真的并行。

对内核来说，NVMe 盘就是一个标准的块设备：上面有 request_queue、hctx、IO 调度器，和 SATA 盘一样被 mkfs、被挂载。驱动的任务只是把 request 翻译成 NVMe 命令、拷进环形队列、敲 doorbell、等中断。这一篇看的就是这台翻译机。

2. 核心名词

术语英文一句话解释
NVMeNon-Volatile Memory Express为闪存设计的 PCIe 上的命令协议，多队列、低延迟。
提交队列SQ (Submission Queue)主机内存中的环形数组，放 64 字节命令；控制器从这里取任务。
完成队列CQ (Completion Queue)环形的 16 字节完成条目，控制器写、主机读。
门铃doorbell设备 BAR 里的寄存器，主机写“尾指针”告诉控制器有新命令。
命令 capsulecommand64 字节固定格式：opcode、命令号、命名空间、数据指针、起始 LBA、长度。
PRPPhysical Region Page命令里的数据指针，指向内存页；跨页时用 PRP list 串成链。
命名空间namespace / nsid控制器里的一块逻辑存储，对应一个 /dev/nvme0n1。
管理队列admin queue队列 0，专门跑 identify、创建/删除 IO 队列等控制命令。

3. 整体结构

先看一条命令如何从主机内存走到控制器，再回来看完成：

主机内存（驱动分配的一圈页）                 控制器（BAR 寄存器）
 SQ ring:  [ ... | cmd5 | cmd6 | 空 | 空 ]     SQ0 Tail  ← writel(sq_tail)
                ▲                                    │
                │ 驱动 memcpy 命令                   ▼
                └────────────── doorbell ──►  取走命令、DMA 读数据
 CQ ring:  [ ... | cqe3 | 空 | 空 ]
                ▲                                    │
                │ 驱动读 cqe、处理完                │ 写完 cqe
                └──────── 写 CQ0 Head ──► doorbell  ◄┘
                       (告诉控制器“这条我取走了”)
PCIe BAR0 布局: [ SQ0 Tail ][ CQ0 Head ][ SQ1 Tail ][ CQ1 Head ] ...

command capsule（64 字节）关键字段：

0  opcode      如 0x02 = Read, 0x01 = Write
1  flags
2  command_id  等于块层的 request tag，用来对上完成项
4  nsid        命名空间号（哪块盘）
8  metadata 指针 / 16  dptr: PRP1, PRP2（数据放在哪）
24 slba        起始逻辑块地址（LBA）
32 length      传输扇区数减一
34 control     含 FUA 等标志

队列深度由控制器支持的上限和驱动配置共同决定（常见 1024）。每个 IO 队列有独立的中断（MSI-X），所以 CPU 0 提交的 IO 完成时大概率回到 CPU 0，缓存亲和性好。

整个驱动的生命周期：probe（PCI 匹配、映射 BAR、建 admin 队列、identify 控制器）→ setup IO queues（按 CPU 数创建 IO 队列）→ alloc namespace（每块逻辑盘建 gendisk 与 request_queue）→ 运行时 nvme_queue_rq 循环 → 移除/reset 时销毁。

4. 源码走读

4.1 探测：nvme_probe

drivers/nvme/host/pci.c:2946-2985 nvme_probe（节选）

static int nvme_probe(struct pci_dev *pdev, const struct pci_device_id *id)
{
	int node, result = -ENOMEM;
	struct nvme_dev *dev;
	unsigned long quirks = id->driver_data;
	// ...
	node = dev_to_node(&pdev->dev);
	if (node == NUMA_NO_NODE)
		set_dev_node(&pdev->dev, first_memory_node);

	dev = kzalloc_node(sizeof(*dev), GFP_KERNEL, node);
	if (!dev)
		return -ENOMEM;

	dev->nr_write_queues = write_queues;
	dev->nr_poll_queues = poll_queues;
	dev->nr_allocated_queues = nvme_max_io_queues(dev) + 1;
	dev->queues = kcalloc_node(dev->nr_allocated_queues,
			sizeof(struct nvme_queue), GFP_KERNEL, node);
	// ...
	pci_set_drvdata(pdev, dev);
	result = nvme_dev_map(dev);          /* 映射 BAR0，拿到 doorbell */
	// ...
	result = nvme_setup_prp_pools(dev);  /* 预分配 PRP list 池 */
	// ... 省略 quirk 检测与中断向量申请
	nvme_reset_ctrl(&dev->ctrl);         /* 异步 reset：建队列、identify */
	async_schedule(nvme_async_probe, dev);
	return 0;

nr_allocated_queues 比 IO 队列多 1，那 1 个就是 admin 队列。nvme_dev_map 用 pci_iomap 把 BAR0 映射进内核虚拟地址，之后写 doorbell 就是 writel 到这段地址。真正的硬件初始化（复位、建队列、identify 控制器与命名空间）在 nvme_reset_ctrl 的工作线程里做，probe 本身快速返回。

4.2 多队列：nvme_setup_io_queues

drivers/nvme/host/pci.c:2208-2237 nvme_setup_io_queues（节选）

static int nvme_setup_io_queues(struct nvme_dev *dev)
{
	struct nvme_queue *adminq = &dev->queues[0];
	struct pci_dev *pdev = to_pci_dev(dev->dev);
	unsigned int nr_io_queues;
	// ...
	dev->nr_write_queues = write_queues;
	dev->nr_poll_queues = poll_queues;

	if (dev->ctrl.quirks & NVME_QUIRK_SHARED_TAGS)
		nr_io_queues = 1;
	else
		nr_io_queues = min(nvme_max_io_queues(dev),
				   dev->nr_allocated_queues - 1);

	result = nvme_set_queue_count(&dev->ctrl, &nr_io_queues);
	if (result < 0)
		return result;
	if (nr_io_queues == 0)
		return 0;

	clear_bit(NVMEQ_ENABLED, &adminq->flags);
	// ... 省略 CMB（控制器内存）优化与 BAR 重映射
	// 之后为每个队列分配 SQ/CQ 内存并向控制器发 Create CQ/SQ 命令

先算“想要几个队列”（nvme_max_io_queues 取 CPU 数与配置上限的较小值），再让控制器确认实际能给几个（nvme_set_queue_count，走 admin 命令 Set Features）。NVME_QUIRK_SHARED_TAGS 是 Apple 硬件的一个怪癖：admin 与 IO 共用 tag，只能用一个 IO 队列。clear_bit(NVMEQ_ENABLED) 是先把 admin 队列标为不可用，避免重建期间有新请求塞进来。

队列创建完后，块层的 tagset 由 nvme_pci_map_queues（:443）按 PCIe 的 NUMA 亲和关系映射：blk_mq_pci_map_queues(map, pdev, offset)，让提交 IO 的 CPU 和它的 PCIe 根节点在同一个 NUMA 域。轮询模式（poll_queues）没有中断亲和，退回通用 blk_mq_map_queues。

4.3 命名空间变成块设备：nvme_alloc_ns

drivers/nvme/host/core.c:3800-3845 nvme_alloc_ns（节选）

static void nvme_alloc_ns(struct nvme_ctrl *ctrl, unsigned nsid,
		struct nvme_ns_ids *ids)
{
	struct nvme_ns *ns;
	struct gendisk *disk;
	struct nvme_id_ns *id;
	// ...
	if (nvme_identify_ns(ctrl, nsid, ids, &id))
		return;

	ns = kzalloc_node(sizeof(*ns), GFP_KERNEL, node);
	ns->queue = blk_mq_init_queue(ctrl->tagset);   /* 共享控制器 tagset */
	if (IS_ERR(ns->queue))
		goto out_free_ns;

	blk_queue_flag_set(QUEUE_FLAG_NONROT, ns->queue);  /* 非旋转设备 */
	ns->queue->queuedata = ns;        /* 驱动从 hctx->queue 反查 ns */
	ns->ctrl = ctrl;
	// ...
	nvme_set_disk_name(disk_name, ns, ctrl, &flags);
	disk = alloc_disk_node(0, node);
	// ...
	disk->fops = &nvme_fops;
	disk->private_data = ns;
	disk->queue = ns->queue;
	memcpy(disk->disk_name, disk_name, DISK_NAME_LEN);
	ns->disk = disk;
	// ... 省略 update_ns_info 与 LightNVM 分支
	device_add_disk(ctrl->device, ns->disk, nvme_ns_id_attr_groups);

nvme_identify_ns 发管理命令拿命名空间参数（容量、扇区大小、LBA 格式）。每个命名空间建一个 request_queue，但共享控制器级的 tagset（ctrl->tagset）——tag 是硬件队列里的槽位，同一控制器的所有盘共用同一批队列。QUEUE_FLAG_NONROT 让块层知道这是非旋转介质，影响合并与调度器选择。device_add_disk 之后 /dev/nvme0n1 出现，udev 建 /dev 节点，文件系统就能挂载了。

4.4 提交一条请求：nvme_queue_rq

drivers/nvme/host/pci.c:903-950 nvme_queue_rq（节选）

static blk_status_t nvme_queue_rq(struct blk_mq_hw_ctx *hctx,
			 const struct blk_mq_queue_data *bd)
{
	struct nvme_ns *ns = hctx->queue->queuedata;  /* 名字空间 */
	struct nvme_queue *nvmeq = hctx->driver_data;  /* 硬件队列 */
	struct nvme_dev *dev = nvmeq->dev;
	struct request *req = bd->rq;
	struct nvme_iod *iod = blk_mq_rq_to_pdu(req);  /* 请求私有区 */
	struct nvme_command cmnd;
	blk_status_t ret;

	iod->aborted = 0;  iod->npages = -1;  iod->nents = 0;

	if (unlikely(!test_bit(NVMEQ_ENABLED, &nvmeq->flags)))
		return BLK_STS_IOERR;             /* 队列已停用 */

	ret = nvme_setup_cmd(ns, req, &cmnd);  /* request → NVMe 命令 */
	if (ret)
		return ret;

	if (blk_rq_nr_phys_segments(req)) {
		ret = nvme_map_data(dev, req, &cmnd);   /* DMA 映射 + 填 PRP */
		if (ret)
			goto out_free_cmd;
	}

	blk_mq_start_request(req);          /* 启动超时计时 */
	nvme_submit_cmd(nvmeq, &cmnd, bd->last);   /* 拷进 SQ + doorbell */
	return BLK_STS_OK;
out_free_cmd:
	nvme_cleanup_cmd(req);
	return ret;

这是驱动的核心回调，由块层在 hctx 派发时调用。顺序：构造命令（nvme_setup_cmd 按 req_op 分发到读/写/flush/discard 等）、映射数据（nvme_map_data 把 request 的页做 DMA 映射，填进命令的 PRP1/PRP2 或 PRP list）、启动请求（开始超时计时）、提交（拷命令、敲铃）。bd->last 是“这批的最后一个”，用于决定是否立刻敲铃。

drivers/nvme/host/core.c:808-860 nvme_setup_cmd（节选）

	memset(cmd, 0, sizeof(*cmd));
	switch (req_op(req)) {
	case REQ_OP_FLUSH:
		nvme_setup_flush(ns, cmd);
		break;
	case REQ_OP_WRITE_ZEROES:
		ret = nvme_setup_write_zeroes(ns, req, cmd);
		break;
	case REQ_OP_DISCARD:
		ret = nvme_setup_discard(ns, req, cmd);
		break;
	case REQ_OP_READ:
		ret = nvme_setup_rw(ns, req, cmd, nvme_cmd_read);
		break;

		break;
	// ... 省略 zone append / 直通等

command_id = req->tag 极重要：完成队列条目只回传这个 16 位 id，驱动靠它找回是哪个 request 完成了。命令结构在 include/linux/nvme.h:797（struct nvme_rw_command）：slba 起始 LBA、length 扇区数减一、dptr 数据指针。

4.5 拷命令与敲铃：nvme_submit_cmd

drivers/nvme/host/pci.c:505-518 nvme_submit_cmd

static void nvme_submit_cmd(struct nvme_queue *nvmeq, struct nvme_command *cmd,
			    bool write_sq)
{
	spin_lock(&nvmeq->sq_lock);   /* 保护 SQ 尾指针 */
	memcpy(nvmeq->sq_cmds + (nvmeq->sq_tail << nvmeq->sqes),
	       cmd, sizeof(*cmd));
	if (++nvmeq->sq_tail == nvmeq->q_depth)
		nvmeq->sq_tail = 0;       /* 环形回绕 */
	nvme_write_sq_db(nvmeq, write_sq);   /* 写 SQ Tail 门铃 */
	spin_unlock(&nvmeq->sq_lock);
}

sq_cmds 是驱动分配的一段连续内存，控制器通过 SQ0 Base Address 寄存器也能看到它（同一块物理内存，DMA 一致性）。sq_tail << sqes 计算槽位字节偏移（sqes 是命令大小的 log2，通常 6 → 64 字节）。写完修改 tail 并回绕；nvme_write_sq_db 决定是否立即敲铃：若不是本批最后一个，且下一个位置不会回绕，就跳过门铃——批量提交时只敲一次，减少 MMIO 开销。

4.6 完成：nvme_process_cq

drivers/nvme/host/pci.c:1073-1094 nvme_process_cq（节选）

static inline int nvme_process_cq(struct nvme_queue *nvmeq)
{
	int found = 0;

	while (nvme_cqe_pending(nvmeq)) {   /* 用 phase bit 判断新条目 */
		found++;
		dma_rmb();                     /* 保证读到完整 CQE */
		nvme_handle_cqe(nvmeq, nvmeq->cq_head);
		nvme_update_cq_head(nvmeq);    /* head++，回绕时翻转 phase */
	}

	if (found)
		nvme_ring_cq_doorbell(nvmeq);  /* 告诉控制器已消费 */
	return found;
}

中断处理里循环取完成项，直到 nvme_cqe_pending 为假。判断“有没有新条目”靠 phase bit：CQ 内存初始清零，控制器写条目时把 status 的最低位设为当前 phase；主机回绕一圈后翻转自己的 phase 期望值，于是“清零的旧条目”不会被误认成新的——不需要额外计数器。dma_rmb() 防止读到半个 CQE。nvme_handle_cqe 里 blk_mq_complete_request(req) 完成请求，最终唤醒等 IO 的线程。

5. 动手验证

看设备与驱动。

lspci | grep -i nvme                 # 形如 Non-Volatile memory controller
lspci -vv -s <bus:dev.fn> | grep -E 'LnkCap|LnkSta|MSI-X'
nvme list                            # 需 nvme-cli：列出 /dev/nvme0n1 容量/型号
nvme id-ctrl /dev/nvme0 | head -20   # 控制器 identify：型号、固件、队列上限
nvme id-ns /dev/nvme0n1 | head -20   # 命名空间：容量、LBA 格式

LnkSta 显示当前 PCIe 速率（如 8GT/s x4）；MSI-X: Enable+ Count=N 的 N 就对应队列数（每队列一个中断向量）。nvme id-ctrl 里的 sqes/cqes 是命令/完成项大小，maxcmd 是队列深度上限。

看内核侧的队列。

ls /sys/block/nvme0n1/mq/              # hctx 目录
cat /sys/block/nvme0n1/mq/0/cpu_list    # 该队列服务的 CPU
cat /sys/block/nvme0n1/queue/scheduler  # 通常 [none]
cat /sys/block/nvme0n1/queue/nr_requests
grep nvme /proc/interrupts | head -4

mq/ 下的每个目录就是一个硬件队列，cpu_list 是 blk_mq_pci_map_queues 的结果；/proc/interrupts 里每个 nvme0qN 一行，计数随 IO 增长，说明该队列在干活。

没有 NVMe 硬件？用 qemu 造一块。

qemu-system-x86_64 -m 2G -smp 4 \
  -kernel arch/x86/boot/bzImage -append "console=ttyS0" \
  -drive file=rootfs.img,format=raw,if=virtio \
  -device nvme,serial=deadbeef,drive=drv0 \
  -drive file=nvme.img,format=raw,if=none,id=drv0 \
  -nographic

启动后 lspci 能看到 NVMe 控制器，ls /sys/block/ 出现 nvme0n1；nvme id-ctrl /dev/nvme0 可读取 qemu 模拟的 identify 数据。对 /dev/nvme0n1 做 mkfs.ext4、挂载、读写，即可复现本篇所有路径。

6. 自测

Q1. NVMe 为什么比 SATA 快得多？它直接走 PCIe，且协议原生支持多队列（每 CPU 一条或多条 SQ/CQ），命令只有 64 字节、路径短；SATA/AHCI 只有一条队列且经控制器转手。
Q2. SQ 和 CQ 分别由谁写？SQ 由主机驱动写命令、写 SQ Tail 门铃通知控制器；CQ 由控制器写完成条目，主机读完后写 CQ Head 门铃告知已消费。
Q3. 完成项怎么和 request 对上？NVMe 命令的 command_id 被设成 req->tag，CQE 回传该 id，驱动据此找回请求并完成它。
Q4. CQ 的 phase bit 有什么用？区分“控制器刚写入的新条目”和“回绕后残留的旧内容”，避免额外维护计数器，只需读到 status 最低位等于当前期望 phase。
Q5. nvme_alloc_ns 建的 request_queue 和控制器 tagset 什么关系？每命名空间一个 queue，但共享控制器级 tagset：队列与 hctx 都落到同一组硬件队列，tag 池也是同一批。
