🔌 字符设备：cdev、file_operations 与 ioctl

怎么把内核里的一段代码变成用户态能 open/read/write/ioctl 的「设备」 · 预计阅读 12 分钟

1. 它在解决什么问题

先想象一个银行大厅。每个窗口都贴着一块牌子：1 号窗口办存款，2 号窗口办取款。普通人并不知道窗口背后是谁在干活，他只需要走到窗口，递进去一张单子（请求），拿回一张回执（数据）。窗口编号就是「设备号」，窗口后面那套办事流程就是「驱动」。

字符设备（character device）就是内核里的这套「窗口」机制。它的关键特点是：窗口背后没有文件内容。普通文件（/etc/passwd）的字节躺在磁盘上，read() 就是从磁盘搬到内存；而字符设备更像一根管道或一个终端——你 open() 它拿到的不是一份数据，而是一条可以来回传话的通道。通道那头是什么、怎么解释传过去的东西，全由驱动自己决定：可以是内存（/dev/mem）、可以是串口（/dev/ttyS0）、可以是自定义硬件，也可以是内核里的一个计数器。

从操作系统视角看，内核要解决三个问题：

  • 寻址：用户态要有一个「路径」能指向设备（/dev/hello），内核要能把「这个路径」翻译成「设备号 major:minor」，再把设备号翻译成「一组函数指针」——也就是 struct file_operations；
  • 调用：用户态调 read()，VFS 要知道该转给哪个 file_operations 的 read 成员；
  • 传话：驱动要读写用户态传来的缓冲区，而用户指针是不可信的，必须用专门的安全拷贝接口。

本篇就把这三件事拆开：设备号怎么编码（major/minor）、cdev 怎么把设备号挂到函数表上、device_create() 怎么让 udev 在 /dev 下凭空造出节点、以及 copy_to_user() 到底在防什么。最后你会亲手写一个能编译、能加载、能读写的字符设备模块。

和块设备的区别：块设备（/dev/sda）以「块」为单位，走 page cache、请求队列、I/O 调度器那一整套复杂流水线；字符设备是「字节流」语义，读写直接进驱动回调，没有中间层。规则是：数据是线性的、没有随机寻址需求 → 字符设备；数据是块状、可随机寻址、要挂文件系统 → 块设备。

3.2 三个概念之间的关系

用「快递」再打一个比方：

概念类比作用
major:minor快递公司编号 + 运单号唯一定位一个字符设备；major 决定用哪套处理流程
struct cdev分拣中心的登记册登记「运单号 240:0 → 交给哪台分拣机（file_operations）」
struct file_operations分拣机（流水线）真正干活的函数指针：open/read/write/ioctl
class + device_create门口的告示牌 + 叫号系统把「设备存在」这件事告诉用户态，好让 udev 造出 /dev 节点

注意一个关键点：设备号和设备节点是两回事。内核内部只认 major:minor；/dev/hello 这个路径只是用户态的一个入口，udev 建节点时把它和 major:minor 绑定在一起。用户态 open("/dev/hello")，VFS 顺着 dentry 拿到 inode 里的 i_rdev（就是 240:0），再去 cdev_map 里查表。删掉 /dev/hello 这个节点，内核里的设备照样在，只是用户态再也找不到入口了（可以用 mknod 手工补一个）。

3.4 udev 是怎么知道要建节点的

内核在 device_create() 时做三件事：建 sysfs 目录、在目录里写一个叫 dev 的文件（内容是 "240:0"）、发一个 uevent。uevent 的内容形如：


ACTION=add
DEVPATH=/devices/platform/hello
SUBSYSTEM=hello
DEVNAME=hello
MAJOR=240
MINOR=0

udev（systemd 的那一半）监听 /sys/kernel/uevent，收到 ACTION=add 后查规则：SUBSYSTEM=hello 命中默认规则，就按 DEVNAME 在 /dev 下 mknod 出一个字符设备节点（主次设备号取自 MAJOR/MINOR），再按规则设权限。规则文件在 /usr/lib/udev/rules.d/ 下。

小知识：如果你在 /etc/udev/rules.d/ 里放一个文件 99-hello.rules，内容是 SUBSYSTEM=="hello", MODE="0666"，重新加载规则后 /dev/hello 的权限就会变成 666。这就是「不加 udev 规则就读写不了设备」的解法。

4. 源码走读

4.1 设备号：一个整数拆成两半

先看 major/minor 是怎么塞进一个 32 位整数的。dev_t 在 include/linux/types.h 里就是 typedef u32 __kernel_dev_t;。

include/linux/kdev_t.h:7-12

#define MINORBITS	20
#define MINORMASK	((1U << MINORBITS) - 1)

#define MAJOR(dev)	((unsigned int) ((dev) >> MINORBITS))
#define MINOR(dev)	((unsigned int) ((dev) & MINORMASK))
#define MKDEV(ma,mi)	(((ma) << MINORBITS) | (mi))
  • MINORBITS 20：低 20 位留给 minor（最多 1048576 个），剩下高 12 位留给 major（最多 4096 种驱动类型）。
  • MAJOR(dev) 是右移 20 位，把高 12 位取出来；MINOR(dev) 是 & MINORMASK，把低 20 位抠出来。
  • MKDEV(ma,mi) 是逆运算：major 左移 20 位后与 minor 或起来。

于是 MKDEV(240, 0) = 240 << 20 = 0x0F000000。你在 /proc/devices 里看到的「240 hello」和 /sys/class/hello/hello/dev 里的「240:0」，就是这两个数的十进制文本形式。

4.2 申请设备号

alloc_chrdev_region() 让内核自己挑一个空闲 major，你只指定起始 minor 和数量。

fs/char_dev.c:236-245 alloc_chrdev_region

int alloc_chrdev_region(dev_t *dev, unsigned baseminor, unsigned count,
			const char *name)
{
	struct char_device_struct *cd;
	cd = __register_chrdev_region(0, baseminor, count, name);
	if (IS_ERR(cd))
		return PTR_ERR(cd);
	*dev = MKDEV(cd->major, cd->baseminor);
	return 0;
}
  • 第一个参数 0 表示 major 由内核动态分配（register_chrdev_region() 传进来的则必须是你自己指定的具体 major）。
  • 返回的 *dev 是起始设备号；如果你申请了 4 个 minor，那么实际可用的是 dev 到 dev+3。
  • 失败时返回的是 ERR_PTR 形式的负错误码，所以必须用 IS_ERR() 判断。

它的表兄 register_chrdev_region(from, count, name) 用法几乎一样，区别是 major 必须自己指定，而且它要处理「一段范围跨了 major 边界」的情况：

fs/char_dev.c:200-223 register_chrdev_region

int register_chrdev_region(dev_t from, unsigned count, const char *name)
{
	struct char_device_struct *cd;
	dev_t to = from + count;
	dev_t n, next;

	for (n = from; n < to; n = next) {
		next = MKDEV(MAJOR(n)+1, 0);
		if (next > to)
			next = to;
		cd = __register_chrdev_region(MAJOR(n), MINOR(n),
			       next - n, name);
		if (IS_ERR(cd))
			goto fail;
	}
	return 0;
fail:
	// ... 回滚：把已经登记的区间逐个 __unregister_chrdev_region() 掉
}

两个函数登记的其实只是「这段号归我了」这条信息，真正的分发表在下一步。

4.3 cdev_init 与 cdev_add

struct cdev 的定义很短，但它就是「设备号 → 函数表」这条映射的载体。

include/linux/cdev.h:14-21

struct cdev {
	struct kobject kobj;
	struct module *owner;
	const struct file_operations *ops;
	struct list_head list;
	dev_t dev;
	unsigned int count;
} __randomize_layout;
  • ops：指向驱动的那张 file_operations 表。
  • dev / count：这段 cdev 负责的起始设备号和 minor 个数。
  • owner：持有者模块，模块被卸载时内核据此检查「还有没有人开着这个设备」。

cdev_init() 做初始化：

fs/char_dev.c:651-657 cdev_init

void cdev_init(struct cdev *cdev, const struct file_operations *fops)
{
	memset(cdev, 0, sizeof *cdev);
	INIT_LIST_HEAD(&cdev->list);
	kobject_init(&cdev->kobj, &ktype_cdev_default);
	cdev->ops = fops;
}

cdev_add() 才是「挂上去」：它把这段设备号写进内核全局的 cdev_map 索引表。

fs/char_dev.c:479-497 cdev_add

int cdev_add(struct cdev *p, dev_t dev, unsigned count)
{
	int error;

	p->dev = dev;
	p->count = count;

	if (WARN_ON(dev == WHITEOUT_DEV))
		return -EBUSY;

	error = kobj_map(cdev_map, dev, count, NULL,
			 exact_match, exact_lock, p);
	if (error)
		return error;

	kobject_get(p->kobj.parent);

	return 0;
}
  • kobj_map(cdev_map, dev, count, ...)：在字符设备索引表里插入「dev 起、连续 count 个 minor → 指向 p 这个 cdev」。查表时内核靠它把 i_rdev 翻译成 struct cdev *。
  • exact_match 是查表时的比较函数：只要落在 [dev, dev+count) 区间内就算命中；exact_lock 是命中后拿引用计数（防止设备被删掉时还在用）。
  • 因为这里用的是设备号区间，一个 cdev 可以连续管多个 minor——这正是 alloc_chrdev_region 申请 4 个 minor 时的用法。

4.4 file_operations：驱动与用户之间的全部接口

字符设备能干的事，全写在这张表里。注意 owner 一定要填 THIS_MODULE，否则模块可能被提前卸载。

include/linux/fs.h:1822-1862

  • read/write 里的缓冲区类型带 __user 标注 —— 这是给静态检查工具看的，表示「这个指针来自用户空间，不许直接解引用」。
  • read_iter/write_iter 是「现代版」的读写接口，支持 splice/tee 等零拷贝管道操作；用 read/write 就够绝大多数场景。
  • poll 让设备能被 select()/epoll() 监听，是驱动实现「可读/可写事件通知」的地方。
  • open/release 成对出现：open 时申请资源、release 时释放。

4.5 为什么必须用 copy_to_user / copy_from_user

这是新手最容易写错的地方。用户传进来的指针不能直接解引用，原因有三：

  • 地址可能非法：用户可以传 0xdeadbeef，内核直接读就会触发缺页异常，可能让内核进程被杀死。
  • 地址可能越界：用户可以传一个只差 1 字节就越界的指针，拷贝 4096 字节会踩到别的内存。
  • 地址可能在睡眠中变化：另一个线程可以随时 munmap() 掉那段内存。

copy_to_user() 的完整链路是：最外层做长度检查 → 中间层做 access_ok() 范围检查 → 架构相关的 raw_copy_to_user() → 汇编。

include/linux/uaccess.h:196-202 copy_to_user

static __always_inline unsigned long __must_check
copy_to_user(void __user *to, const void *from, unsigned long n)
{
	if (likely(check_copy_size(from, n, true)))
		n = _copy_to_user(to, from, n);
	return n;
}

中间层在 x86 上是 out-of-line 的（放在 lib/usercopy.c，因为它要能被各个架构共用）：

lib/usercopy.c:26-37 _copy_to_user

unsigned long _copy_to_user(void __user *to, const void *from, unsigned long n)
{
	might_fault();
	if (should_fail_usercopy())
		return n;
	if (likely(access_ok(to, n))) {
		instrument_copy_to_user(to, from, n);
		n = raw_copy_to_user(to, from, n);
	}
	return n;
}
EXPORT_SYMBOL(_copy_to_user);

再往下是架构相关的一层，x86 上它用 alternative_call_2 根据 CPU 特性在三份汇编之间自动选择（ERMS > rep_good > 手工展开）：

arch/x86/include/asm/uaccess_64.h:28-59 copy_user_generic / raw_copy_to_user

static __always_inline __must_check unsigned long
copy_user_generic(void *to, const void *from, unsigned len)
{
	unsigned ret;

	/*
	 * If CPU has ERMS feature, use copy_user_enhanced_fast_string.
	 * Otherwise, if CPU has rep_good feature, use copy_user_generic_string.
	 * Otherwise, use copy_user_generic_unrolled.
	 */
	alternative_call_2(copy_user_generic_unrolled,
			 copy_user_generic_string,
			 X86_FEATURE_REP_GOOD,
			 copy_user_enhanced_fast_string,
			 X86_FEATURE_ERMS,
			 ASM_OUTPUT2("=a" (ret), "=D" (to), "=S" (from),
				     "=d" (len)),
			 "1" (to), "2" (from), "3" (len)
			 : "memory", "rcx", "r8", "r9", "r10", "r11");
	return ret;
}

static __always_inline __must_check unsigned long
raw_copy_to_user(void __user *dst, const void *src, unsigned long size)
{
	return copy_user_generic((__force void *)dst, src, size);
}

真正干活的是汇编，因为要尽可能快：

arch/x86/lib/copy_user_64.S:201-219 copy_user_enhanced_fast_string

SYM_FUNC_START(copy_user_enhanced_fast_string)
	ASM_STAC
	cmpl $64,%edx
	jb .L_copy_short_string	/* less then 64 bytes, avoid the costly 'rep' */
	movl %edx,%ecx
1:	rep
	movsb
	xorl %eax,%eax
	ASM_CLAC
	ret

	.section .fixup,"ax"
12:	movl %ecx,%edx		/* ecx is zerorest also */
	jmp .Lcopy_user_handle_tail
	.previous

	_ASM_EXTABLE_CPY(1b, 12b)
SYM_FUNC_END(copy_user_enhanced_fast_string)
EXPORT_SYMBOL(copy_user_enhanced_fast_string)
  • ASM_STAC / ASM_CLAC：打开/关闭 AC（Access Check）标志位。关掉之后，CPU 访问用户地址不再触发页保护检查，于是可以在 C 层完成缺页处理（换入页面、修正用户页表），处理完再重试——这是 Linux 能让用户页延迟换入的关键。
  • rep movsb：用字符串指令批量复制（ERMS 特性）。小于 64 字节走短路径，避免 rep 的启动开销。
  • .section .fixup + _ASM_EXTABLE_CPY：如果拷贝过程中真的缺页了，CPU 跳到 fixup 段，把剩余字节数记进 %edx，跳去 .Lcopy_user_handle_tail 让 C 层去处理缺页并重试。
  • 返回值语义：0 表示全部拷贝成功，非 0 表示「还剩多少字节没拷」。所以判断写法是 if (copy_to_user(...)) return -EFAULT;，而不是 if (!copy_to_user(...))。

在 copy_from_user() 上还有一个额外细节：短拷贝时内核会把目标缓冲区清零，避免把内核栈上的残留数据泄露给用户态。

lib/usercopy.c:9-22 _copy_from_user

unsigned long _copy_from_user(void *to, const void __user *from, unsigned long n)
{
	unsigned long res = n;
	might_fault();
	if (!should_fail_usercopy() && likely(access_ok(from, n))) {
		instrument_copy_from_user(to, from, n);
		res = raw_copy_from_user(to, from, n);
	}
	if (unlikely(res))
		memset(to + (n - res), 0, res);
	return res;
}
EXPORT_SYMBOL(_copy_from_user);
常见错误：① 直接 memcpy(buf, user_ptr, n)；② 忘记检查返回值；③ 用 __user 之外的指针做直接解引用（比如把用户指针存进结构体后再解引用）。编译器不会帮你抓这类 bug，只能靠 code review 和 KASAN。

4.6 ioctl：给设备发「带参数的命令」

read/write 只能传字节流，像「设置波特率」这种带参数的命令就要靠 ioctl()。它把命令号编码成一个 32 位整数，再通过 arg 传一个指针。

include/uapi/asm-generic/ioctl.h:69-91

#define _IOC(dir,type,nr,size) \
	(((dir)  << _IOC_DIRSHIFT) | \
	 ((type) << _IOC_TYPESHIFT) | \
	 ((nr)   << _IOC_NRSHIFT) | \
	 ((size) << _IOC_SIZESHIFT))

#define _IO(type,nr)		_IOC(_IOC_NONE,(type),(nr),0)
#define _IOR(type,nr,size)	_IOC(_IOC_READ,(type),(nr),(_IOC_TYPECHECK(size)))
#define _IOW(type,nr,size)	_IOC(_IOC_WRITE,(type),(nr),(_IOC_TYPECHECK(size)))
#define _IOWR(type,nr,size)	_IOC(_IOC_READ|_IOC_WRITE,(type),(nr),(_IOC_TYPECHECK(size)))
#define _IOR_BAD(type,nr,size)	_IOC(_IOC_READ,(type),(nr),sizeof(size))
#define _IOW_BAD(type,nr,size)	_IOC(_IOC_WRITE,(type),(nr),sizeof(size))
#define _IOWR_BAD(type,nr,size)	_IOC(_IOC_READ|_IOC_WRITE,(type),(nr),sizeof(size))

四个字段各占一段位：

字段位数含义
dir2方向：_IOC_NONE(0) 无参数、_IOC_WRITE(1) 用户写内核读、_IOC_READ(2) 用户读内核写
type8「设备类型」，惯例用一个字符，如 'H'，用来避免不同驱动的命令号撞车
nr8命令序号，同一驱动内部区分不同命令
size14参数结构体大小，内核可用它做长度校验

方向位有个容易搞反的约定，源码注释里专门提醒过：

include/uapi/asm-generic/ioctl.h:79-88

 * NOTE: _IOW means userland is writing and kernel is reading. _IOR
 * means userland is reading and kernel is writing.
 */
#define _IO(type,nr)		_IOC(_IOC_NONE,(type),(nr),0)

驱动侧接收命令的回调是 unlocked_ioctl：

include/linux/fs.h:1833-1834

	long (*unlocked_ioctl) (struct file *, unsigned int, unsigned long);
	long (*compat_ioctl) (struct file *, unsigned int, unsigned long);
  • unlocked_ioctl 在「没有持有该文件的 inode 锁」时调用。现代内核的 ioctl 路径没有大锁，所以绝大多数驱动只实现它就够了。
  • compat_ioctl 用于 32 位用户程序跑在 64 位内核上的兼容层；不实现时，如果命令里带指针，内核会拒绝执行（避免 32 位指针被当成 64 位用）。

一个典型的 ioctl 回调长这样（下面的代码会在第 5 节的模块里出现）：

static long hello_unlocked_ioctl(struct file *filp, unsigned int cmd, unsigned long arg)
{
	struct hello_dev *dev = filp->private_data;
	int val = 0;

	switch (cmd) {
	case HELLO_IOCTL_GET_LEN: {
		size_t l = dev->len;
		if (copy_to_user((void __user *)arg, &l, sizeof(l)))
			return -EFAULT;
		return 0;
	}
	case HELLO_IOCTL_SET_LEN:
		if (copy_from_user(&val, (void __user *)arg, sizeof(val)))
			return -EFAULT;
		dev->len = (size_t)val;
		return 0;
	default:
		return -ENOTTY;
	}
}

两个细节：① arg 是 unsigned long，当它是用户指针时必须手动强转成 void __user *，编译器才会提醒你「这指针不可信」；② 未知命令返回 -ENOTTY（Not a typewriter），这是内核的惯例错误码。

4.7 class_create 与 device_create：让用户态看得见

设备号登记好了，用户态还是不知道怎么访问——因为 /dev 下还没有节点。先建一个「设备类」把同类设备归到一起：

drivers/base/class.c:226-251 __class_create

struct class *__class_create(struct module *owner, const char *name,
			     struct lock_class_key *key)
{
	struct class *cls;
	int retval;

	cls = kzalloc(sizeof(*cls), GFP_KERNEL);
	if (!cls) {
		retval = -ENOMEM;
		goto error;
	}

	cls->name = name;
	cls->owner = owner;
	cls->class_release = class_create_release;

	retval = __class_register(cls, key);
	if (retval)
		goto error;

	return cls;

error:
	kfree(cls);
	return ERR_PTR(retval);
}

然后用 device_create() 在这个类下创建一台具体设备：

drivers/base/core.c:3621-3633 device_create

struct device *device_create(struct class *class, struct device *parent,
			     dev_t devt, void *drvdata, const char *fmt, ...)
{
	va_list vargs;
	struct device *dev;

	va_start(vargs, fmt);
	dev = device_create_groups_vargs(class, parent, devt, drvdata, NULL,
					  fmt, vargs);
	va_end(vargs);
	return dev;
}
  • devt：就是前面申请到的 240:0。
  • drvdata：驱动私货，会存进 struct device，以后用 dev_get_drvdata() 取回。
  • fmt：设备名，支持格式化（device_create(cls, NULL, devt, NULL, "hello%d", i)）。

device_create() 内部会 device_add()，于是产生两样用户态看得见的东西：

drivers/base/core.c:2237-2242 dev_show

static ssize_t dev_show(struct device *dev, struct device_attribute *attr,
			char *buf)
{
	return print_dev_t(buf, dev->devt);
}
static DEVICE_ATTR_RO(dev);

也就是 /sys/class/hello/hello/dev 这个文件，内容是 "240:0"（print_dev_t() 就是 sprintf(buf, "%u:%u", MAJOR, MINOR)）。

以及一个 uevent：

drivers/base/core.c:1871-1887 dev_uevent

	/* add device node properties if present */
	if (MAJOR(dev->devt)) {
		const char *tmp;
		const char *name;
		umode_t mode = 0;
		kuid_t uid = GLOBAL_ROOT_UID;
		kgid_t gid = GLOBAL_ROOT_GID;

		add_uevent_var(env, "MAJOR=%u", MAJOR(dev->devt));
		add_uevent_var(env, "MINOR=%u", MINOR(dev->devt));
		name = device_get_devnode(dev, &mode, &uid, &gid, &tmp);
		if (name) {
			add_uevent_var(env, "DEVNAME=%s", name);

			// ...
		}
	}

内核把「MAJOR=240 MINOR=0 DEVNAME=hello」写进 uevent 缓冲区，用户态的 udev 读到后按 DEVNAME 在 /dev 建节点。内核自己其实也能建节点（devtmpfs，CONFIG_DEVTMPFS=y 时自动挂载），udev 的增量价值在于：按规则改权限、改属主、建软链（比如 /dev/disk/by-uuid/...）、以及按 ID_MODEL 之类属性做智能命名。

5.2 写一个完整的 hello 字符设备模块

新建目录 hello/，放入三个文件。

hello.c（驱动）：

// SPDX-License-Identifier: GPL-2.0
#include <linux/module.h>
#include <linux/init.h>
#include <linux/fs.h>
#include <linux/cdev.h>
#include <linux/device.h>
#include <linux/slab.h>
#include <linux/uaccess.h>
#include <linux/err.h>

#define HELLO_DEVICE_NAME "hello"
#define HELLO_MINOR      0
#define HELLO_MAGIC      'H'

/* ioctl 命令号：type 用 'H'，nr 从 1 开始 */
#define HELLO_IOCTL_GET_LEN _IO(HELLO_MAGIC, 1)
#define HELLO_IOCTL_SET_LEN _IOW(HELLO_MAGIC, 2, int)

struct hello_dev {
	struct cdev cdev;
	struct class *class;
	dev_t devno;
	char   buf[64];
	size_t len;
};

static struct hello_dev *hello;

static int hello_open(struct inode *inode, struct file *filp)
{
	struct hello_dev *dev = container_of(inode->i_cdev,
					    struct hello_dev, cdev);
	filp->private_data = dev;
	return 0;
}

static int hello_release(struct inode *inode, struct file *filp)
{
	return 0;
}

static ssize_t hello_read(struct file *filp, char __user *buf,
			  size_t count, loff_t *ppos)
{
	struct hello_dev *dev = filp->private_data;
	size_t len;

	if (*ppos >= dev->len)
		return 0;			/* 读到文件末尾 */

	len = min(count, dev->len - *ppos);
	if (copy_to_user(buf, dev->buf + *ppos, len))
		return -EFAULT;

	*ppos += len;
	return len;
}

static ssize_t hello_write(struct file *filp, const char __user *buf,
			   size_t count, loff_t *ppos)
{
	struct hello_dev *dev = filp->private_data;
	size_t len = min(count, sizeof(dev->buf));

	if (copy_from_user(dev->buf, buf, len))
		return -EFAULT;

	dev->len = len;
	return len;
}

static long hello_unlocked_ioctl(struct file *filp, unsigned int cmd,
				 unsigned long arg)
{
	struct hello_dev *dev = filp->private_data;
	int val = 0;

	switch (cmd) {
	case HELLO_IOCTL_GET_LEN: {
		size_t l = dev->len;
		if (copy_to_user((void __user *)arg, &l, sizeof(l)))
			return -EFAULT;
		return 0;
	}
	case HELLO_IOCTL_SET_LEN:
		if (copy_from_user(&val, (void __user *)arg, sizeof(val)))
			return -EFAULT;
		if (val < 0 || (size_t)val > sizeof(dev->buf))
			return -EINVAL;
		dev->len = (size_t)val;
		return 0;
	default:
		return -ENOTTY;
	}
}

static const struct file_operations hello_fops = {
	.owner		= THIS_MODULE,
	.read		= hello_read,
	.write		= hello_write,
	.unlocked_ioctl	= hello_unlocked_ioctl,
	.open		= hello_open,
	.release	= hello_release,
	.llseek		= default_llseek,
};

static int __init hello_init(void)
{
	int ret;
	struct device *cdev_dev;

	/* 0) 先给驱动私有结构体分配内存 */
	hello = kzalloc(sizeof(*hello), GFP_KERNEL);
	if (!hello)
		return -ENOMEM;

	/* 1) 申请设备号，major 由内核动态分配 */
	ret = alloc_chrdev_region(&hello->devno, HELLO_MINOR, 1,
				  HELLO_DEVICE_NAME);
	if (ret) {
		pr_err("alloc_chrdev_region failed: %d\n", ret);
		return ret;
	}

	/* 2) 初始化 cdev 并挂进内核索引表 */
	cdev_init(&hello->cdev, &hello_fops);
	hello->cdev.owner = THIS_MODULE;
	ret = cdev_add(&hello->cdev, hello->devno, 1);
	if (ret) {
		pr_err("cdev_add failed: %d\n", ret);
		goto err_region;
	}

	/* 3) 建 class，让用户态能看见 */
	hello->class = class_create(THIS_MODULE, HELLO_DEVICE_NAME);
	if (IS_ERR(hello->class)) {
		ret = PTR_ERR(hello->class);
		goto err_cdev;
	}

	/* 4) 创建设备，发 uevent，udev 会据此建 /dev/hello */
	cdev_dev = device_create(hello->class, NULL, hello->devno,
				 NULL, HELLO_DEVICE_NAME);
	if (IS_ERR(cdev_dev)) {
		ret = PTR_ERR(cdev_dev);
		goto err_class;
	}

	pr_info("hello: registered with major %d minor %d\n",
		MAJOR(hello->devno), MINOR(hello->devno));
	return 0;

err_class:
	class_destroy(hello->class);
err_cdev:
	cdev_del(&hello->cdev);
err_region:
	unregister_chrdev_region(hello->devno, 1);
	kfree(hello);
	return ret;
}

static void __exit hello_exit(void)
{
	device_destroy(hello->class, hello->devno);
	class_destroy(hello->class);
	cdev_del(&hello->cdev);
	unregister_chrdev_region(hello->devno, 1);
	kfree(hello);
	pr_info("hello: bye\n");
}

module_init(hello_init);
module_exit(hello_exit);

MODULE_LICENSE("GPL");
MODULE_DESCRIPTION("A minimal character device for learning");

test.c（用户态测试程序）：

#include <stdio.h>
#include <string.h>
#include <fcntl.h>
#include <unistd.h>
#include <sys/ioctl.h>
#include <errno.h>

#define HELLO_MAGIC       'H'
#define HELLO_IOCTL_GET_LEN _IO(HELLO_MAGIC, 1)
#define HELLO_IOCTL_SET_LEN _IOW(HELLO_MAGIC, 2, int)

int main(void)
{
	int fd = open("/dev/hello", O_RDWR);
	char buf[64] = {0};
	size_t len = 0;
	int val = 42;
	ssize_t n;

	if (fd < 0) {
		perror("open");
		return 1;
	}

	if (write(fd, "hello char device", 17) != 17) {
		perror("write");
		close(fd);
		return 1;
	}

	n = read(fd, buf, sizeof(buf));
	if (n < 0) {
		perror("read");
		close(fd);
		return 1;
	}
	printf("read %zd bytes: %s\n", n, buf);

	if (ioctl(fd, HELLO_IOCTL_SET_LEN, &val) < 0) {
		perror("ioctl SET_LEN");
		close(fd);
		return 1;
	}
	if (ioctl(fd, HELLO_IOCTL_GET_LEN, &len) < 0) {
		perror("ioctl GET_LEN");
		close(fd);
		return 1;
	}
	printf("ioctl says len = %zu\n", len);

	close(fd);
	return 0;
}

预期在串口终端看到 hello: registered with major 240 minor 0 和 crw------- 1 root root 240, 0 /dev/hello。

6. 自测

Q1. alloc_chrdev_region() 和 register_chrdev_region() 到底差在哪？前者 major 由内核动态挑选（第一个参数传 0），返回实际的设备号；后者 major 必须由你自己指定，而且要自己保证不和别人冲突。两者都只是「登记号段」，真正把号段接到函数表上的是 cdev_add()。
Q2. cdev_init() 和 cdev_add() 分别做了什么？cdev_init() 把 cdev 结构清零、初始化链表和 kobject、把 ops 指向你的 file_operations（此时还没生效）；cdev_add() 才把这段设备号写进内核全局的 cdev_map 索引表，从这一刻起用户态 open() 才能找到你的驱动。卸载时顺序相反：先 cdev_del() 再 unregister_chrdev_region()。
Q3. 为什么内核不能直接用 memcpy(buf, user_ptr, n)？用户指针可能非法、越界，或者在拷贝途中被另一个线程 munmap() 掉。直接解引用会触发内核态缺页异常，轻则杀进程，重则破坏内核内存。copy_to_user()/copy_from_user() 先做 access_ok() 范围检查，再由架构代码在关闭 AC 标志的情况下拷贝，缺页时交给内核补页后重试；它们的返回值是「未拷贝成功的字节数」，非 0 即出错。同样的道理，不要把用户指针长期存进驱动自己的结构体——它随时可能失效（进程退出、munmap、地址空间切换），正确做法是立刻拷进内核缓冲区，用完就丢弃。
Q4. _IO、_IOR、_IOW 分别什么时候用？_IO 不带参数；_IOR 表示「用户态读、内核写」（参数是输出）；_IOW 表示「用户态写、内核读」（参数是输入）。注意方向是站在用户态的角度说的，很容易记反。命令号里的 type 通常取一个字符（如 'H'），用来避免不同驱动的命令号冲突。
Q5. /dev/hello 这个节点是谁创建的？内核能自己建吗？内核发 uevent（含 DEVNAME=hello MAJOR=240 MINOR=0），由用户态的 udev 按规则在 /dev 下 mknod。内核也能建：CONFIG_DEVTMPFS=y 时 devtmpfs 会自动创建节点，udev 在此基础上做权限、命名、软链等增强。所以「内核里注册了设备但 /dev 下没节点」通常意味着 udev 没装或规则没命中，此时可以手工 mknod /dev/hello c 240 0。
