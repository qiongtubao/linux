🌱 fork 与 exit：进程的诞生与消亡

一次 fork 复制了整个 task_struct 却几乎不复制内存，一次 exit 让进程“死而不腐”等父进程来收尸 · 预计阅读 28 分钟

1. 它在解决什么问题

细胞分裂：一个细胞长到一定程度，把自己一分为二。新细胞要有自己的细胞核（独立身份）、独立的代谢状态，但遗传物质在分裂瞬间是“同一份拷贝”——而且为了省事，很多细胞器先共享，直到真正需要分离才复制。

Linux 的 fork() 就是这个过程的最佳工程实现。用户敲下 ls，shell 要执行它：shell 不能自己变成 ls（那样 shell 就消失了），所以要“复制一个自己”，让副本去 execve 成 ls，自己继续等待。这就是 fork——创建一个几乎完全相同的子进程。

问题在于：复制一整个进程的地址空间（几百 MB 的页表加数据）非常昂贵，而 fork 之后最常见的动作是 execve 立刻丢掉这些内存。所以 Linux 用 写时复制（COW）：fork 时只复制页表项、把父子双方都标成只读，共享同一批物理页；谁先写，谁触发缺页，缺页处理程序再复制那一页。既保证语义（父子互不影响），又避免无谓拷贝。

另一半是 exit：进程死了不能立刻把 task_struct 和内核对它的记账全部抹掉，因为父进程可能还想知道“它怎么死的、退出码是多少、用了多少 CPU”。于是进程先进入 僵尸 状态，只保留最小记录；父进程 wait() 之后，内核才真正释放它。这套“生—死—收尸”的协议，就是本篇要讲的两段代码。

3. 整体结构

3.1 fork 的三层调用栈

   │
   ▼

   │
   ├── dup_task_struct()   新 task_struct + 新内核栈
   ├── sched_fork()        分配 CPU、设优先级
   ├── copy_files()        fd 表 或 CLONE_FILES 共享
   ├── copy_fs()           cwd/root 或 CLONE_FS 共享
   ├── copy_sighand()      处理函数表 或 CLONE_SIGHAND 共享

                    │

顺序不是随便排的：出错回滚要按逆序释放；copy_mm 在 copy_namespaces 之前，因为新建 pid namespace 时要重新 alloc_pid，而它依赖 nsproxy；copy_thread 最后，因为它要用到已经建好的栈和 mm。

3.2 COW 到底“省”在哪

fork 前：父进程                       fork 后初始状态
  虚拟页 0x400000 ─┐                   父 PTE ──┐
                   ├─► 物理页 A                   ├─► 物理页 A（只读，refcount=2）
  虚拟页 0x401000 ─┘                   子 PTE ──┘

父进程写 0x400000 触发 #PF（页只读）：
   alloc 物理页 B，拷贝 A 的内容
   父 PTE 改为 → B（可写），A 留给子进程

所以 fork 的开销 ≈ 复制页表（不是复制数据页）+ 复制 VMA 元数据。对一个 1GB 的进程，页表可能几 MB，这仍然可观；但对共享库、fork 后立即 execve 的场景，省掉了 1GB 的数据拷贝，收益巨大。

4. 源码走读

4.1 clone 系统调用与 kernel_clone

fork() 在 libc 里其实就是 clone(SIGCHLD, 0)。clone 的参数按 ABI 打包成 kernel_clone_args，然后进入统一入口。

kernel/fork.c:3039-3057 SYSCALL_DEFINE5(clone)

SYSCALL_DEFINE5(clone, unsigned long, clone_flags, unsigned long, newsp,
		 int __user *, parent_tidptr,
		 int __user *, child_tidptr,
		 unsigned long, tls)
#endif
{
	struct kernel_clone_args args = {
		.flags		= (lower_32_bits(clone_flags) & ~CSIGNAL),
		.pidfd		= parent_tidptr,
		.child_tid	= child_tidptr,
		.parent_tid	= parent_tidptr,
		.exit_signal	= (lower_32_bits(clone_flags) & CSIGNAL),
		.stack		= newsp,
		.tls		= tls,
	};

	return kernel_clone(&args);
}
  • clone_flags 的低 8 位是 CSIGNAL（退出时给父进程发哪个信号，fork 是 SIGCHLD，线程是 0），所以拆出来放进 exit_signal，其余位放进 flags。
  • newsp 是新栈指针：分叉线程时由用户传入新栈；fork 时是 0，表示沿用父进程用户栈（实际是复制父栈内容）。
  • .child_tid 用于 CLONE_CHILD_CLEARTID：子线程退出时内核把这块用户内存清零并 futex 唤醒，这是 pthread_join 的底层机制。

4.2 copy_process 的复制顺序

kernel/fork.c:2483-2525 copy_process 的逐项复制

	/* Perform scheduler related setup. Assign this task to a CPU. */
	retval = sched_fork(clone_flags, p);	/* 调度器相关设置，分配CPU */
	if (retval)
		goto bad_fork_cleanup_policy;
	/* ... 此处省略 perf/audit/shm/security 的初始化 ... */
	retval = copy_semundo(clone_flags, p);	/* 复制信号量撤销信息 */
	if (retval)
		goto bad_fork_cleanup_security;
	retval = copy_files(clone_flags, p);	/* 复制文件描述符表 */
	if (retval)
		goto bad_fork_cleanup_semundo;
	retval = copy_fs(clone_flags, p);	/* 复制文件系统信息 */
	if (retval)
		goto bad_fork_cleanup_files;
	retval = copy_sighand(clone_flags, p);	/* 复制信号处理函数 */
	if (retval)
		goto bad_fork_cleanup_fs;
	retval = copy_signal(clone_flags, p);	/* 复制信号结构 */
	if (retval)
		goto bad_fork_cleanup_sighand;
	retval = copy_mm(clone_flags, p);	/* 复制内存管理结构 */
	if (retval)
		goto bad_fork_cleanup_signal;
	retval = copy_namespaces(clone_flags, p);	/* 复制命名空间 */
	if (retval)
		goto bad_fork_cleanup_mm;
	retval = copy_io(clone_flags, p);	/* 复制IO上下文 */
	if (retval)
		goto bad_fork_cleanup_namespaces;
	retval = copy_thread(clone_flags, args->stack, args->stack_size, p, args->tls);	/* 复制线程特定信息 */
	if (retval)
		goto bad_fork_cleanup_io;
  • 每个步骤失败都跳到“上一步的清理标签”，bad_fork_cleanup_xxx 标签链是一条逆序的清理流水线。这是内核里非常标准的“goto 错误处理”写法。
  • copy_sighand 在 copy_signal 之前：copy_signal 需要拿 sighand->siglock，也要判断是否新线程组。
  • copy_mm 在 copy_namespaces 之前：新建 pid namespace 时要重新 alloc_pid，而它用 p->nsproxy->pid_ns_for_children，所以 nsproxy 必须先就位；反过来 mm 失败时 nsproxy 还没被改，便于回滚。
  • sched_fork 在最前面就把 task 塞进某个 CPU 的 runqueue 的准备结构（p->on_rq=0，但 p->cpu 已定），但它还不会被调度——wake_up_new_task 才真正 activate_task。

4.3 dup_task_struct：结构体可以复制，栈必须新建

父进程的 task_struct 是“模板”，但内核栈不能共用——否则父子会用同一段栈帧互相踩。所以流程是：分配新 task_struct、分配新内核栈、把父结构体内容 memcpy 过去、再把新栈指针覆盖回 tsk->stack（因为 memcpy 把父进程的栈指针也抄过来了）。

kernel/fork.c:1050-1086 dup_task_struct

static struct task_struct *dup_task_struct(struct task_struct *orig, int node)
{
	struct task_struct *tsk;
	unsigned long *stack;
	struct vm_struct *stack_vm_area __maybe_unused;
	int err;

	if (node == NUMA_NO_NODE)
		node = tsk_fork_get_node(orig);		/* 获取合适的NUMA节点 */
	tsk = alloc_task_struct_node(node);		/* 分配任务结构体 */
	if (!tsk)
		return NULL;

	stack = alloc_thread_stack_node(tsk, node);	/* 分配线程栈 */
	if (!stack)
		goto free_tsk;

	if (memcg_charge_kernel_stack(tsk))		/* 对内核栈进行内存控制组计费 */
		goto free_stack;

	stack_vm_area = task_stack_vm_area(tsk);

	err = arch_dup_task_struct(tsk, orig);		/* 执行架构特定的复制 */
	/* ... 省略注释 ... */
	tsk->stack = stack;				/* 恢复栈指针 */
#ifdef CONFIG_VMAP_STACK
	tsk->stack_vm_area = stack_vm_area;		/* 恢复栈虚拟内存区域 */
#endif
#ifdef CONFIG_THREAD_INFO_IN_TASK
	refcount_set(&tsk->stack_refcount, 1);		/* 设置栈引用计数 */
#endif
  • alloc_task_struct_node(node) 从 slab 缓存（task_struct_cachep）分配约 9KB 的对象；node 是 NUMA 节点，尽量与父进程同节点以减少跨节点内存访问。
  • alloc_thread_stack_node 分配 16KB 内核栈。开了 CONFIG_VMAP_STACK 时从 vmalloc 区拿，好处是可以在栈区放 guard page，溢出会触发 page fault 而不是悄悄踩坏邻接对象。
  • arch_dup_task_struct 就是 *dst = *orig 加一些架构特定动作。它会整体覆盖 tsk->stack，所以之后必须手工写回新栈指针——memcpy 语义下，凡是“指向自身的字段”都必须重新初始化，这是 C 结构体复制的经典坑。

4.4 copy_mm：CLONE_VM 还是 dup_mm

kernel/fork.c:1779-1826 copy_mm

static int copy_mm(unsigned long clone_flags, struct task_struct *tsk)
{
	struct mm_struct *mm, *oldmm;
	int retval;

	tsk->min_flt = tsk->maj_flt = 0;
	tsk->nvcsw = tsk->nivcsw = 0;
	/* ... 省略 hung task 初始化 ... */

	tsk->mm = NULL;
	tsk->active_mm = NULL;

	/*
	 * Are we cloning a kernel thread?
	 *
	 * We need to steal a active VM for that..
	 */
	oldmm = current->mm;
	if (!oldmm)
		return 0;

	/* initialize the new vmacache entries */
	vmacache_flush(tsk);

	if (clone_flags & CLONE_VM) {
		mmget(oldmm);
		mm = oldmm;
		goto good_mm;
	}

	retval = -ENOMEM;
	mm = dup_mm(tsk, current->mm);
	if (!mm)
		goto fail_nomem;

good_mm:
	tsk->mm = mm;
	tsk->active_mm = mm;
	return 0;

fail_nomem:
	return retval;
}
  • current->mm == NULL 表示父进程是内核线程（用户态没有地址空间）。内核线程 fork 出的子进程也是内核线程，直接返回，tsk->mm 保持 NULL。
  • CLONE_VM 分支只做 mmget()（引用计数 +1），指针复用——这就是线程共享地址空间的实现。写一个变量，另一个线程立刻看到。
  • dup_mm() 才是 fork 的重量级步骤：分配新 mm_struct、复制 vm_area_struct 链表、copy_page_range() 复制页表。注意它复制的是页表项，物理页共享并置只读。
  • active_mm = mm：新进程马上要上 CPU，需要知道该加载哪张页表。

4.5 copy_files：表复制，file 共享

kernel/fork.c:1846-1871 copy_files

static int copy_files(unsigned long clone_flags, struct task_struct *tsk)
{
	struct files_struct *oldf, *newf;
	int error = 0;

	/*
	 * A background process may not have any files ...
	 */
	oldf = current->files;
	if (!oldf)
		goto out;

	if (clone_flags & CLONE_FILES) {
		atomic_inc(&oldf->count);
		goto out;
	}

	newf = dup_fd(oldf, NR_OPEN_MAX, &error);
	if (!newf)
		goto out;

	tsk->files = newf;
	error = 0;
out:
	return error;
}
  • 注意 tsk->files 在 CLONE_FILES 分支里没有赋值——因为 dup_task_struct 已经把父进程的指针抄过来了，这里只需要把计数加一。
  • dup_fd 分配新的 files_struct 与 fd 数组，但每个 struct file 只把引用计数 +1，不复制文件对象本身。所以 fork 后父子共享同一个打开文件：共享文件偏移 f_pos、共享 O_APPEND 语义。这正是“父子同时写同一个 fd 会互相穿插”的原因（要独立偏移必须 open 两次）。
  • 而 close 是各自独立的：父进程 close(fd) 只减父进程表里的引用，子进程的 fd 仍然有效，直到两边都 close，struct file 才真正释放——所以 unlink 之后文件仍占空间，就是有进程还开着它。

4.6 COW：copy_present_pte 把双方都改成只读

fork 复制页表时，不能直接复制“可写”的 PTE——那父子就真的共享可写页了。内核的做法是：复制 PTE 内容，然后把父子双方的这条 PTE 都改成只读（写保护），并增加物理页引用计数。

mm/memory.c:962-993 copy_present_pte

copy_present_pte(struct vm_area_struct *dst_vma, struct vm_area_struct *src_vma,
		 pte_t *dst_pte, pte_t *src_pte, unsigned long addr, int *rss,
		 struct page **prealloc)
{
	struct mm_struct *src_mm = src_vma->vm_mm;
	unsigned long vm_flags = src_vma->vm_flags;
	pte_t pte = *src_pte;
	struct page *page;

	page = vm_normal_page(src_vma, addr, pte);
	if (page) {
		int retval;

		retval = copy_present_page(dst_vma, src_vma, dst_pte, src_pte,
					   addr, rss, prealloc, pte, page);
		if (retval <= 0)
			return retval;

		get_page(page); /* 增加页面引用计数 */
		page_dup_rmap(page, false);
		rss[mm_counter(page)]++;
	}

	/*
	 * If it's a COW mapping, write protect it both
	 * in the parent and the child
	 */
	if (is_cow_mapping(vm_flags) && pte_write(pte)) {
		ptep_set_wrprotect(src_mm, addr, src_pte);
		pte = pte_wrprotect(pte);
	}
  • is_cow_mapping(vm_flags) 判断这个 VMA 是不是“私有可写”（VM_MAYWRITE && !VM_SHARED）。私有只读映射（比如代码段）本来就是只读，不需要 COW；共享映射（MAP_SHARED）本来就该共享可写。
  • ptep_set_wrprotect(src_mm, ...) 改的是父进程的页表，pte_wrprotect(pte) 改的是即将写入子进程页表的副本。两边的 PTE 都变成只读，谁写谁 #PF。
  • 缺页后 do_wp_page()（mm/memory.c:3202）→ wp_page_copy()（2940）分配新页并复制内容，让写者拿到私有的可写页。引用计数为 1 时还有优化：直接复用原页，避免拷贝。

4.7 copy_thread：子进程从哪开始执行

结构体复制完了，但“子进程的第一条指令是哪条”？答案在 copy_thread：它伪造一个内核栈帧，让子进程第一次被调度时，从 ret_from_fork 返回，然后像“刚刚从系统调用返回”一样回到用户态。

arch/x86/kernel/process.c:130-140 copy_thread 头部

	struct pt_regs *childregs;
	int ret = 0;

	childregs = task_pt_regs(p);
	fork_frame = container_of(childregs, struct fork_frame, regs);
	frame = &fork_frame->frame;

	frame->bp = encode_frame_pointer(childregs);
	frame->ret_addr = (unsigned long) ret_from_fork;
	p->thread.sp = (unsigned long) fork_frame;
	p->thread.io_bitmap = NULL;
	memset(p->thread.ptrace_bps, 0, sizeof(p->thread.ptrace_bps));
  • task_pt_regs(p) 指向新内核栈顶部预留的 pt_regs 区域；fork_frame 是它外面再包一层“调用帧”。
  • frame->ret_addr = ret_from_fork 是关键：子进程被 switch_to 切上去时，栈帧里的返回地址是 ret_from_fork，于是它从汇编返回路径开始跑，而不是从 copy_process 中间。
  • p->thread.sp 是这个新帧的地址，__switch_to 会把它写进 TSS 的 sp0。之后所有“从用户态进内核”都会落到这个栈上。
  • 后半段（源码未摘）把父进程的 pt_regs 整体拷给子进程（*childregs = *current_pt_regs()），再把 childregs->ax 置 0——这就是“fork 在子进程返回 0”的实现。

4.8 vfork 的同步：completion 与 wait_for_vfork_done

kernel/fork.c:2930-2949 kernel_clone 的 vfork 部分

	if (clone_flags & CLONE_VFORK) {
		p->vfork_done = &vfork;	/* 设置vfork完成标志 */
		init_completion(&vfork);	/* 初始化完成量 */
		get_task_struct(p);	/* 增加任务引用计数 */
	}

  • p->vfork_done 指向父进程栈上的一个 completion（注意：这是父进程栈上的变量，所以父进程必须活着等）。
  • 子进程在 execve 成功替换地址空间时，或 exit_mm() 释放 mm 时，会调用 complete_vfork_done() 唤醒它。mm_release() 里那段 “if vfork_done … complete” 就是这个机制。
  • wake_up_new_task 之后父进程立即进入 wait_for_vfork_done 睡眠——所以 vfork 语义上“父进程阻塞”，实现上是一个内核里的等待，而不是用户态忙等。

4.9 do_exit：从“活着”到“僵尸”

kernel/exit.c:765-830 do_exit（节选）

	exit_signals(tsk);  /* sets PF_EXITING */

	/* sync mm's RSS info before statistics gathering */

  • atomic_dec_and_test(&tsk->signal->live)：live 是线程组里“还活着的 task 数”。减到 0 说明整个线程组都死了，这时才做“组级”清理（tty 断开、统计上报）。单个线程退出 group_dead 为 false，很多动作跳过。
  • tsk->exit_code = code 是给 wait() 读的退出码。注意它和 exit_signal 是两个不同字段。
  • exit_mm() 在文件/命名空间之前：释放 mm 时要 mm_release()（清 child_tid、唤醒 vfork 父进程），此时还不能依赖文件系统。
  • exit_task_namespaces 放在很后面，因为前面的一些清理还可能要访问 /proc 之类的挂载。
  • 最后一行（源码节选外）是 do_task_dead()（kernel/sched/core.c:5539 附近）：它把 state 设成 TASK_DEAD 然后调 schedule()，并且永不返回。这个 task 的内核栈永远不会再被使用，之后由别的 task 在 finish_task_switch 里 put_task_struct 回收。

4.10 exit_notify：发讣告、托孤、决定要不要自己收尸

kernel/exit.c:646-678 exit_notify

static void exit_notify(struct task_struct *tsk, int group_dead)
{
	bool autoreap;
	struct task_struct *p, *n;
	LIST_HEAD(dead);

	write_lock_irq(&tasklist_lock);
	forget_original_parent(tsk, &dead);

	if (group_dead)
		kill_orphaned_pgrp(tsk->group_leader, NULL);

	tsk->exit_state = EXIT_ZOMBIE;
	if (unlikely(tsk->ptrace)) {
		int sig = thread_group_leader(tsk) &&
				thread_group_empty(tsk) &&
				!ptrace_reparented(tsk) ?
			tsk->exit_signal : SIGCHLD;
		autoreap = do_notify_parent(tsk, sig);
	} else if (thread_group_leader(tsk)) {
		autoreap = thread_group_empty(tsk) &&
			do_notify_parent(tsk, tsk->exit_signal);
	} else {
		autoreap = true;
	}

	if (autoreap) {
		tsk->exit_state = EXIT_DEAD;
		list_add(&tsk->ptrace_entry, &dead);
	}
	/* ... 省略 de_thread 唤醒 ... */
	write_unlock_irq(&tasklist_lock);

	list_for_each_entry_safe(p, n, &dead, ptrace_entry) {
		list_del_init(&p->ptrace_entry);
		release_task(p);
	}
}
  • forget_original_parent(tsk, &dead) 处理托孤：把这个 task 的子进程 reparent 给 init 或最近的 subreaper，如果有子进程已经是僵尸，就收集到 dead 链表里一起释放。
  • tsk->exit_state = EXIT_ZOMBIE：从这一刻起，它就是僵尸。ps 读 state | exit_state 看到的是 Z。
  • do_notify_parent 返回 autoreap：如果父进程明确表示“不关心”（SIGCHLD 被设成 SIG_IGN 或 SA_NOCLDWAIT），内核就不留僵尸，直接 EXIT_DEAD + release_task。这就是 signal(SIGCHLD, SIG_IGN) 能自动收割僵尸的原因。
  • 非组长线程（普通线程）autoreap = true，因为线程退出不需要父进程 wait，pthread_join 是另一套（futex）机制。
  • release_task(p) 在这里被调用的条件很窄——只对“已经确定无人认领”的；正常僵尸要等父进程 wait4() 才走到这一步。

4.11 wait4：父进程收尸

父进程调 wait4(pid, &status, options, &rusage)，内核进入 kernel_wait4() → do_wait()。核心逻辑是一个“扫一遍子进程链表，看谁状态变了”的循环，找不到就把自己挂到 signal->wait_chldexit 等待队列上睡一觉：

kernel/exit.c:1442-1497 do_wait 主体

	wo->notask_error = -ECHILD;
	if ((wo->wo_type < PIDTYPE_MAX) &&
	   (!wo->wo_pid || !pid_has_task(wo->wo_pid, wo->wo_type)))
		goto notask;

	set_current_state(TASK_INTERRUPTIBLE);
	read_lock(&tasklist_lock);
	tsk = current;
	do {
		retval = do_wait_thread(wo, tsk);
		if (retval)
			goto end;

		retval = ptrace_do_wait(wo, tsk);
		if (retval)
			goto end;

		if (wo->wo_flags & __WNOTHREAD)
			break;
	} while_each_thread(current, tsk);
	read_unlock(&tasklist_lock);

notask:
	retval = wo->notask_error;
	if (!retval && !(wo->wo_flags & WNOHANG)) {
		retval = -ERESTARTSYS;
		if (!signal_pending(current)) {
			schedule();
			goto repeat;
		}
	}
end:
	__set_current_state(TASK_RUNNING);
	remove_wait_queue(&current->signal->wait_chldexit, &wo->child_wait);
	return retval;
}
  • set_current_state(TASK_INTERRUPTIBLE) 必须在拿 tasklist_lock 之前：这样即使子进程在你拿锁前就死了并发 SIGCHLD 唤醒你，schedule() 也不会真的睡下去（signal_pending 或 try_to_wake_up 会把 state 改回 RUNNING）。这是内核里经典的“先设状态再检查、再睡”的无丢唤醒模式。
  • WNOHANG 表示“不等，没死就立刻返回 0”；__WNOTHREAD 表示不代其他线程 wait；WUNTRACED 让 stop 状态也报。
  • do_wait_thread(wo, tsk) 内部遍历 tsk->children 链表，对每个子进程调 wait_consider_task()，再按状态分派到 wait_task_zombie()、wait_task_stopped()、wait_task_continued()。
  • 一旦找到僵尸，wait_task_zombie()（981 行）用 cmpxchg(&p->exit_state, EXIT_ZOMBIE, EXIT_DEAD) 抢占“收尸权”（多线程父进程可能同时 wait，只有一个能成功），然后 release_task(p)（1091 行）真正释放。

4.12 release_task：最后一步

kernel/exit.c:181-214 release_task（节选）

	write_lock_irq(&tasklist_lock);
	ptrace_release_task(p);
	thread_pid = get_pid(p->thread_pid);
	__exit_signal(p);
	/* ... 此处省略组长判定、do_notify_parent、退出锁 ... */

  • __exit_signal(p) 把 task 从线程组链表里摘掉、结算 CPU 时间、清 pending 信号。
  • put_pid(thread_pid) 释放 pid 号——所以僵尸期间 PID 仍被占用，ps 能看到它；一旦收尸，PID 才能被复用。
  • put_task_struct_rcu_user 递减 task_struct 的 refcount，最后一个引用消失后由 RCU 回调 free_task 释放 9KB 结构与 16KB 内核栈。

5. 动手验证

实验一：看 fork 返回两次与 PID 关系。

$ cat > /tmp/f.c <<'EOF'
#include <stdio.h>
#include <unistd.h>
int main(void) {
    pid_t p = fork();
    if (p == 0) printf("child  pid=%d ppid=%d\n", getpid(), getppid());
    else        printf("parent pid=%d child=%d\n", getpid(), p);
    return 0;
}
EOF
$ cc -o /tmp/f /tmp/f.c && /tmp/f
parent pid=12345 child=12346
child  pid=12346 ppid=12345

预期：子进程拿到的返回值是 0，父进程拿到的是子 PID；子进程的 PPID 等于父进程 PID，这就是 copy_process 里 p->real_parent = current 与 list_add_tail(&p->sibling, &p->real_parent->children) 的结果。

实验二：验证 COW——fork 后内存不复制，写才复制。

$ cat > /tmp/cow.c <<'EOF'
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <string.h>
int main(void) {
    char *p = malloc(200*1024*1024);   /* 200MB */
    memset(p, 1, 200*1024*1024);       /* 先全部写实 */
    pid_t c = fork();
    if (c == 0) { sleep(3); _exit(0); }
    char cmd[128]; snprintf(cmd, sizeof cmd, "grep VmRSS /proc/%d/status", c);
    system(cmd);                       /* 子进程 RSS 应该接近 200MB */
    sleep(4);
    return 0;
}
EOF
$ cc -O0 -o /tmp/cow /tmp/cow.c && /tmp/cow
VmRSS:	  204808 kB

子进程没写任何数据，RSS 却接近 200MB——因为 RSS 统计的是“映射到的物理页”，COW 后子进程的页表指向同一批物理页，引用计数为 2。如果在子进程里 memset(p, 2, ...)，RSS 会再涨一份（真正复制）；用 /proc/<pid>/smaps 的 Private_Dirty 字段对比更直观。

实验三：僵尸与 ps -o pid,ppid,stat。

$ python3 - <<'EOF' &
import os, time
if os.fork() == 0:
    os._exit(0)          # 子进程立刻退出
time.sleep(0.2)          # 父进程不 wait，直接睡
EOF
$ ps -o pid,ppid,stat,comm -C python3
  PID  PPID STAT COMMAND
 5601     1 Z    python3

预期：STAT 是 Z（EXIT_ZOMBIE = 0x20），PPID 变成 1（被 reparent）。这个 Z 进程不占地址空间（mm 已经释放），只占一个 task_struct 和 PID，kill -9 无效——只有父进程 wait，或父进程退出、init 接管并 wait，才会消失。

实验五：vfork 的阻塞语义。

6. 自测

Q1. fork() 为什么不在内核里直接“拷贝内存页”？因为绝大多数 fork 后面紧跟 execve，拷贝的内存立刻会被丢弃；而 fork 出的子进程可能只读写其中很少一部分。COW 把“复制”推迟到真正写的那一刻，摊薄了成本。代价是每次写首次触页都会 #PF，且页表仍要复制。
Q2. 线程和进程在 copy_process 中真正不同的只有哪几个标志？主要是 CLONE_VM | CLONE_FS | CLONE_FILES | CLONE_SIGHAND | CLONE_THREAD | CLONE_SYSVSEM | CLONE_SETTLS | CLONE_PARENT_SETTID | CLONE_CHILD_CLEARTID。其中 CLONE_THREAD 决定 tgid 继承与 exit_signal=-1；CLONE_VM 决定 mm 共享。线程不是另一种数据结构，只是共享程度更高的一组 clone 标志。
Q3. 为什么 copy_files 里共享分支不需要给 tsk->files 赋值？因为 dup_task_struct 已经用 *dst = *orig 整体复制了父进程的 files 指针。共享语义恰好就等于“指针相同”，所以只需把被共享对象的引用计数 +1，防止父进程 close 之后对象被释放。
Q4. 僵尸进程占不占内存？能不能 kill -9 掉？不占地址空间（exit_mm() 已释放 mm），但占一个 task_struct（约 9KB）、内核栈（16KB）以及一个 PID。它已经不在运行队列里，没有代码可以“执行”信号处理，所以 kill -9 不能让它消失。只能靠父进程 wait()，或父进程先死让它变成孤儿被 init 收割。
Q5. vfork 为什么要求父进程阻塞，而 fork 不用？因为 vfork 共享同一个地址空间和同一套用户栈。如果父子同时跑，子进程往栈上压一个返回地址就会覆盖父进程的栈帧，导致父进程数据损坏。阻塞保证“同一时刻只有一个执行流在使用这套栈”，因此子进程只能立即 exec（exec 会换掉地址空间并唤醒父进程）或 exit。
