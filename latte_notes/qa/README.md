## 问题 1 的关键对照（同一台 128M + 64M swap）

| | `dd if=/dev/zero`（全零） | `dd if=/dev/urandom`（非零） |
|---|---|---|
| `SwapFree` 用掉 | 26388 kB | 31148 kB |
| `pswpout` | **39** | **7811**（≈31144 kB） |
| `SwapCached` | 28 kB | 4128 kB |

代码依据：`mm/page_io.c:241` 的 `swap_writeout()` 对 `is_folio_zero_filled()` 的页
只设 zeromap 标记就 `goto out_unlock`，不进 `__swap_writepage()`，而 `pswpout` 只在
后者里计数。

## 三条方法论

1. **计数器先看实现再解读**：`pswpout` 统计的是“产生 IO 的页”，不是“换出的页”。
2. **判定“有没有”要用精确匹配**：`ps | grep <pid>` 或直接读 `/proc/<pid>/stat`，
   别用 `head` 截断后肉眼看。
3. **未解就写未解，但要写清“缩小到了什么程度”**：问题 3 用一次 `ls -R /`
   （`nr_unused` 1 → 18804，`drop_caches` 收回 16700 个）证伪了“统计口径过期”的假设，
   把范围锁到“新建 dentry 的引用未归零”；并给出了 kprobe 的具体配方（配置已具备）。

## 仍未结的口子
