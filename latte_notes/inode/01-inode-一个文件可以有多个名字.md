# 主题一 · inode：一个文件可以有多个名字

## 你已知的

Windows 里“文件”就是盘上的一个名字。Linux 不一样：**文件本体（inode）和名字（目录项）
是分开的**，一个 inode 可以有多个名字。这正是硬链接的基础。

## 两个层次

| 层次 | 是什么 | 例子 |
|---|---|---|
| **名字**（dentry） | 目录里的一条记录：“这个名字 → inode 号” | `/a`、`/b` |
| **本体**（inode） | 元数据：类型、权限、大小、时间、数据块位置、**链接计数 i_nlink** | inode 号 12345 |

`ls -i` 看到的是 inode 号；`ls -l` 第二列是 `i_nlink`（有几个名字指着它）。

## 硬链接 vs 符号链接

| | 硬链接（`ln a b`） | 符号链接（`ln -s a b`） |
|---|---|---|
| `/b` 指向 | 同一个 inode（与 `/a` 完全等价） | 一个新的 inode，内容是字符串 `"a"` |
| `inode` 数 | 不变（还是 1 个） | +1（链接自己有 inode） |
| `ls -l` 显示 | 第二列 +1；类型仍是普通文件 | 类型 `l`，末尾显示 `-> a` |
| 跨文件系统 | ❌ 不行（inode 号只在同一 fs 内有意义） | ✅ 可以 |
| 指向目录 | ❌ 一般不允许（防环） | ✅ 可以 |
| 原文件删除后 | 数据还在（还有另一个名字） | 变成悬空链接（打不开） |

## 删除到底删什么

```
unlink("/b")            →  i_nlink--（2 → 1），目录项 /b 变成 negative
                             inode 与数据完全不受影响，/a 照常可读

unlink("/a")            →  i_nlink--（1 → 0）
                             若没人打开着 → inode 与数据真正释放
                             若还有进程打开着 → 数据留着，等最后一个 close 再释放
```

这就是“删了一个正在下载的文件，磁盘空间没立刻回来”的原因：**句柄还开着**。

## 为什么 Linux 的 `rm` 看起来飞快

因为 `rm` 只做“目录项删除 + i_nlink--”，并不去清数据块（那是后台/延迟的事）。
在内存文件系统（rootfs 是 tmpfs）里更是只动了内存结构。

## 本次实验要看的三件事

| 动作 | 期望：inode 数 | 期望：dentry 数 |
|---|---|---|
| `touch /a` | +1 | +1 |
| `ln /a /b`（硬链接） | **不变** | **+1** |
| `ln -s /a /c`（符号链接） | +1 | +1 |
| `rm /b` | 不变（nlink 2→1） | 不变或留 negative |

如果第二行“inode 不变、dentry +1”成立，就证明了三件套的分层。
