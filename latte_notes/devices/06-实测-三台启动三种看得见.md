# 主题六 · 实测：三台启动，三种“看得见”

这一站的所有结论都来自三次启动，用同一个内核、三个不同的 initramfs/参数。

## 三次启动的设置

| | A | B | C |
|---|---|---|---|
| initramfs | `bb_initramfs.cpio` | 同 A | 诊断版（init 跑 `cat /proc/consoles` 等） |
| 命令行 | `console=ttyS0 earlyprintk=serial` | **只** `earlyprintk=serial` | 同 A |
| 想验证什么 | 正常路径 | earlycon 与真 console 的交接 | `/dev` 里到底有什么 |

## A：正常（控制台 = 串口）

```
[    0.000000] [latte] register_console: earlyser-1 flags=0x9
[    0.000000] [latte] early console registered: earlyser (keep=0)
[    0.277806] [latte] console_init: run __con_initcall section
[    0.281885] [latte] register_console: tty-1 flags=0x1
[    0.282244] [latte] register_console: hvc-1 flags=0x1
[    0.283040] [latte] register_console: ttyS-1 flags=0x11
[    1.260885] [latte] devtmpfsd: kdevtmpfs thread running
[    3.767738] [latte] console_on_rootfs: /dev/console -> fd 0/1/2
```

四个 console 依次上岗：earlycon（临时）→ tty（虚拟终端）→ hvc（hypervisor console）
→ ttyS（串口）。只有 `ttyS0` 真正连在串口上，所以后面的日志都从它出来。

## B：只留 `earlyprintk`，串口在第 396 行后彻底静默

```
[    0.000000] [latte] register_console: tty-1 flags=0x1
[    0.000000] printk: legacy console [tty0] enabled
[    0.000000] printk: legacy bootconsole [earlyser0] disabled
（无后续输出，QEMU 超时被杀）
```

原因：`console=` 缺省时首选 console 是 VGA 的 `tty0`，它一注册就把 `earlyser`
顶掉；而 VGA 在 `-nographic` 下看不见。**console 名单与你能不能看到输出是两件事。**

## C：诊断 init 揭开 `/dev`

`/dev` 一共 **111** 项（`ls -l /dev | wc -l` 口径），全部来自 devtmpfs，例如：

```
crw-------    1 0  0    5,   1  console
crw-------    1 0  0    4,  64  ttyS0      ← ls 里能看到，它在 2.84s 才被 8250 驱动建出来
crw-rw-rw-    1 0  0    1,   3  null
crw-rw-rw-    1 0  0    1,   8  random
crw-rw-rw-    1 0  0    5,   0  tty
crw-------    1 0  0    4,   0  tty0
brw-------    1 0  0    7,   0  loop0
brw-------    1 0  0   11,   0  sr0
```

`/proc/mounts` 里对应的挂载：

```
none /dev devtmpfs rw,relatime,size=1009404k,nr_inodes=252351,mode=755 0 0
```

`/proc/consoles`（主题五讲的格式）：

```
ttyS0                -W- (EC    a)    4:64
```

## 三条结论

1. **设备节点不是“文件”，是设备号的载体**：`console` 是 `5:1`、`ttyS0` 是 `4:64`，
   权限位与属主都只是元数据。
2. **`/dev` 的内容由内核自动生成**（devtmpfs + `kdevtmpfs` 线程），不需要 udev；
   udev 只做改名/权限/符号链接这类“美颜”。
3. **能看到日志≠名单里有 console**：必须有某个 console 的 `write()` 真的指向串口
   （`console=ttyS0`），否则日志去 VGA，串口一片安静。

## 复现

```bash
cd /home/dong/Documents/github/linux
make -j16 bzImage
BASE="nokaslr ignore_loglevel panic=1"

# A：正常
timeout 30 qemu-system-x86_64 -kernel arch/x86/boot/bzImage -initrd bb_initramfs.cpio \
  -append "console=ttyS0 earlyprintk=serial $BASE" -nographic -m 2G -no-reboot \
  > /tmp/latte-conA.log 2>&1

# B：只 earlyprintk（串口会静默）
timeout 25 qemu-system-x86_64 -kernel arch/x86/boot/bzImage -initrd bb_initramfs.cpio \
  -append "earlyprintk=serial $BASE" -nographic -m 2G -no-reboot \
  > /tmp/latte-conB.log 2>&1

# C：诊断 init（打印 consoles/devices//dev/mounts）
rm -rf /tmp/diag && cp -a bb_rootfs /tmp/diag
cat > /tmp/diag/init <<'EOF'
#!/bin/sh
mount -t proc none /proc
mount -t sysfs none /sys
mount -t devtmpfs none /dev
echo "=== consoles ==="; cat /proc/consoles
echo "=== devices ==="; cat /proc/devices
echo "=== ls /dev ==="; ls -l /dev
echo "=== mounts ==="; cat /proc/mounts
echo "=== diag done ==="
exec /bin/sh
EOF
chmod +x /tmp/diag/init
( cd /tmp/diag && find . | cpio -o -H newc --quiet ) > /tmp/bb_diag.cpio
timeout 30 qemu-system-x86_64 -kernel arch/x86/boot/bzImage -initrd /tmp/bb_diag.cpio \
  -append "console=ttyS0 earlyprintk=serial $BASE" -nographic -m 2G -no-reboot \
  > /tmp/latte-conC.log 2>&1
```
