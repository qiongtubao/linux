# 主题一 · 设备三件套：设备号、设备节点、驱动

## 你已知的

电脑上有各种“设备”：硬盘、U 盘、串口、键盘、网卡。Windows 用“设备管理器”管它们；
Linux 里它们全都表现为 `/dev` 下的文件，以及 `/sys` 下的一堆属性。

## 三件套

| 东西 | 是什么 | 例子 |
|---|---|---|
| **设备号** | “哪类驱动 + 这一类里的第几个”，格式 `主:次` | `5:1` = console |
| **设备节点** | `/dev` 下那个文件，本身不存数据，只记设备号 | `/dev/console` |
| **驱动** | 真正会读写硬件的代码，按设备号找到 | 8250 串口驱动、tty 层 |

打开 `/dev/console` 读写的流程：VFS 看到它是设备文件 → 查 `inode->i_rdev` 得到
`5:1` → 按主设备号 5 找到字符设备驱动 → 调它的 `read`/`write`。
**设备节点只是“把设备号暴露成一个路径”**，删掉节点不影响驱动，重建节点也不影响数据。

## 字符设备 vs 块设备

| | 字符设备（c） | 块设备（b） |
|---|---|---|
| 访问方式 | 按字节流顺序读写 | 按块随机读写，走页缓存 |
| 例子 | 串口、键盘、`/dev/null`、`/dev/tty` | 硬盘、分区、`/dev/ram0` |
| 主设备号 | 5（tty/console）、1（mem）、4（串口） | 8（sd）、1（ram） |

## 本机几个真实的设备号

`arch/x86` 的默认 builtin initramfs 里有这么一行（`usr/default_cpio_list`）：

```
nod /dev/console 0600 0 0 c 5 1
```

意思是：字符设备（c）、主设备号 5、次设备号 1。这解释了为什么内核在**还没有任何
`/dev` 管理程序**的时候，就已经有一个能用的 `/dev/console`——它是打包进内核的那份
initramfs 里带的静态节点。

| 节点 | 类型 | 主:次 | 谁提供 |
|---|---|---|---|
| `/dev/console` | c | 5:1 | tty 层（`console` 设备） |
| `/dev/tty` | c | 5:0 | tty 层（当前终端） |
| `/dev/ttyS0` | c | 4:64 | 8250 串口驱动 + devtmpfs |
| `/dev/null` | c | 1:3 | mem 设备驱动 + devtmpfs |

## 为什么“节点”不用手工建

`/dev/console` 是打包带的，但一块新插入的 U 盘、一个刚初始化的串口，内核怎么让
`/dev` 里自动出现对应节点？答案是 `devtmpfs`：内核里有个 `kdevtmpfs` 线程，设备一
注册就往 `/dev` 里 mknod（主题四）。

## 代码位置

| 位置 | 内容 |
|---|---|
| `usr/default_cpio_list` | `nod /dev/console 0600 0 0 c 5 1`：builtin initramfs 带的节点 |
| `fs/char_dev.c` | 字符设备注册表（`cdev_add` / `chrdev_open`） |
| `drivers/base/devtmpfs.c:222` `handle_create()` | 设备出现时自动 mknod |
| `include/linux/major.h` | 那些著名主设备号的来历（`TTY_MAJOR`、`MEM_MAJOR`…） |
