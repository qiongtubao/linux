# 主题一 · 物理内存的三层记账：memblock → buddy → slab

## 你已知的

内存条就是一堆 RAM。程序要内存，得向操作系统申请；内核自己也要内存（每个进程的
`task_struct`、每个文件的 `dentry`、每个网络包……）。Linux 用**三层**分别管这三种需求。

## 三层

| 层 | 管理单位 | 给谁用 | 什么时候上位 |
|---|---|---|---|
| `memblock` | 物理地址区间 | 启动最早期的“谁占了哪段”账本 | 内核刚起来时唯一可用，buddy 就绪后退休 |
| buddy（伙伴系统） | 页（4K），按 2^order 成块 | 通用页分配：用户页、页缓存、DMA 缓冲 | `free_area_init()` 之后 |
| slab / slub | 对象（几十字节 ~ 几 KB） | 内核自己的小对象：`task_struct`、`inode`… | `kmem_cache_init()` 之后 |

为什么必须分三层？因为粒度差三个数量级：

- “这段内存被内核镜像占了” → 区间级（memblock）
- “要 4K 页给用户做缺页填充” → 页级（buddy）
- “要 256 字节放一个 `task_struct`” → 对象级（slab）

用页级去满足对象级会浪费（一个 256 字节对象占 4K 页 = 94% 浪费），于是需要 slab
把页切成等长槽位。

## 交班顺序（本系列已走过的路）

```
memblock（存下 E820/memblock 区间，启动期记账）
  └─ memblock_free_all()      ← 把空闲区间整批塞给 buddy（见 mm-core-init.md）
      └─ buddy（free_area[]，按 order 分链表）
          └─ kmem_cache_init() ← 建起第一批 slab 缓存（本站主题三）
              └─ kmalloc()/kmem_cache_alloc() 可用
```

## 三层各自的“账本”怎么看

| 想看什么 | 接口 | 例子 |
|---|---|---|
| 系统总内存/可用/缓存 | `/proc/meminfo` | `MemFree`、`Cached`、`Slab` |
| buddy 各 order 的空闲块 | `/proc/buddyinfo` | `Node 0, zone Normal 123 45 6 …` |
| 页级事件累计 | `/proc/vmstat` | `pgalloc_*`、`pgfree`、`pgscan_*`、`pgsteal_*` |
| slab 每种缓存的对象数 | `/proc/slabinfo` | `kmalloc-256`、`task_struct` |
| 每个 zone 的水位 | `/proc/zoneinfo` | `min/low/high` 与当前 `free` |

本站后面的实测（主题五）会把这些接口逐个读一遍。

## 代码位置

| 位置 | 内容 |
|---|---|
| `mm/memblock.c` | 早期区间记账 |
| `mm/mm_init.c` `memblock_free_all()` | 把空闲内存交给 buddy |
| `mm/page_alloc.c` | buddy 实现（`free_area`、`__rmqueue`、`__free_one_page`） |
| `mm/slub.c:8478` `kmem_cache_init()` | slab 自举（主题三） |
| `mm/vmscan.c` | 页回收（主题四） |
