# 主题五 · 实测：2G / 128M / 128M+写满，三种内存状态

三组启动，同一个内核，只看内存子系统。

## 三组实验

| | A：`-m 2G` | B：`-m 128M` | C：`-m 128M` + 往 tmpfs 写 100M |
|---|---|---|---|
| `MemTotal` | 2024684 kB | 92208 kB | 92208 kB |
| `MemFree` | 2003664 kB | 75460 kB | **2860 kB** |
| `MemAvailable` | 1986436 kB | 73728 kB | 1216 kB |
| `Cached` | 2148 kB | 2148 kB | **80124 kB** |
| `Slab` | 6872 kB | 5796 kB | — |
| `kswapd` 就绪 | 2.45s | 2.20s | 2.22s |
| `balance_pgdat` | 0 次 | 0 次 | **16 次**（100ms 内） |
| 直接回收 | 0 次 | 0 次 | **3 次** |
| `pgscan_*` / `pgsteal_*` | 0 | 0 | **仍然是 0** |
| 结局 | 空闲 | 空闲 | OOM 杀掉写文件的进程 |

打点输出（C 组）：

```
[latte] kswapd: node0 reclaim thread ready
[latte] balance_pgdat: order=0      ×16     （4.2558s ~ 4.3524s）
[latte] direct reclaim: order=0     ×3
Out of memory: Killed process 61 (busybox) total-vm:3492kB, anon-rss:1024kB,
              file-rss:0kB, shmem-rss:1452kB
```

## 发现一：rootfs 是 tmpfs，上限是 RAM 的一半

第一次压力实验里 `dd` 写到 40M 就停，没有报错。原因在 `/proc/mounts`：

```
rootfs / rootfs rw,size=1009404k,nr_inodes=252351 0 0
```

`size=` 是 tmpfs 的参数——**根文件系统是 tmpfs，不是 ramfs**（无 `root=`、无
`rootfstype=` 时 `init_rootfs()` 选 tmpfs）。tmpfs 默认总量 = RAM 的 50%，
128M 的机器就是 46M，所以写到 40M 就 `ENOSPC`。

这条直接影响所有“往根里写文件”的实验：**写进 `/` 的东西既占内存，又受 50% 上限约束。**

## 发现二：kswapd 忙了 16 次，却一页也没回收

| 计数 | 值 | 含义 |
|---|---|---|
| `balance_pgdat` | 16 次 | kswapd 确实被唤醒并进入回收循环 |
| `direct reclaim` | 3 次 | 分配路径上也真的自己扫过 |
| `pgscan_kswapd` / `pgscan_direct` | 0 | 但 LRU 上一页都没扫到 |
| `pgsteal_*` | 0 | 也没回收掉任何页 |
| 结局 | OOM | 最后只能杀进程 |

原因：**这台机器没有 swap**（`CONFIG_SWAP=y` 但没交换设备），而 `Cached` 里那 80M
是 tmpfs 页——没有 swap 就没法换出，于是它们不在可回收 LRU 上。内核“扫了一圈发现
没得回收”，直接掉进 OOM 分支。

一句话：**回收的前提是“页可丢弃或可换出”；两者都不成立时，回收只是空转。**

## 发现三：buddy 的“大块”是连续内存的镜子

```
2G      : Node 0, zone DMA32  … 2 1 484      ← order 10 有 484 块（约 1.9G 连续）
128M    : Node 0, zone DMA32  … 4 1  13      ← order 10 只有 13 块（约 52M）
写满后  : Node 0, zone DMA32  0 1 2 6 3 2 2 0 1 0 0   ← order≥6 全 0
```

`order 10` 那一列就是“还能凑出多大连续块”。写满 tmpfs 后高阶全变 0：不是总量没了
（`MemFree` 还剩 2.8M），而是**连续块没了**——高阶分配会失败，转向 compaction 或 OOM。

## 复现（三组）

```bash
cd /home/dong/Documents/github/linux
make -j16 bzImage
CMD="console=ttyS0 earlyprintk=serial nokaslr ignore_loglevel panic=1"

# A/B：只读 /proc，不制造压力
rm -rf /tmp/memdiag && cp -a bb_rootfs /tmp/memdiag
cat > /tmp/memdiag/init <<'EOF'
#!/bin/sh
mount -t proc none /proc; mount -t sysfs none /sys; mount -t devtmpfs none /dev
cat /proc/meminfo; cat /proc/buddyinfo
/bin/busybox sed -n '/^pg/p' /proc/vmstat
exec /bin/sh
EOF
chmod +x /tmp/memdiag/init
( cd /tmp/memdiag && find . | cpio -o -H newc --quiet ) > /tmp/bb_memdiag.cpio
timeout 30 qemu-system-x86_64 -kernel arch/x86/boot/bzImage -initrd /tmp/bb_memdiag.cpio \
  -append "$CMD" -nographic -m 2G   -no-reboot > /tmp/latte-mem2G.log 2>&1
timeout 30 qemu-system-x86_64 -kernel arch/x86/boot/bzImage -initrd /tmp/bb_memdiag.cpio \
  -append "$CMD" -nographic -m 128M -no-reboot > /tmp/latte-mem128M.log 2>&1

# C：挂一个 110M 的 tmpfs 写满，逼出回收与 OOM
rm -rf /tmp/oomtest && cp -a bb_rootfs /tmp/oomtest
cat > /tmp/oomtest/init <<'EOF'
#!/bin/sh
B=/bin/busybox
mount -t proc none /proc; mount -t sysfs none /sys; mount -t devtmpfs none /dev
$B mkdir -p /mnt; mount -t tmpfs -o size=110M none /mnt
$B dd if=/dev/zero of=/mnt/big bs=1M count=100
$B sed -n '/^MemFree\|^Cached/p' /proc/meminfo
cat /proc/buddyinfo
exec /bin/sh
EOF
chmod +x /tmp/oomtest/init
( cd /tmp/oomtest && find . | cpio -o -H newc --quiet ) > /tmp/bb_oomtest.cpio
timeout 60 qemu-system-x86_64 -kernel arch/x86/boot/bzImage -initrd /tmp/bb_oomtest.cpio \
  -append "$CMD" -nographic -m 128M -no-reboot > /tmp/latte-oom.log 2>&1
```
