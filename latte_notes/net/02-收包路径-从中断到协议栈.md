# 主题二 · 收包路径：从中断到协议栈

## 你已知的

网线/虚拟线收到一个包，最终你的程序 `recv()` 拿到数据。中间要经过：网卡 → 驱动 →
NAPI → 协议分发 → IP → 传输层 → socket。

## 七跳

```
① 网卡把包 DMA 进内存，触发 MSI-X 中断（virtio0-input.0）
② 中断处理只做一件事：napi_schedule()  ← 把 NAPI 实例挂进轮询队列
③ 软中断 NET_RX_SOFTIRQ → net_rx_action() → napi_poll()
④ 驱动回调 virtnet_poll(budget)          ← 打点
     └─ virtnet_receive()：从 virtqueue 取 buffer，构造 sk_buff
         └─ napi_gro_receive()（顺便做 GRO 合并）
⑤ netif_receive_skb() → __netif_receive_skb_core()   ← 打点
     按 skb->protocol（以太网类型）在 packet_type 链里找处理者
⑥ ip_rcv()                                ← 打点
     ├─ ip_rcv_core()：长度/校验和/版本检查
     ├─ netfilter PRE_ROUTING
     └─ ip_rcv_finish()：查路由 → 本机 or 转发
⑦ 本机：icmp_rcv() / udp_rcv() / tcp_v4_rcv()
     └─ 找到 socket → 放进 sk_receive_queue → 唤醒等在这个 socket 上的进程
```

## 为什么拆成“中断 + 轮询”两段

| 做法 | 问题 |
|---|---|
| 每个包一个中断，全部在中断上下文处理 | 高速网络下中断风暴，CPU 全花在进出中断 |
| 中断里什么都不做，全靠轮询 | 空闲时白白烧 CPU |
| **NAPI（两者结合）** | 中断只“叫一声”，随后在软中断里按 budget 批量收；没包了立刻停止轮询 |

`budget`（本次打点可见）就是“这一轮最多收多少个”，通常是 64。

## GRO：把多个小包合成一个大包

`napi_gro_receive()` 会把同一流的连续 TCP 包临时合并，让上层只处理一次。
它解释了为什么 `/proc/net/dev` 的收包数可能少于网卡实际收到的帧数。

## 本次打点会看到的顺序

```
[latte] virtnet_probe: ...          ← 驱动探测（一次）
[latte] virtnet_poll: budget=64     ← 每次 NAPI 轮询
[latte] netif_receive_skb: len=… proto=0x0800 dev=eth0   ← 每个包
[latte] ip_rcv: proto=1 len=…       ← 每个 IPv4 包（proto=1 是 ICMP）
```

`proto=0x0800` = IPv4；`ip_rcv` 里的 `proto=1` = ICMP（ping 用的协议）。
