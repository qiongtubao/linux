# 主题九 · GSO：188 次协议栈处理怎么变成 22 次

`net/08` 讲收包侧的合并（GRO）：186 个段 → 24 个 skb。
这篇讲发包侧的反向操作 **GSO**（Generic Segmentation Offload）：
让**一个 skb 代表好几个 TCP 段**，协议栈只处理一次，拆成帧的事推给后面。
实测里最有意思的一点：**它省的不是网线帧数，是协议栈处理次数**。

## 你已知的

- 发包只有一个汇聚点 `__dev_queue_xmit`（`net/06`）；
- GRO 在收侧把多个段粘进同一个 skb（`net/08`）；
- TCP 段有 MSS，通常 1440 字节载荷、MTU 1500。

## 内核里对应什么：谁在“假装”成一个包

```
write(fd, buf, 256KB)
 └─ tcp_sendmsg → 写队列（256KB 拆成若干 skb）
     └─ tcp_write_xmit → __tcp_transmit_skb()      net/ipv4/tcp_output.c:1448  ← 打点
         每个 skb 里可以装 N 个段：skb->len 很大，gso_size = MSS(1460)
         └─ ip_queue_xmit → __dev_queue_xmit（`net/06` 的打点）
             └─ validate_xmit_skb()                net/core/dev.c:3982        ← 打点
                 ├─ 设备支持 TSO（NETIF_F_TSO4）→ 大 skb 直接交给驱动
                 └─ 不支持 → skb_gso_segment()      net/core/dev.c:4006        ← 打点
                     └─ 拆成 188 个 1480 字节的帧 → virtnet_xmit（`net/06`）
```

`skb_shinfo(skb)->gso_size` 是关键字段：**非 0 就表示“这个 skb 是假的，
实际是 gso_size 大小的若干段”**。所以判断有没有 GSO，看 `gso` 比看 `len` 更准。

## 3 个打点

| 打点 | 位置 | 内容 |
|---|---|---|
| `tcp_transmit: len=… gso=…` | `net/ipv4/tcp_output.c` | TCP 每个要发出去的 skb（`gso=0` 表示真是单段） |
| `validate_xmit: len=… gso=… mtu=…` | `net/core/dev.c` | 交驱动前，带设备 MTU |
| `gso_software: len=… gso=…` | `net/core/dev.c` | 只有**设备吃不下**时才触发（软件分片） |

## 实测 A：`busybox nc` 分块写，GSO 几乎没有机会

guest `nc 10.0.2.2 10080 < /data.bin` 发 256KB：

```
tcp_transmit=188  validate_xmit=189  gso_software=1  dev_queue_xmit=189  virtnet_xmit=191
tcp_transmit: len=1024 gso=0   ×119
tcp_transmit: len=1460 gso=0   ×33
tcp_transmit: len=588  gso=0   ×32
```

`busybox nc` 每次只 `read()` 1024 字节再 `write()`，
于是 TCP 每次只拿到一小段数据，**188 个 skb 里 187 个是单段**（`gso=0`），
只有一次把两个段凑进了同一个 skb（`len=2974 gso=1460`，触发 1 次软件分片）。
**这不是 GSO 坏了，是没有可合并的东西**——和 `net/08` 里“ping 一轮一个包就没得 GRO”是同一件事。

## 实测 B：一次 `write(256KB)`，GSO 才真正生效

换成一个小程序，`connect()` 之后**一次 `write()` 推 256KB**：

```
[sendall] write(262144) returned 262144
  eth0:  ...  272408     188   ← TX 272408 字节 / 188 个帧

tcp_transmit=22  validate_xmit=26  gso_software=17  dev_queue_xmit=26  virtnet_xmit=188
```

| 阶段 | 次数 | 说明 |
|---|---|---|
| TCP 造出的 skb（`tcp_transmit`） | **22** | `len` 从 2920 到 **43800** |
| 交驱动前的 skb（`validate_xmit`） | 26 | 含几个控制包 |
| 其中触发**软件分片**的（`gso_software`） | **17** | `len=43854 gso=1460` 这种 |
| 真正交给驱动的帧（`virtnet_xmit`） | **188** | `len=1514` ×177 |

`tcp_transmit` 的长度分布直接说明 GSO：

```
      1 tcp_transmit: len=21735 gso=0
      1 tcp_transmit: len=26280 gso=0
      1 tcp_transmit: len=43800 gso=0
      2 tcp_transmit: len=30660 gso=0
      5 tcp_transmit: len=2920  gso=0
```

注意这里 `gso=0` 是**打点时机**造成的：`gso_size` 是在同一函数靠后的
`skb_shinfo(skb)->gso_size = tcp_skb_mss(skb);`（`net/ipv4/tcp_output.c:1622`）才写进去的，
而我们打在函数入口。所以 `tcp_transmit` 这一侧看 `len` 更可靠；
`validate_xmit` 那边就能看到 `gso=1460`，`len=43854` = 30 个段 + 54 字节头。

**所以 GSO 省掉的是协议栈的活**：TCP/IP 只处理 22 次，而不是 188 次；
但因为这台机器的 virtio-net **没有 TSO**（`gso_software` 触发 17 次），
最终网线上仍然是 **188 个 1480 字节的帧**，一个不多一个不少。

## 三个结论

1. **GSO 的收益是“少进协议栈”，不是“少发帧”**：`tcp_transmit` 22 次 vs `virtnet_xmit` 188 次。
   要让帧数真的变少，需要设备支持 TSO（`NETIF_F_TSO4`）；本次 virtio-net 不支持，
   所以 `validate_xmit_skb()` 用 `skb_gso_segment()` 软件拆开了——
   **大 skb 走完整条 TCP/IP 路径，只在最后一米才碎开**。
2. **`write()` 的粒度决定 GSO 效率**：`busybox nc` 的 1024 字节循环写了 188 个单段 skb，
   GSO 只碰到 1 次；一次 256KB `write()` 造出 22 个多段 skb。
   上层应用怎么写，直接决定下层能不能合并。
3. **GSO 与 GRO 是对称的一对**：GRO 在收侧“把多个段粘成一个 skb”，
   GSO 在发侧“让一个 skb 代表多个段”；中间那层网卡决定最终帧数。
   两者的共同前提都是“**手里同时有多个段**”——一个段谈不上合并。

## 复现

```c
/* sendall.c: 连上去之后一次 write() 把 N KB 全推出去 */
#define _GNU_SOURCE
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>
#include <arpa/inet.h>
#include <sys/socket.h>

int main(int argc, char **argv)
{
	const char *ip = argc > 1 ? argv[1] : "10.0.2.2";
	int port = argc > 2 ? atoi(argv[2]) : 10080;
	size_t total = (argc > 3 ? (size_t)atoi(argv[3]) : 256) * 1024;
	struct sockaddr_in sa;
	int fd;
	char *buf;
	ssize_t n;

	fd = socket(AF_INET, SOCK_STREAM, 0);
	if (fd < 0) { perror("socket"); return 1; }
	memset(&sa, 0, sizeof(sa));
	sa.sin_family = AF_INET;
	sa.sin_port = htons(port);
	inet_pton(AF_INET, ip, &sa.sin_addr);
	if (connect(fd, (struct sockaddr *)&sa, sizeof(sa)) < 0) {
		perror("connect");
		return 1;
	}
	buf = malloc(total);
	memset(buf, 'A', total);
	n = write(fd, buf, total);
	printf("[sendall] write(%zu) returned %zd\n", total, n);
	fflush(stdout);
	sleep(1);
	close(fd);
	return 0;
}
```

## 代码位置

| 位置 | 函数 | 做什么 |
|---|---|---|
| `net/ipv4/tcp_output.c:1448` | `__tcp_transmit_skb()` | TCP 生成待发 skb 的地方 |
| `net/ipv4/tcp_output.c:1622` | 同函数内 | `skb_shinfo(skb)->gso_size = tcp_skb_mss(skb)`，GSO 标记在这里落地 |
| `net/ipv4/tcp_output.c:2901` | `tcp_write_xmit()` | 从发送队列取 skb、算 MSS、决定发多少 |
| `net/core/dev.c:3982` | `validate_xmit_skb()` | 交驱动前检查：设备需不需要软件分片 |
| `net/core/dev.c:4006` | `skb_gso_segment()` 调用点 | 软件分片（本次触发 17 次） |
| `net/core/dev.c:4675` | `__dev_queue_xmit()` | 发包汇聚点（`net/06`） |
| `drivers/net/virtio_net.c` | `start_xmit()` | 每个帧一次（`net/06` 的 `virtnet_xmit`） |

## 一句话收尾

GRO 与 GSO 是一对镜像操作：一个在收侧“多段合一 skb”，一个在发侧“一 skb 当多段”。
两者都只能省**协议栈的处理器时间**，网线上到底多少个帧，最终由网卡的能力
（这次是“没有 TSO”）决定。
