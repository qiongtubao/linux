# 主题五 · 挂真根：等设备、认设备号、逐个文件系统试

## 你已知的

插上 U 盘不会立刻出现在系统里：要等驱动发现它、读分区表、再判断里面是 FAT 还是
ext4。开机挂根是同一件事，只是**没有第二次机会**——挂不上就 panic 停机。

## `prepare_namespace()` 的六个动作

| 顺序 | 动作 | 为什么必须先做 |
|---|---|---|
| 1 | 睡 `root_delay` 秒 | 机械盘/U 盘上电要几秒才响应，`rootdelay=5` 就是给它留时间 |
| 2 | `wait_for_device_probe()` | 等已注册设备的探测跑完，否则根设备的驱动还在 probe 中途 |
| 3 | `md_run_setup()` | 根在软 RAID 上：先把阵列组起来，否则根本看不到 `/dev/mdX` |
| 4 | `parse_root_device(root=)` | 把 `root=/dev/sda2`、`root=/dev/nfs` 变成 `ROOT_DEV` |
| 5 | `initrd_load()` | 老式 initrd 兼容路径（主题七）；返回 true 就跳过真根 |
| 6 | `wait_for_root()` + `mount_root()` | `rootwait` 时才轮询等设备出现，然后按 `ROOT_DEV` 挂 |

前四个动作都是“等/认”：等设备、等探测、等阵列、认设备号。因为挂载失败一次就直接
panic，所以这些准备全部前置。

## `mount_root()` 按 `ROOT_DEV` 分派

| `ROOT_DEV` | 走哪条路 | 说明 |
|---|---|---|
| `Root_NFS` | `mount_nfs_root()` | 走 `nfsroot=`，5→30 秒退避，最多 5 次重试 |
| `Root_CIFS` | `mount_cifs_root()` | CIFS 版，同样带重试 |
| `Root_Generic` | `mount_root_generic()` | `root=mtd/ubi` 这类 |
| `0` | 先试 `mount_nodev_root()` | 没给 `root=`：只有显式 `rootfstype=` 才试 tmpfs 这类 |
| 其它 | `mount_block_root()` | 造 `/dev/root`，再走通用挂载 |

`case 0` 里那句 `fallthrough` 是本次的关键：没给 `root=`、也没给 `rootfstype=`
时条件不成立，直接掉进 `default`（当块设备挂）。

## `mount_root_generic()`：两轮重试

1. **列文件系统**：给了 `rootfstype=` 就只用它，否则列出所有块设备文件系统全试。
2. **逐个试挂**：
   - 成功 → 走人；
   - `-EACCES` / `-EINVAL` → “这个 fs 不认这块设备”，换下一个；
   - 其它错误 → 打印 `VFS: Cannot open root device ...` + 分区表 + 可用 fs 列表，
     **立即 panic**。
3. **一轮全失败**：若还没只读，加 `SB_RDONLY` `goto retry` 再来一轮（“也许只是脏了，
   只读能挂上”）。
4. **只读也全失败**：打印试过的 fs 列表，`panic("No filesystem could mount root, tried:")`。

两个 panic 文案对应两个层次：`Unable to mount root fs on ...` 是“设备/超级块层面
打不开”，`... tried: ...` 是“设备能开、但没有一个 fs 认它”。

## 本次实际走的路径

没有 `root=`，于是 `ROOT_DEV == 0`、`root_device_name == NULL`：

```
case 0 → 条件为假 → fallthrough
  → mount_block_root(NULL)
      → create_dev("/dev/root", 0)        ← 造出 0:0 的设备节点
      → mount_root_generic("/dev/root", NULL, root_mountflags)
          → 打开设备失败（-ENXIO）→ 立即 panic
```

实测里 `error -6` 就是 `-ENXIO`，所以第 3 步的“只读重试”根本没发生——日志见主题七。
