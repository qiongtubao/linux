# 主题六 · 换根：新根怎么变成 `/`

## 你已知的

Linux 只有一棵目录树。挂一个 U 盘到 `/mnt` 只是给树加了个分支；而“把磁盘上的根
当成 `/`”是**换掉树根**。两者不是一回事。

## 内核的做法：先挂 `/root`，成功后再整体挪

```c
/* do_mount_root()：挂在 /root，不直接挂 / */
ret = init_mount(name, "/root", fs, flags, data_page);
if (ret)
	goto out;
init_chdir("/root");
```

挂到 `/root` 而不是 `/` 的理由很实在：**挂失败时旧根还完整可用**，于是还能打印
分区表、报出 `unknown-block(0,0)` 这种线索（主题七）。直接挂 `/` 一旦失败，连
报错的现场都没了。

挂成功之后，在 `prepare_namespace()` 的 `out:` 做三件事：

```c
devtmpfs_mount();                            /* 给新根准备 /dev */
init_mount(".", "/", NULL, MS_MOVE, NULL);   /* 把新根挪到 / */
init_chroot(".");                            /* 进程的根切过去 */
```

| 语句 | 作用 |
|---|---|
| `devtmpfs_mount()` | 用**相对路径** `dev` 挂 devtmpfs；此刻 cwd 已经是 `/root`（新根），所以落在新根的 `/dev` 上 |
| `init_mount(".", "/", MS_MOVE)` | 把 cwd 上的那个挂载（新根）整体移到 `/`，覆盖原来的 rootfs |
| `init_chroot(".")` | 把进程的根目录切到新根，旧 rootfs 从命名空间里消失 |

三步用的都是 `init_*()`（`fs/init.c`），不是系统调用：init 阶段没有用户地址空间，
也不该占用文件描述符。

## 为什么不用 `pivot_root`

`pivot_root(2)` 是给**用户态程序**用的系统调用（老式 initrd 的 `linuxrc` 就用它把
initrd 换成 `/old`）。内核自己换根时更直接：`MS_MOVE` 把挂载点挪到 `/`，
`chroot` 切根，等价效果、少一层系统调用。

## initramfs 场景里这三步根本不跑

有 `/init` 时 `prepare_namespace()` 不会被调用（主题四），rootfs 自始至终就是 `/`，
`/init` 直接在它上面 `execve`。所以“换根”是**给块设备根、网络根准备的机制**。

反过来它还是个诊断信号：一旦 `mount_root()` panic，`out:` 永远到不了，于是
`[latte] prepare_namespace: devtmpfs + switch root` 这条打点必然缺失——**缺哪条打点，
就是死在哪一步**。

## 三种“根”的关系

| 概念 | 谁创建 | 什么时候是 `/` |
|---|---|---|
| rootfs（ramfs/tmpfs） | `init_rootfs()` | 内核一启动就是 |
| 真根（ext4/nfs/…） | `mount_root()` 挂到 `/root` | 挂成功后、换根前（还在 `/root`） |
| 换根之后 | `MS_MOVE` + `init_chroot()` | 真根成为 `/`，rootfs 退出 |

initramfs 的价值，就是在“rootfs 是 `/`”和“真根成为 `/`”这两个时刻之间，提供一个
能跑 `/init` 的落脚点。
