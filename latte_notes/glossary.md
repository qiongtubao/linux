# 术语表（先扫一遍再读主题文档）

每条一句话，按“硬件 → 存储 → 文件系统 → 内存 → 启动 → 进程”排。

## 硬件与固件

| 术语 | 一句话 |
|---|---|
| BIOS / UEFI | 主板上电后跑的第一段程序：自检硬件，然后找可启动的设备（磁盘、网卡、光驱） |
| bootloader（GRUB 等） | BIOS 找到启动盘后跑的下一段程序：把内核读进内存、把 initrd 一并递过去、然后跳进内核 |
| boot protocol | bootloader 与内核之间的交接约定：内核放哪、initrd 放哪、命令行字符串在哪 |
| bzImage | 压缩过的内核镜像文件（`arch/x86/boot/bzImage`），本次 QEMU 用 `-kernel` 直接加载它 |

## 存储：块设备与文件系统

| 术语 | 一句话 |
|---|---|
| 块设备 | 按“块”（通常 512 字节或 4K）随机读写的设备，硬盘/U 盘/虚拟盘都算；字符设备（键盘、串口）只能按字节流顺序读写 |
| 设备号 | 内核区分设备的编号：主设备号=哪类驱动，次设备号=这一类里的第几个 |
| 设备节点 | `/dev/sda2` 这种文件，本身不存数据，只记“主:次设备号”，打开它等于打开那块设备 |
| 分区 | 把一块磁盘切成几段，每段有起止位置；分区表在磁盘开头 |
| 文件系统 | 磁盘上数据的组织方式（ext4/xfs/fat…）：超级块 + inode + 目录 + 数据块 |
| 超级块 | 文件系统的“总目录”：块多大、inode 在哪、是否只读……挂载时要先读它 |
| 挂载（mount） | 把某个文件系统“接”到目录树的一个点上，之后访问那个目录就等于访问那个文件系统 |
| 挂载点 | 被接上去的目录；本次内核先把真根挂到 `/root`，再整体挪到 `/` |
| 根文件系统 | 挂在 `/` 上的那个文件系统，也就是“整套目录树的起点” |
| `root=` | 内核命令行参数：告诉内核根文件系统在哪（`/dev/sda2`、`/dev/nfs`、`9p`…） |
| `rootfstype=` | 显式指定根的文件系统类型，省得内核一个个试 |
| `rootwait` / `rootdelay` | 等根设备的两种方式：前者轮询等出现，后者先睡几秒 |

## 内存：RAM 与内存里的文件系统

| 术语 | 一句话 |
|---|---|
| 页（page） | 内核管理内存的最小单位，x86 通常是 4K |
| 页缓存 | 内核把文件内容缓存在内存里的那一份；写读都先过它 |
| buddy 分配器 | 内核的物理内存分配器：按 2 的幂管理空闲页块，分配/释放都成对 |
| memblock | 启动最早期用的简易内存记账器，buddy 就绪后交班 |
| 保留区（reserved region） | 被 memblock 标记“别动”的内存，比如内核镜像、initrd；用完了要显式还回去 |
| ramfs | 完全活在内存里的文件系统：目录和文件都在页缓存里，不落盘，重启就没 |
| tmpfs | 带 swap 和大小限制的 ramfs 升级版；两者都可能当 rootfs |
| rootfs | 内核启动时自动创建的第一个文件系统（ramfs 或 tmpfs），一开始就挂在 `/` |
| initramfs | 一个 cpio 归档（可再压缩），内核把它**解压进 rootfs**，于是内存里就有了一套目录树 |
| cpio | 一种“把很多文件打成一个流”的归档格式；initramfs 用的 newc 变体，每条目前有 110 字节头 |

## 启动：内核怎么把控制权交出去

| 术语 | 一句话 |
|---|---|
| `init`（1 号进程） | 内核启动的最后一个动作：`execve` 一个用户态程序，它就是 1 号进程 |
| `/init` | initramfs 里约定的第一个候选 init（等于内核变量 `ramdisk_execute_command` 的默认值） |
| `rdinit=` | 换掉上面那个默认值，比如 `rdinit=/bin/sh` |
| `init=` | 根文件系统里的 init 路径，`/init` 不存在时才会用到 |
| 老式 initrd | 一个**块设备镜像**：内核把它读进 `/dev/ram0` 挂起来，然后 chroot 进去跑 `/linuxrc` |
| linuxrc | 老式 initrd 里的那个“微型 init”，负责找到真正的根并告诉内核（`real-root-dev`） |
| `prepare_namespace()` | 没有可用 `/init` 时，内核用来“挂真正的根并换根”的总入口 |
| 换根 | 把新挂上的根挪到 `/` 并 chroot 进去；老式说法叫 `pivot_root` 的近亲（这里是 `MS_MOVE` + `chroot`） |
| panic | 内核遇到无法继续的错误时停机的动作；init 相关的两条是“挂不上根”和“没有 init 可跑” |

## CPU 与进程

| 术语 | 一句话 |
|---|---|
| 内核态 / 用户态 | CPU 的两种特权级：内核态能碰所有硬件和内存，用户态只能通过系统调用请内核代劳 |
| 系统调用 | 用户态请求内核做事的入口；`execve` 就是其中之一 |
| `execve` | “把当前进程换成另一个程序”：加载新程序、重建地址空间、跳到它的入口 |
| 0 / 1 / 2 号进程 | idle（0 号，内核栈上的“进程”）、init（1 号，用户态起点）、kthreadd（2 号，内核线程总管） |
| 内核线程 | 只在内核态跑的“进程”，没有用户地址空间；1 号进程在 `execve` 之前也是这种状态 |
