# Linux 内核学习笔记（按领域组织）

笔记不按内核函数组织，而按**你在系统里看得见的东西**分领域：
启动、内存、磁盘与文件系统、CPU 与进程、设备与中断。
每个领域下面再分主题，一个主题一份文档，配代码里的中文注释和 `[latte]` 打点。

## 五个领域

| 领域 | 一句话解释 | 已有的文档 |
|---|---|---|
| **启动** | 按下电源后，谁把内核叫醒；内核把自己和外设准备到什么程度；最后把控制权交给谁 | `init-process.md`、`initramfs-rootfs.md`、`root-mount/01`、`04`、`06`、`07`、`execve/01`、`05` |
| **内存** | 三层记账（memblock/buddy/slab）、页分配与回收、内存里的“文件系统” | `mm-core-init.md`、`memory/01`~`05`、`swap/01`~`04`、`root-mount/03`、`execve/03` |
| **磁盘与文件系统** | 块设备/分区/文件系统/挂载，路径怎么解析成 inode，dentry 缓存 | `root-mount/02`、`05`、`execve/04`、`vfs/01`~`04`、`inode/01`~`04` |
| **CPU 与进程** | 0/1/2 号进程、内核态与用户态、`execve` 那一步跨过什么 | `init-process.md`、`root-mount/04`、`execve/02`、`06` |
| **设备与中断** | 设备号与 `/dev`、console 与 tty、printk 怎么落到串口、中断与 IDT | `devices/01`~`06`、`interrupts/01`~`05`、`tty/01`~`04` |

## 建议阅读顺序

1. `glossary.md` —— 先扫术语：块设备、文件系统、挂载、ramfs、内核态……
2. `mm-core-init.md` —— 内存先能用，这是启动的下限
3. `init-process.md` —— 1 号进程诞生、`__init` 段回收
4. `initramfs-rootfs.md` —— `/init` 是怎么被塞进 rootfs 的
5. `root-mount/` —— 反过来：**没有 `/init`** 时内核怎么挂真正的根（1 索引 + 7 篇）
6. `execve/` —— 找到 `/init` 之后：怎么把它变成用户态 1 号进程（1 索引 + 6 篇）
7. `devices/` —— 反身自问：这些日志和 `/dev` 节点是谁弄出来的（1 索引 + 6 篇）
8. `interrupts/` —— 硬件怎么打断内核：IDT 装表 → 进门 → 驱动 handler（1 索引 + 5 篇）
9. `memory/` —— 页怎么分配、对象怎么缓存、紧张时谁去回收（1 索引 + 5 篇）
10. `tty/` —— 终端行规程与信号：`Ctrl-C` 到底发给了谁（1 索引 + 4 篇）
11. `swap/` —— 让匿名页可回收：加一块交换区后回收从空转变真干活（1 索引 + 4 篇）
12. `vfs/` —— 路径怎么变成 inode：dentry 缓存与 drop_caches 实测（1 索引 + 4 篇）
13. `inode/` —— 一个文件多个名字：硬链接让 dentry+1 而 inode 不变（1 索引 + 4 篇）

## 每篇主题文档的固定骨架

1. **你已知的概念**：先用磁盘、内存、开机这些日常说法把问题讲清楚；
2. **内核里对应什么**：贴到具体数据结构、全局变量、函数；
3. **代码在哪**：`file:line`，方便对照源码；
4. **实测证据**：`[latte]` 打点日志，证明这条路真的这么走。

看不懂某篇时，先回 `glossary.md` 查词，再看这篇的“你已知的概念”那一节。
