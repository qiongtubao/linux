# 主题五 · 挂载传播：一次挂载怎么变成两份

`mount/01`~`04` 讲的是“一个挂载点怎么接进目录树”。这篇讲一个更绕的机制：
**你在 `/a` 底下挂了个东西，`/b` 底下自动也多出来一个**——因为 `/a` 和 `/b` 属于同一个
**peer group（对等组）**。这是容器里 bind mount 会“漏”到别处（或不会漏）的根源。

## 你已知的

- `mount()` = 建 superblock + 造一个 `vfsmount` 接到树上（`mount/01`）；
- 每个挂载点在挂载树里有唯一位置，跨挂载点解析靠 `follow_managed`（`mount/03`）；
- 挂载点两侧 `st_dev` 不同，是“换了一棵树”的标志（`mount/04`）。

## 内核里对应什么：树 + 对等组

每个 `mount` 结构有两个关键字段（`fs/mount.h`）：

| 字段 | 含义 |
|---|---|
| `mnt_group_id` | 所属 peer group 的编号；**0 表示不在任何组里**（private） |
| `mnt_share` | 同组所有成员的循环链表（自己也在里面） |

挂载时的两条代码路径：

```
mount(2) → 建好新 mount
 ├─ attach_recursive_mnt()          fs/namespace.c:2558   ← 打点
 │    把新 mount 接到父目录的挂载树上
 │    若父 mount 在某个 peer group 里 → 继续传播
 └─ propagate_mnt()                 fs/pnode.c:312        ← 打点
      遍历 dest_mnt 的 mnt_share 列表，
      给**组里每一份**都复制一个对应的 mount（copy_tree）
```

所以“传播”不是“多个挂载点共享同一个 mount”，而是**多份 mount 被一起创建**：
`/a/sub` 和 `/b/sub` 是两个不同的 `mount`（`/proc/self/mountinfo` 里 id 不同），
但它们的父分别是 `/a` 和 `/b`，而后两者在同一个 peer group 里。

标记由 `mount(2)` 的 `MS_SHARED` / `MS_PRIVATE` / `MS_SLAVE` / `MS_UNBINDABLE` 控制，
`mount -o rshared` 就是 `MS_SHARED|MS_REC`。

## 2 个打点

| 打点 | 位置 | 内容 |
|---|---|---|
| `attach_mnt: src_group=… moving=…` | `fs/namespace.c` | 新 mount 属于哪个组（0=private） |
| `propagate_mnt: dest_group=… peers=…` | `fs/pnode.c` | 传播落点：父 mount 的组号与当前 peer 数 |

## 实测：shared 会传播，private 不会

A 组（`rshared` + bind）：`/a` 设为 shared，bind 成 `/b`，再往 `/a/sub` 上挂 tmpfs。

```
--- mounts A ---
none /a     tmpfs rw,relatime 0 0
none /b     tmpfs rw,relatime 0 0
none /a/sub tmpfs rw,relatime 0 0
none /b/sub tmpfs rw,relatime 0 0        ← 没人挂它，自己出现了

--- mountinfo A ---
24 2 0:21 / /a     rw,relatime shared:1 - tmpfs none rw
25 2 0:21 / /b     rw,relatime shared:1 - tmpfs none rw      ← 同组 shared:1
26 24 0:22 / /a/sub rw,relatime shared:2 - tmpfs none rw
27 25 0:22 / /b/sub rw,relatime shared:2 - tmpfs none rw     ← 复制出来的第二份
```

B 组（`private` + bind）：同样的操作，只是把 `/a`→`/c`、`/b`→`/d`，并把 `/c` 设为 private。

```
--- mounts B ---
none /c     tmpfs rw,relatime 0 0
none /d     tmpfs rw,relatime 0 0
none /c/sub tmpfs rw,relatime 0 0
                                          ← 没有 /d/sub

--- mountinfo B ---
28 2 0:23 / /c     rw,relatime - tmpfs none rw     ← 没有 shared: 标记
29 2 0:23 / /d     rw,relatime - tmpfs none rw
30 28 0:24 / /c/sub rw,relatime - tmpfs none rw
```

打点（整机日志，A、B 两段都在里面）：

```
[latte] attach_mnt: src_group=1 moving=0        ← bind /a→/b，源在组 1
[latte] propagate_mnt: dest_group=1 peers=1     ← 唯一一次传播
...（B 组 private 阶段：一条 propagate_mnt 都没有）
```

三个证据互相对齐：

1. `mountinfo` 里 `/a` 与 `/b` 都标 **`shared:1`** —— 同一个 peer group；
2. `/b/sub` **不请自来** —— 传播确实发生了；
3. `propagate_mnt` 打点**只出现 1 次**（A 组），B 组一次都没有 —— private 的 mount
   `mnt_group_id=0`，`attach_recursive_mnt` 根本不会去调传播。

（`peers=1` 是打点时刻的瞬时值：打印发生在传播循环之前，此时新 peer 还没串进
`mnt_share`。判断“有几个成员”以 `mountinfo` 的 `shared:` 标记为准。）

## 三个结论

1. **传播 = 复制 mount，不是共享 mount**：`/a/sub` 与 `/b/sub` 的 mount id 是 26 和 27，
   两份独立的 `struct mount`；它们的父分属同一个 peer group。
   所以 umount 一侧也有对应逻辑（`propagate_umount`），否则树会不平衡。
2. **默认是 private，一旦设成 shared 就会“漏”**：`mnt_group_id=0` 时
   `propagate_mnt` 一次都不调（B 组实测 0 次）。这正是容器默认把挂载设成
   private/slave 的原因——不设的话，容器里的挂载会跑回宿主机的同名挂载点。
3. **slave 是“只收不发”的那个标记**：shared 双向、slave 单向（收别人传播过来的，
   不往外传）。本篇没有实测 slave 分支，因为需要两个 mount namespace
   （`unshare -m`）才能造出“上游”，而 busybox 没有 `unshare`——这是下一篇的事。

## 复现

```c
/* mntprobe.c: mount(2) 的薄封装，只为看清传播标记 */
#define _GNU_SOURCE
#include <stdio.h>
#include <string.h>
#include <errno.h>
#include <sys/mount.h>

static int do_mount(const char *src, const char *tgt, const char *type,
		    unsigned long flags)
{
	if (mount(src, tgt, type, flags, NULL) < 0) {
		fprintf(stderr, "mount(%s,%s,%s,0x%lx): %s\n",
			src ? src : "-", tgt, type ? type : "-", flags,
			strerror(errno));
		return 1;
	}
	return 0;
}

int main(int argc, char **argv)
{
	const char *op = argc > 1 ? argv[1] : "";

	if (!strcmp(op, "tmpfs") && argc > 2)
		return do_mount("none", argv[2], "tmpfs", 0);
	if (!strcmp(op, "shared") && argc > 2)
		return do_mount(NULL, argv[2], NULL, MS_SHARED | MS_REC);
	if (!strcmp(op, "private") && argc > 2)
		return do_mount(NULL, argv[2], NULL, MS_PRIVATE | MS_REC);
	if (!strcmp(op, "bind") && argc > 3)
		return do_mount(argv[2], argv[3], NULL, MS_BIND | MS_REC);
	fprintf(stderr, "usage: mntprobe tmpfs|shared|private <dir> | bind <src> <dst>\n");
	return 2;
}
```

两个顺序细节决定了实验能不能成：

- **`/a/sub` 必须先 `mkdir` 再 `bind`**：bind 会把当时的子树一起复制过去，
  如果 `/b/sub` 还不存在，后面的传播就没有落点。
- **`/c/sub` 要在 `private` 之前建好**：private 之后新挂的东西不会传播，
  但目录本身还是要在，否则挂载直接失败。

## 代码位置

| 位置 | 符号 | 做什么 |
|---|---|---|
| `fs/namespace.c:2558` | `attach_recursive_mnt()` | 把新 mount 接到父目录的树上，并决定是否传播 |
| `fs/pnode.c:312` | `propagate_mnt()` | 给同组每一份复制一个挂载 |
| `fs/pnode.c` | `propagate_umount()` | umount 时对称地撤掉复制品 |
| `fs/mount.h:68` | `mnt_share` | 同组循环链表（peer group 的成员） |
| `fs/mount.h:87` | `mnt_group_id` | 组号，0 = private |
| `/proc/self/mountinfo` | `shared:N` / `master:N` | 每个挂载点的组号与上游（slave 才有 master） |

## 一句话收尾

挂载传播的全部机制就是一张表：**mount 有个组号，组里有几个成员，
挂一个东西就给每个成员复制一份**。shared 双向、slave 单向、private 不参与。
容器挂载“漏不漏”，取决于这张表里的组号。
