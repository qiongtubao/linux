# 主题三 · 控制终端与会话：Ctrl-C 到底发给谁

## 你已知的

一个终端上可以同时跑很多程序（前台一个、后台若干）。`Ctrl-C` 只该打断**前台**那个。
要做到这点，内核需要知道两件事：**这个终端属于哪个会话**、**现在谁在前台**。

## 三个层次

| 层次 | 是什么 | 谁维护 |
|---|---|---|
| 会话（session） | 一组进程的“登录会话”，一个会话最多一个控制终端 | `setsid()` 创建 |
| 进程组（pgrp） | 会话里再分组，作业控制的单位（前台/后台） | `setpgid()`、shell 的 job control |
| 控制终端（ctty） | 会话绑定的那个 tty；`tty_struct.ctrl.session` / `.pgrp` | `TIOCSCTTY`，或 session leader 首次 `open()` |

`Ctrl-C` 的投递路径只看最后一项：

```c
static void __isig(int sig, struct tty_struct *tty)
{
	struct pid *tty_pgrp = tty_get_pgrp(tty);   /* ← 读 tty->ctrl.pgrp */
	if (tty_pgrp) {
		kill_pgrp(tty_pgrp, sig, 1);
		put_pid(tty_pgrp);
	}
	/* 没有 pgrp：什么也不做，连日志都不打 */
}
```

所以“Ctrl-C 没反应”几乎总是同一件事：**这个 tty 上没有前台进程组**。

## 本次实测暴露的两个坑

### 坑一：initramfs 里的 sh 根本没有控制终端

1 号进程由内核用 `user_mode_thread()` 直接创建，既没 `setsid()`，也没 `open()` 过任何
tty。于是它起的 `sh`：

- 没有控制终端 → `tty->ctrl.pgrp` 为空；
- 打 `Ctrl-C`：`isig` 照样触发（字节被认成 `INTR_CHAR` 了），但 `__isig` 打印
  `pgrp=none`，信号无处可投；
- 结果：命令停不下来，只能等它自己结束或被 `timeout` 杀掉（实测 `rc=143`）；
- shell 开头那句 `can't access tty; job control turned off` 说的就是这件事。

### 坑二：`/dev/console` 与 `/dev/ttyS0` 是两个 tty_struct

第一次修复尝试把控制终端建在 `/dev/console`（5:1）上，结果依然是 `pgrp=none`。
原因：**字符是从 `/dev/ttyS0`（4:64）进来的**，行规程跑在 ttyS0 的 `tty_struct` 上，
而控制终端记在 console 那个 `tty_struct` 上——两个对象，各记各的前台进程组。

把控制终端改建在 `/dev/ttyS0` 上，立刻成功：

```
[latte] __isig: sig=2 pgrp=set
p2b-rc=130            ← 128 + SIGINT(2)，cat 被 Ctrl-C 杀死
```

## 三种场景对照（真实数据）

| 场景 | `tty_get_pgrp()` | `cat` 的结局 |
|---|---|---|
| 无控制终端（init 直接 `cat`） | `none` | 只能被 `timeout` 杀 → `rc=143` |
| ctty 建在 `/dev/console` | `none`（字符走 ttyS0） | 同样收不到信号 |
| ctty 建在 `/dev/ttyS0` | `set` | `Ctrl-C` 生效 → `rc=130` |

## 正确的“建控制终端”写法

```sh
setsid sh -c 'exec </dev/ttyS0 >/dev/ttyS0 2>&1; exec /bin/cat'
```

- `setsid`：新会话、成为 session leader；
- `exec < /dev/ttyS0`：session leader 首次 `open()` 一个 tty（不带 `O_NOCTTY`）→
  这个 tty 成为它的控制终端；
- 之后 `Ctrl-C` 才能通过 `tty_get_pgrp()` 找到前台进程组。
