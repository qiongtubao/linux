# 主题一 · 中断是什么：硬件怎么“打断”CPU

## 你已知的

按键、网线来包、磁盘读完——CPU 并不知道这些事什么时候发生。如果靠程序不停去问
（轮询），要么慢要么费电。**中断**就是反过来：设备有事就“打断”CPU，CPU 放下
手头的活去处理，处理完再回来。

## 三种“打断”，别混

| 类型 | 谁发起 | 例子 | 向量号 |
|---|---|---|---|
| 异常（exception） | CPU 自己 | 除零、`#PF` 缺页、`#GP` 非法指令 | 0–31 |
| 系统调用 | 用户程序主动 | `syscall` 指令进内核 | 由 syscall 机制分配，有独立入口 |
| 硬件中断（IRQ） | 外部设备 | 串口收到字节、定时器到点、网卡收到包 | 32 起（外部） |

本次实验里的时钟、串口都属于第三类；`#PF` 属于第一类，它们**共用同一张表**。

## 硬件中断的物理路线

```
设备（UART/定时器/网卡）
  │  拉高一条 IRQ 线
  ▼
中断控制器（老式 8259、现代 IO-APIC / 本地 APIC）
  │  挑一个“向量号”，把 CPU 打断
  ▼
CPU：保存现场 → 按向量号查 IDT → 跳到处理函数
```

- **IRQ 线**是物理连线（或 APIC 里的虚拟线），每设备一条，可共享；
- **中断控制器**负责排队、屏蔽、优先级，并决定用哪个向量号；
- **IDT（中断描述符表）**是 CPU 唯一认识的表：第 N 项就是“向量 N 该跳哪儿”。

## IDT 长什么样

256 项，每项 16 字节的“门描述符”（gate descriptor）：

| 字段 | 作用 |
|---|---|
| 偏移（offset） | 处理函数入口地址（分两段拼） |
| 段选择子（segment） | 通常 `__KERNEL_CS` |
| 类型（type） | 中断门 / 陷阱门 / 任务门 |
| DPL | 权限级：0 表示只有内核能 `int n` 触发 |

**中断门 vs 陷阱门**的唯一实质区别：中断门进去时 CPU 自动关中断（IF=0），陷阱门
不关。所以设备 IRQ 用中断门（处理期间别被同级中断打断），`#BP`（断点）用陷阱门
（调试器要能继续单步）。

## 为什么还要“上半部 / 下半部”

中断处理时 CPU 在**中断上下文**里：不能睡眠、不能用会睡眠的锁、要尽快返回。
所以内核把活拆成两半：

| | 上半部（hardirq） | 下半部（softirq / tasklet / workqueue） |
|---|---|---|
| 什么时候跑 | 中断发生立刻 | 中断返回后、或线程里 |
| 能睡眠吗 | 不能 | softirq 不能，workqueue 可以 |
| 典型活 | 读设备状态、清中断标志、拷到缓冲区 | 处理协议栈、唤醒等待者 |

本次实验的 `/proc/softirqs`（主题五）就是下半部的计数器。
