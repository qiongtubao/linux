# 主题一 · 什么时候换人：两种让出与抢占

进程不会自己“跑很久”——它要么**自己睡**（等 IO、等时间），要么**被人抢**
（时间片用完、被更高优先级的唤醒）。这两种情况在 `/proc/PID/status` 里
分别记成 `voluntary_ctxt_switches` 与 `nonvoluntary_ctxt_switches`。
这篇用两个打点把两者的区别钉死。

## 你已知的

- 进程状态 `R/S/D/T/Z` 的字母表（`jobs/01`）；
- `execve` 最后一跳 `iretq` 回用户态（`execve/05`）；
- 阻塞的东西（`sleep`、读管道、等锁）在内核里都是“把当前任务挂起，调 `schedule()`”。

## 内核里对应什么：一个 runqueue + 三种走向

每个 CPU 一个 runqueue（`struct rq`），调度器只从**队列里**挑下一个任务。
`sleep` 之所以不占 CPU，是因为它**根本不在队列里**。

```
try_to_wake_up()              kernel/sched/core.c:4144   ← 打点
 └─ 把任务从睡眠队列拉回 runqueue，必要时置 TIF_NEED_RESCHED

__schedule()                  kernel/sched/core.c:6784
 ├─ prev->state != RUNNING  → 阻塞：任务自己让出（从队列里摘掉）
 ├─ prev->state == RUNNING  → 抢占：还在队列里，但被要求让位
 └─ context_switch → switch_to：换内核栈、换页表、换寄存器

finish_task_switch()          kernel/sched/core.c:5150   ← 打点
 └─ 新任务视角：清理 prev（on_cpu、mm、rq->prev_mm），记 prev_state
```

`prev_state` 就是“上一个任务为什么让出”：`0`（`TASK_RUNNING`）表示被抢占，
非 0 就是自己睡（`TASK_INTERRUPTIBLE`=1、`TASK_UNINTERRUPTIBLE`=2……）。
`user_mode` 的时钟中断里若发现时间片用完，就只是置一个标志位，
真正切人还是走 `__schedule()`。

## 2 个打点，都必须带过滤

| 打点 | 位置 | 内容 |
|---|---|---|
| `wake: comm=… pid=… state=…` | `try_to_wake_up()` 入口 | 谁被唤醒、唤醒时的 state |
| `switch: prev(state=…) -> next` | `finish_task_switch()` 里 `prev_state` 之后 | 谁让出、为什么、谁接上 |

过滤条件写在代码里：

```c
	if (p->mm)                        /* 只打用户进程 */
		printk(KERN_INFO "[latte] wake: ...", p->comm, p->pid, p->__state);

	if (prev_state != TASK_RUNNING && prev->mm)   /* 只打“主动让出” */
		printk(KERN_INFO "[latte] switch: ...", ...);
```

**为什么必须过滤**：第一版不加条件，`try_to_wake_up()` 被 `rcu_preempt`、
`kworker` 这类内核线程反复命中，2 核启动**90 秒都没跑完**（串口 115200，
每条 `printk` 都是一次真实的串口写）。后来加了两条过滤 + 启动参数
`loglevel=3`（`KERN_INFO` 只进 ring buffer 不上控制台），启动回到 6 秒，
实验末尾用 `dmesg | grep latte` 一次性取证据。
这段弯路本身就是结论：**打点位置选错不会报错，只会让系统变慢**。

## 实测 A：`usleep(200ms)` 就是一次“自己让出”

探针进程 `schedprobe` 先 `usleep(200000)`，`dmesg` 里这一对打点挨着：

```
[    3.524987] [latte] wake: comm=schedprobe pid=65 state=0x0
[    3.526245] [latte] switch: schedprobe/65(state=0x2001) -> swapper/1/0
[    3.726667] [latte] wake: comm=schedprobe pid=65 state=0x2001
[    3.730368] [latte] wake: comm=schedprobe pid=65 state=0x0
```

三个细节都能读出含义：

- `switch` 到 `swapper/1/0`：让出后本 CPU 空闲（idle 任务）。
- `state=0x2001` = `TASK_INTERRUPTIBLE(0x1) | TASK_FREEZABLE(0x2000)`
  （`include/linux/sched.h:106`、`:122`）——`nanosleep` 用的就是“可被信号/冻结打断”的睡法。
- `3.726667 − 3.526245 = 0.2004 秒`：睡够 200ms 才被定时器唤醒，和参数对得上。
- 那次 `wake` 的 `state=0x2001` 是**睡眠中被唤醒**；后面几行 `state=0x0`
  是唤醒一个还在 runqueue 上的任务（信号、IPI 一类），不是睡眠唤醒。

进程自己看到的计数（`/proc/self/status`）：

```
[probe] start                      voluntary=0 nonvoluntary=1
[probe] after usleep 200ms         voluntary=1 nonvoluntary=1
```

`voluntary` +1，`nonvoluntary` 不动——**自己让出**只记前者。

## 实测 B：加一个竞争者，`nonvoluntary` 立刻涨

把父子两个进程都绑到 CPU 0（`sched_setaffinity`），一起忙等 500ms：

```
[probe] after usleep 200ms         voluntary=2 nonvoluntary=1
[probe] after 500ms contention     voluntary=2 nonvoluntary=128
```

500ms 里被**强制**换下 CPU **127 次**（≈ 每 4ms 一次）。这些切换在 `switch`
打点里看不到——因为 `prev_state == TASK_RUNNING`，被我们的过滤条件挡掉了，
正好对应“抢占的量级和主动让出不是一个数量级”（`sched/README` 里那句话）。

## 三个结论

1. **`voluntary` vs `nonvoluntary` 就是“谁让出”**：前者是自己调 `schedule()`
   睡下去（`state != RUNNING`），后者是还被标记为 RUNNING 却被要求让位。
   同一份 `/proc/PID/status` 里两个计数，含义完全不同。
2. **睡眠的进程不在 runqueue 里**：`usleep` 之后 `swapper` 才会被选中；
   `state` 字段（`0x2001`）说明它睡在“可中断 + 可冻结”的状态上，
   所以 `kill` 能把它提前叫醒（`jobs/05` 的信号投递就是在回用户态前插入）。
3. **抢占是常态，不是异常**：两个 CPU-bound 进程抢一个核，500ms 内 127 次抢占。
   所以“一个进程一直占着 CPU”在 CFS/EEVDF 下不成立，
   想看它拿了多少 CPU 要看 `utime`/`sum_exec_runtime`（见 `02`）。

## 复现

需要 `-smp 2`（单核下抢占对手只有自己，测不出 `nonvoluntary`）：

```c
/* schedprobe.c 的 a 模式：睡眠 vs 抢 CPU0 */
#define _GNU_SOURCE
#include <stdio.h>
#include <string.h>
#include <unistd.h>
#include <time.h>
#include <sched.h>
#include <sys/wait.h>

static void pin_cpu0(void)
{
	cpu_set_t s;
	CPU_ZERO(&s);
	CPU_SET(0, &s);
	sched_setaffinity(0, sizeof(s), &s);
}

static void ctxt(const char *tag)
{
	FILE *f = fopen("/proc/self/status", "r");
	char line[256];
	unsigned v = 0, nv = 0;

	if (!f) return;
	while (fgets(line, sizeof(line), f)) {
		if (sscanf(line, "voluntary_ctxt_switches: %u", &v) == 1) continue;
		if (sscanf(line, "nonvoluntary_ctxt_switches: %u", &nv) == 1) continue;
	}
	fclose(f);
	printf("[probe] %-26s voluntary=%u nonvoluntary=%u\n", tag, v, nv);
}

static void spin_ms(int ms)
{
	struct timespec t0, t1;
	long i;

	clock_gettime(CLOCK_MONOTONIC, &t0);
	for (;;) {
		for (i = 0; i < 20000; i++) __asm__ volatile("" ::: "memory");
		clock_gettime(CLOCK_MONOTONIC, &t1);
		if ((t1.tv_sec - t0.tv_sec) * 1000 + (t1.tv_nsec - t0.tv_nsec) / 1000000 >= ms)
			break;
	}
}

int main(void)
{
	pid_t pid;

	ctxt("start");
	usleep(200000);
	ctxt("after usleep 200ms");

	pin_cpu0();
	pid = fork();
	if (pid == 0) { pin_cpu0(); spin_ms(500); _exit(0); }
	spin_ms(500);
	waitpid(pid, 0, 0);
	ctxt("after 500ms contention");
	return 0;
}
```

## 代码位置

| 位置 | 函数 | 做什么 |
|---|---|---|
| `kernel/sched/core.c:4144` | `try_to_wake_up()` | 唤醒：把任务放回 runqueue |
| `kernel/sched/core.c:6784` | `__schedule()` | 调度主循环：选下一个、调 `context_switch` |
| `kernel/sched/core.c:5150` | `finish_task_switch()` | 切换完成：清理 prev，`prev_state` 记让出原因 |
| `include/linux/sched.h:105` | `TASK_*` 常量 | `0x0`=RUNNING、`0x1`=INTERRUPTIBLE、`0x2000`=FREEZABLE |
| `/proc/PID/status` | `voluntary_ctxt_switches` | 自己让出的次数 |
| `/proc/PID/status` | `nonvoluntary_ctxt_switches` | 被抢占的次数 |

## 一句话收尾

`sleep` 不占 CPU，是因为它离开了 runqueue；被抢占不丢 CPU 时间，
只是换了一次“谁在跑”。这两种切换在 `prev_state` 里分得清清楚楚，
也是下一篇“公平性”要处理的两种不同代价。
