# 主题五 · 多核负载均衡：任务怎么被搬到别的核

`sched/01`~`04` 都是“单核上谁先跑”。这篇换 4 核：**任务怎么被放到某个核上，
什么时候会被搬走**。实测里最反直觉的一点：8 个忙循环跑 4 个核，
**稳态一次都没搬**——负载均衡是“纠正失衡”，不是“轮流跑”。

## 你已知的

- 两种让出（`sched/01`）、nice 是权重（`sched/02`）、cgroup 份额（`03`）、RT 抢占（`04`）；
- 每个核有自己的 runqueue；
- `/proc/stat` 的 `cpuN` 行是每个核的 tick 计数，`/proc/PID/stat` 的第 39 个字段是“上次跑在哪个核”。

## 内核里对应什么：三条放置路径 + 一个执行者

```
① 唤醒放置：select_task_rq_fair()        kernel/sched/fair.c:8566
    新任务/被唤醒时，按负载与亲和性选一个核（wake_affine：能原地就别搬）

② 周期均衡：sched_balance_domains()      kernel/sched/fair.c:12192
             → sched_balance_rq()        kernel/sched/fair.c:11736
    按调度域逐级检查“我比邻居忙多少”，超阈值就把任务拉过来

③ 新空闲：sched_balance_newidle()        kernel/sched/fair.c:12786
    一个核要变空闲时，先看看能不能从别的核偷一个任务
```

①②③ 的结论最后都落到同一个函数改归属：

```
set_task_cpu(p, new_cpu)                 kernel/sched/core.c:3286   ← 打点
  旧 CPU → 新 CPU；同时更新 p->wake_cpu、rq->nr_running 等
```

所以“迁移”在代码里只有一处，但在 **逻辑上有三种原因**（初始放置、周期纠偏、空闲偷取）。

## 1 个打点

| 打点 | 位置 | 内容 |
|---|---|---|
| `migrate: comm=… pid=… 旧->新` | `set_task_cpu()` | **只在旧核≠新核时打**，所以它只记“真实的搬迁” |

不打全部：`set_task_cpu` 在唤醒密集时段被调用得很频繁，但其中大部分是 `old == new`
（只是确认归属），打出来全是噪声。

## 实测：4 核，先 4 个忙循环，再 8 个

每个忙循环自己用 `sched_getcpu()` 观察自己被搬到别的核几次（`moves`），
并读自己的 `utime`；`/proc/stat` 记录每个核的 user tick。

**A 组：4 个任务 / 4 个核 / 2 秒**

```
[smp] pid=81 cpu=0 moves=0 utime=200 ticks
[smp] pid=83 cpu=3 moves=0 utime=199 ticks
[smp] pid=84 cpu=1 moves=0 utime=199 ticks
[smp] pid=82 cpu=2 moves=0 utime=199 ticks

/proc/stat  cpu0 user 2 → 202 (+200)   cpu1 0 → 201 (+201)
            cpu2 2 → 202 (+200)        cpu3 0 → 200 (+200)
```

四个任务恰好落在四个不同的核上，每个拿到 **200 ticks = 2 秒满速**，
`/proc/stat` 每核也正好 +200 —— 并行度等于核数，一分不多。

**B 组：8 个任务 / 4 个核 / 2 秒**

```
[smp] pid=87 cpu=0 moves=0 utime=100    [smp] pid=94 cpu=0 utime=99
[smp] pid=90 cpu=1 moves=0 utime=99     [smp] pid=91 cpu=1 utime=99
[smp] pid=88 cpu=2 moves=0 utime=100    [smp] pid=92 cpu=2 utime=99
[smp] pid=89 cpu=3 moves=0 utime=100    [smp] pid=93 cpu=3 utime=99

/proc/stat  cpu0 +199   cpu1 +198   cpu2 +198   cpu3 +198
```

8 个任务两两分到 4 个核，每个 100 ticks（正好一半），每核仍 +200 ——
**加任务只增加分时，不增加并行度**。

**迁移打点**（整机 89 次，含内核线程）：

```
migrate: comm=rcu_preempt pid=15 3->2       ← 内核线程也在搬
migrate: comm=smpbench pid=81 0->2          ← 应用进程只在启动瞬间搬
migrate: comm=smpbench pid=82 2->3
migrate: comm=kworker/u16:0 pid=12 0->3
migrate: comm=smpbench pid=91 1->2
migrate: comm=smpbench pid=89 3->1
```

注意 smpbench 的那几条都发生在 **fork 之后的头几毫秒**（初始放置还在收敛），
稳态运行期间一条都没有——和用户态 `moves=0` 完全一致。

## 三个结论

1. **并行度 = 核数，不是任务数**：4 任务 4 核各 200 ticks；8 任务 4 核各 100 ticks，
   每核总数不变。想提高吞吐只能加核，加任务只会摊薄。
2. **负载均衡是“纠偏”，不是“轮流跑”**：稳态 `moves=0`，迁移打点里没有稳态期的搬迁。
   内核只在“核间负载差超过阈值”或“空核想偷活”时才动手，
   均衡之后大家各跑各的，不会周期性地搬来搬去。
3. **看整机迁移率要排除内核线程**：89 次迁移里大部分是 `rcu_preempt`、`kworker`
   这类 per-CPU 内核线程（它们本来就该被搬来搬去）。
   判断“应用有没有被频繁迁移”，必须按 `comm` 过滤。

## 复现

```c
/* smpbench <n> <ms>: n 个忙循环，各自统计被搬核次数（sched_getcpu 变化） */
#define _GNU_SOURCE
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>
#include <time.h>
#include <sched.h>
#include <sys/wait.h>

static unsigned long utime_ticks(void)
{
	FILE *f = fopen("/proc/self/stat", "r");
	char buf[1024], *p;
	unsigned long ut = 0;
	int i = 0;

	if (!f) return 0;
	if (!fgets(buf, sizeof(buf), f)) { fclose(f); return 0; }
	fclose(f);
	p = strrchr(buf, ')');
	if (!p) return 0;
	p++;
	while (*p && i < 13) {
		while (*p == ' ') p++;
		if (!*p) break;
		i++;
		if (i == 12) { ut = strtoul(p, 0, 10); break; }
		while (*p && *p != ' ') p++;
	}
	return ut;
}

static void spin_report(int ms)
{
	struct timespec t0, t1;
	int cpu = sched_getcpu();
	int moves = 0, cur;
	long i;

	clock_gettime(CLOCK_MONOTONIC, &t0);
	for (;;) {
		for (i = 0; i < 20000; i++) __asm__ volatile("" ::: "memory");
		cur = sched_getcpu();
		if (cur != cpu) { moves++; cpu = cur; }
		clock_gettime(CLOCK_MONOTONIC, &t1);
		if ((t1.tv_sec - t0.tv_sec) * 1000 + (t1.tv_nsec - t0.tv_nsec) / 1000000 >= ms)
			break;
	}
	printf("[smp] pid=%d cpu=%d moves=%d utime=%lu ticks\n",
	       getpid(), sched_getcpu(), moves, utime_ticks());
	fflush(stdout);
}

int main(int argc, char **argv)
{
	int n = argc > 1 ? atoi(argv[1]) : 4;
	int ms = argc > 2 ? atoi(argv[2]) : 2000;
	pid_t *pids = calloc(n, sizeof(pid_t));
	int i;

	fflush(stdout);
	for (i = 0; i < n; i++) {
		pids[i] = fork();
		if (pids[i] == 0) { spin_report(ms); _exit(0); }
	}
	for (i = 0; i < n; i++)
		waitpid(pids[i], 0, 0);
	return 0;
}
```

## 代码位置

| 位置 | 符号 | 做什么 |
|---|---|---|
| `kernel/sched/fair.c:8566` | `select_task_rq_fair()` | 唤醒/新建任务时选核（wake_affine） |
| `kernel/sched/fair.c:11736` | `sched_balance_rq()` | 周期均衡的主力：算失衡、拉任务 |
| `kernel/sched/fair.c:12192` | `sched_balance_domains()` | 按调度域逐级触发均衡 |
| `kernel/sched/fair.c:12786` | `sched_balance_newidle()` | 变空闲时先“偷”一个任务再睡 |
| `kernel/sched/core.c:3286` | `set_task_cpu()` | 真正改 `task_cpu(p)`，本次打点处 |
| `/proc/stat` | `cpuN` 行 | 每核 tick（第 2 列是 user） |
| `/proc/PID/stat` | 第 39 字段 | 上次运行的 CPU 号 |

## 一句话收尾

负载均衡不是“把任务平均摊开”，而是“**发现哪个核明显更忙，或者哪个核闲着想偷活**，
才动手搬一个任务过去”。4 任务 4 核各跑满，8 任务 4 核各跑一半——
并行度由核数决定，均衡只负责别让某个核闲着。
