# 主题一 · CPU 的两种特权级，与“1 号进程为什么不是内核线程”

## 你已知的

CPU 分两种运行级别：**内核态**能直接碰硬件和全部内存；**用户态**只能干“读自己内存、
做算术”这种事，想碰硬件或别的进程，必须通过**系统调用**请求内核代劳。Linux 里
“一个进程”通常两边都待过：跑内核代码时是内核态，跑自己的程序时是用户态。

## 内核里对应什么

| 概念 | 内核里的表示 | 说明 |
|---|---|---|
| 正在内核态 | `current` 指向内核代码路径，用的是一套只有内核能访问的页表 | 系统调用、中断、内核线程都在这 |
| 正在用户态 | 同一份 `task_struct`，但页表换成该进程的用户页表 | `execve` 之后就在这里 |
| 只在内核态活的“进程” | `PF_KTHREAD` 标志 + `mm == NULL` | 内核线程：没有用户地址空间，永远不会有用户态 |
| 能去用户态的进程 | 无 `PF_KTHREAD`，有 `mm` | 例如 `kernel_init`：现在跑内核代码，稍后 `execve` 进用户态 |

## 关键一行：`kernel_thread()` 与 `user_mode_thread()` 的差别

```c
pid_t kernel_thread(int (*fn)(void *), void *arg, const char *name, unsigned long flags)
{
	struct kernel_clone_args args = {
		...
		.kthread	= 1,          /* ← 关键：打上 PF_KTHREAD */
	};
	return kernel_clone(&args);
}

pid_t user_mode_thread(int (*fn)(void *), void *arg, unsigned long flags)
{
	struct kernel_clone_args args = {
		...
		/* 没有 .kthread：这个“进程”以后可以进用户态 */
	};
	return kernel_clone(&args);
}
```

`rest_init()` 造 1 号进程用的是 `user_mode_thread(kernel_init, NULL, CLONE_FS)`
（`init/main.c:731`）——所以 `kernel_init` **不是**内核线程，它只是暂时还在跑内核代码。

## 这解释了 `kernel_execve()` 的第一行检查

```c
/* It is non-sense for kernel threads to call execve */
if (WARN_ON_ONCE(current->flags & PF_KTHREAD))
	return -EINVAL;
```

内核线程没有用户地址空间，`execve` 无处可去，于是直接拒绝。1 号进程之所以能通过
这道检查，就是因为它是 `user_mode_thread()` 造出来的。

## 实测证据

镜像 A 启动时：

```
[latte] kernel_execve: /init (PF_KTHREAD=0)
```

`PF_KTHREAD=0`——如果当初用的是 `kernel_thread()`，这一行会是 1，然后 `execve`
直接返回 `-EINVAL`，1 号进程根本进不了用户态。

## 代码位置

| 位置 | 内容 |
|---|---|
| `init/main.c:731` | `user_mode_thread(kernel_init, ...)`：造 1 号进程 |
| `kernel/fork.c:2658` `kernel_thread()` | 带 `.kthread = 1` |
| `kernel/fork.c:2676` `user_mode_thread()` | 不带 `.kthread` |
| `fs/exec.c:1879` | `WARN_ON_ONCE(PF_KTHREAD)` 拒绝内核线程 |

## 一句话总结

**“1 号进程”从诞生那一刻起就注定要去用户态**：它由 `user_mode_thread()` 创建，
所以内核允许它 `execve`；换成 `kernel_thread()`，它一辈子只能在核心里打转。
