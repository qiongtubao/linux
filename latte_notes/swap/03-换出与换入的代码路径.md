# 主题三 · 换出与换入的代码路径

## 你已知的

上一站讲回收，这一站讲“回收匿名页”具体怎么落地：写到哪里、页表怎么改、什么时候再读回来。

## 换出（reclaim 方向）

```
内存紧张
 └─ kswapd / 直接回收 → shrink_folio_list()
     └─ folio_alloc_swap()      ① 拿交换槽位，页进 swap cache
         └─ try_to_unmap()      ② 按 rmap 把每个 PTE 改成 swap entry
             └─ pageout()       ③ 决定写还是放弃
                 └─ swap_writeout()  ④ 真正写交换设备（可批量/异步）
```

关键约束：**② 必须在 ④ 之前**。PTE 先变成 swap entry，进程再访问就会走换入路径；
若先写盘，中间被改写的内容就丢了。

`pageout()` 是“要不要写”的判断点：干净的页可以直接丢（不需要 swap）；脏页、
匿名页、tmpfs 页只能写；写不出去就放弃回收这张页。

## 换入（缺页方向）

```
进程访问一个 PTE 是 swap entry 的地址
 └─ #PF（向量 14，见 interrupts 站）
     └─ handle_mm_fault() → do_swap_page()
         ├─ swap cache 里有？直接用（省一次 I/O）
         ├─ 没有 → 分配页、读交换区（同步等 I/O，major fault）
         ├─ 重建 PTE：swap entry → 物理页
         └─ 带写标志的话，按 COW 处理
```

所以“换出再换入”在用户态看起来就是**一次普通的缺页**，只是它更慢（要读盘）：
`/proc/vmstat` 里的 `pgmajfault` 统计的就是这类 major fault。

## 一次换出的页表变化

| 阶段 | PTE 内容 | 页在哪 |
|---|---|---|
| 换出前 | 物理页帧号（PFN） | 内存 |
| 换出后 | `swap entry`：类型 + 偏移 + present=0 | 交换区 |
| 换入后 | PFN（可能还是同一页，如果在 swap cache 里） | 内存 |

页表项只有 64 位，放不下“设备 + 偏移 + 权限”，所以 swap entry 是一个**重新编码**：
高位标“不是 present”，其余位放 `swp_entry_t`，由 `pte_to_swp_entry()` 解析。

## 我额外加的三个注释点

| 位置 | 注释说明什么 |
|---|---|
| `mm/swapfile.c:1412` `folio_alloc_swap()` | 取槽位、进 swap cache，PTE 随后改成 swap entry |
| `mm/page_io.c:241` `swap_writeout()` | 写交换设备，可能同步也可能异步 |
| `mm/memory.c:4586` `do_swap_page()` | 换入：读回、重建 PTE、必要时 COW |
| `mm/rmap.c:1866` `try_to_unmap_one()` | 摘 PTE 是换出的前提 |

## 为什么这次能“不 OOM”

上一站写满 tmpfs 时，没有 swap 就意味着那 80M tmpfs 页**没有任何出路**；这次多了
64M 交换区，内核可以把其中一部分页写进 swap，腾出物理页继续写——代价是变慢
（读回时要等 I/O），但不再触发 OOM。

实测数据见主题四。
