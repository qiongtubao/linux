# 主题一 · 为什么没有 swap，回收就“空转”

## 你已知的

上一站（`latte_notes/memory/`）实测：128M 机器把 tmpfs 写满时，`kswapd` 被唤醒 16 次、
直接回收 3 次，但 `pgscan_*` / `pgsteal_*` **一直是 0**，最后 OOM 杀掉进程。

那一站的结论是“回收空转”。这一站要回答：**为什么空转，以及加一块 swap 之后会怎样。**

## 页的四种身份，只有前两种能回收

| 页的类型 | 内容在哪有备份 | 回收手段 | 无 swap 时 |
|---|---|---|---|
| 干净文件页 | 磁盘上本来就有 | 直接丢弃，下次读再取 | ✅ 可回收 |
| 脏文件页 | 磁盘上是旧的 | 先回写，再丢弃 | ✅ 可回收 |
| 匿名页（堆/栈） | 只在内存 | **必须换出到 swap** | ❌ 不可回收 |
| tmpfs / shmem 页 | 只在内存（或 swap） | **必须换出到 swap** | ❌ 不可回收 |

`tmpfs` 页和匿名页本质上是同一类：内容没有磁盘备份。没有 swap 时，
`shrink_folio_list()` 找不到可回收页，于是“扫了一圈什么也没收到”。

## 所以 swap 的真正作用

swap 不是“内存的替代品”，它给匿名页提供**第二份存放地**，让它们变得可回收。
有了 swap：

- 内存紧张时，内核可以把最近不用的匿名页/tmpfs 页写到 swap，腾出物理页；
- 进程再次访问这些页时触发缺页，把它从 swap 读回来（换入）。

## 本次实验设计

| | 上一站（无 swap） | 这一站（加 64M swap） |
|---|---|---|
| 内存 | `-m 128M` | `-m 128M` |
| 交换区 | 无 | QEMU 挂一块 64M 虚拟盘，`mkswap` + `swapon` |
| 动作 | 往 tmpfs 写 100M | 同样写 100M |
| 预期 | 回收空转 → OOM | 部分页换出 → 写完不死 |

虚拟盘是用 QEMU 的 `-drive file=/tmp/swap.img,format=raw,if=ide` 挂上的，
内核侧就是一块普通的 SCSI 盘（`/dev/sda`，8:0），**没有改任何 `.config`**。

## 观察点

| 想看什么 | 接口 | 期望 |
|---|---|---|
| 交换区有没有生效 | `/proc/swaps`、`SwapTotal` | `65532 kB` |
| 回收有没有真干活 | `pgscan_kswapd` / `pgsteal_kswapd` | 从 0 变成非 0 |
| 有没有换出 | `pswpout`、`SwapFree`/`SwapCached` | 上涨 / 下降 |
| 有没有换入 | `pswpin` | 可能出现（再次访问被换出的页） |

## 代码位置

| 位置 | 内容 |
