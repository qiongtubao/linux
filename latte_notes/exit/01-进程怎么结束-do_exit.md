# 主题一 · 进程怎么结束：`do_exit` 做的六件事

## 你已知的

程序 `return 0`、调用 `exit()`、或者被 `kill -9`，最后都从系统里消失。
但“消失”不是一瞬间：内核要先**释放它占的东西**，再留一个“壳”等父进程来取退出码。

## 三种“结束”其实走同一条路

| 用户看到的方式 | 内核入口 |
|---|---|
| `main()` 返回 / `exit(3)` | libc 调 `exit_group(2)` → `do_group_exit` → `do_exit` |
| `_exit(2)` | 同上（`_exit` 不刷新 stdio） |
| 被信号杀死（`SIGKILL`、`SIGSEGV`…） | 信号处理路径 → `do_group_exit` → `do_exit` |

`exit(3)`（能跑 atexit 回调）与 `_exit(2)` 的区别在 libc，进了内核就只剩退出码。

## `do_exit()` 做的事

| 顺序 | 做什么 | 为什么必须现在做 |
|---|---|---|
| 1 | 记下 `exit_code` | 父进程 `wait()` 要拿它 |
| 2 | 关闭打开的文件、释放 `mm`（地址空间） | 页表、页、文件引用都不能泄漏 |
| 3 | 清理信号队列、定时器、`task_work` | 避免之后还有人往死进程投递东西 |
| 4 | 通知父进程（`exit_notify` → `SIGCHLD`） | 父进程可能在 `wait()` 里睡着 |
| 5 | 把自己的孩子过继给 `init`（1 号） | 否则孩子成孤儿没人收 |
| 6 | 状态变 `Z`，`schedule()` 让出 CPU | 从此再也不被调度 |

**注意第 6 步之后 `task_struct` 还在**：内核故意留着它，因为父进程还没读退出码。
这就是僵尸（`Z`）状态的由来。

## 为什么不能一步释放干净

因为“退出码”必须由父进程来取。如果内核在退出时就把 `task_struct` 释放了，父进程
`wait()` 时无处可查，也没法做“子进程已结束”的等待/唤醒。

所以生命周期是两段：

```
do_exit()      ：释放资源、变 Z、让出 CPU        （子进程主动）
父进程 wait4() ：取退出码 → release_task() 释放 task_struct（父进程触发）
```

## 内核线程没有僵尸问题

内核线程（`kthreadd` 的孩子）由 `kthreadd` 统一 `wait`，所以不会堆积僵尸。
用户态里如果父进程自己不 `wait`，僵尸就会一直挂着——这就是“僵尸进程占 pid”的原因。
