# 主题三 · 代码路径：停止、继续与状态字母

## 你已知的

`kill -STOP` 之后进程“冻住”，`kill -CONT` 又活过来。中间内核只做了两件事：
**在 `task_struct` 上做个标记**，然后**让出 CPU**。

## 停止的路径

```
kill(2) / 终端 Ctrl-Z
 └─ 信号入队（sighand->siglock 保护）
     └─ 目标进程从内核态返回用户态时 → get_signal()      kernel/signal.c:2808
         ├─ 是 sig_kernel_stop()？（SIGSTOP/SIGTSTP/SIGTTIN/SIGTTOU）
         │   ├─ 非 SIGSTOP 且 pgrp 是孤儿 → 丢弃（不调下一步）
         │   └─ do_signal_stop(signr)                    kernel/signal.c:2551（打点）
         │        ├─ 设 JOBCTL_STOP_PENDING
         │        ├─ 全组线程都停下来
         │        └─ freezable_schedule()  ← 让出 CPU，状态变 T
         └─ 不是停止信号 → 走终止 / handler / ignore 分支
```

关键点：**停止不是“立刻”发生的**。信号只是入队，目标进程下一次从内核态返回用户态时
才处理它——所以正在 `D` 状态等 I/O 的进程停不下来。

## 继续的路径

```
kill -CONT
 └─ 信号入队（SIGCONT 特殊：会清掉 JOBCTL_STOP_PENDING）
     └─ signal_wake_up() 唤醒
         └─ do_signal_stop() 返回后继续，状态回到 R/S
```

`SIGCONT` 不需要 `do_signal_stop()`，它是“撤销停止”。

## 状态字母从哪来

```c
/* fs/proc/array.c:127 */
static const char * const task_state_array[] = {
	"R (running)", "S (sleeping)", "D (disk sleep)",
	"T (stopped)", "t (tracing stop)", "X (dead)", "Z (zombie)", ...
};
```

`/proc/PID/stat` 的第三列就是 `task->__state` 查这张表得到的字母。本次实验用
`awk '{print $3}' /proc/$PID/stat` 读的就是它。

## 四种状态转换（本次实验覆盖了三种）

| 起点 | 动作 | 终点 | 本次实测 |
|---|---|---|---|
| `S`（等 30 秒的 sleep） | `SIGSTOP` | `T` | ✅ |
| `T` | `SIGCONT` | `S` | ✅ |
| `S` | `SIGTSTP`（孤儿组） | 仍是 `S` | ✅（信号被丢弃） |
| `S` | `SIGTSTP`（有 ctty、有作业控制） | `T` | ✅ |

## 打点看到的值

```
[latte] do_signal_stop: signr=19 comm=busybox   ← SIGSTOP（编号 19）
[latte] do_signal_stop: signr=20 comm=sleep     ← SIGTSTP（编号 20）
```

同一个函数，`signr` 直接告诉你“是哪个信号让进程停下的”。
